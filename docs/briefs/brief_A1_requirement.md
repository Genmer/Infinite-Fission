# 派发单 A1：需求分析（Requirement Analyst）

## 输入
必读：`/Users/genmer/Documents/Codes/Agent/Infinite Fission/docs/00_user_requirement.md`（用户原始需求，最终依据）
工作区为全新绿地项目，无既有代码。目标引擎 Godot 4.x（按 4.3+ 稳定 API 设计），GDScript。

## 任务
产出一份**需求分析报告**，写入 `/Users/genmer/Documents/Codes/Agent/Infinite Fission/docs/analysis/A1_requirements.md`，包含：

1. **需求复述**：用自己的话完整复述，确认无理解偏差。
2. **系统模块清单**：把需求拆成最小可交付模块（编号 M-XX），每个模块给出：职责边界、依赖的其它模块、被谁依赖。至少覆盖：核心战斗循环（GameLoop/主场景）、玩家、敌人、敌波管理、四形态武器、投射物系统、Trait/词缀引擎、元素系统、伤害结算管线、对象池、Data-driven Resource 层、GameFeel（顿帧/震屏/色差/粒子）、UI(HUD/跳字/升级选择)、Roguelike 升级卡牌选择流、事件总线、配置/数值表加载。
3. **每条需求的验收标准**：可执行、可验证（如"500 活跃弹幕 + 100 敌人时 120Hz 下帧时间 < 8.3ms，M1 芯片"这种粒度）。禁止"功能正常"式废话。
4. **需求漏洞与边界分析**：空输入/极端构筑（无限分裂递归、乘区堆叠上限、帧内多次事件重入）、生命周期（投射物回收时 Trait 触发顺序）、并发（同帧多次 OnHit）、数据边界（.tres 加载失败）、性能边界（同屏实体上限、Area2D 查询量）。逐条列出风险与处理建议。
5. **待澄清问题清单**：每条附**推荐默认值**（用户已授权 AI 代拍板，列推荐值即可，不必停下等回复）。例如：竖屏分辨率（推荐 1080x1920 逻辑分辨率 + viewport 缩放）、敌人从上方来还是全方向（推荐上方为主）、是否需要移动端触控（推荐鼠标/触屏拖动+自动开火）、首发武器（推荐手枪）、波次结构（推荐无尽波次+精英+Boss 每 5 波）。
6. **范围裁剪建议**：哪些属于"核心系统"必须本期做，哪些留到后续迭代（存档、关卡、美术资源正式化、音频等）。
7. **里程碑切分**：建议 M1（战斗闭环可跑）→ M2（词缀/协同成型）→ M3（卡牌/数值/打磨）三档，每档的验收清单。

## 输出要求
- Markdown，中文。
- 只写这一个文件，不要创建其它文件，不要写任何 GDScript 代码。
- 报告要具体到"能直接当验收测试用例"的程度。
