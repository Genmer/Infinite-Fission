## 等价论证独立复核（本批核心命题）

**A. SpaceGrid.is_empty 的「_snap_items 唯一真源」论证：成立。**
- 写点穷举：`_snap_items` 仅三个写点——`rebuild`（:137 clear 后 :144 经 insert 全量重灌）、
  `insert`（:157 append）、`configure`（:95 clear，同时 :81-84 清全部桶）。无 remove/erase API，
  帧内只增不减。
- 桶↔快照一致性：桶内容 = insert 期 `_snap_items.size()-1` 索引（:164），「桶非空 ⇒ 索引在
  _occupied ⇒ 下次 rebuild 必清」不变式由 :93 的 stamp 初值 −1 保证（R231 修正注释）。逐帧时序
  = rebuild 清桶清快照→重灌，帧内无再清 → **快照空 ⇔ 全桶空**，四个 query_*（snap/circle/
  nearest/arc）全部经桶→快照索引解析，空快照 ⇒ 零候选。查询点与 is_empty 判定点之间无状态
  写入者 ⇒ 同刻判定等价（即使 ④ 内出现补插，也只让两口径同向变非空，早退侧不多跳一次查询）。
- 原生镜像口径：`_nat_cells/_nat_pos` 与 `_snap_*` 在 insert/rebuild 同点同长双写（:139-142/
  :160-163），rebuild 置脏 → 空快照时首次原生查询重喂空 CSR；`_native_state` 进程内缓存
  （:42/:48）不可翻转，configure 不清 `_nat_*` 的路径只在 `_native_on=false`（永不走原生）下
  可达。**口径同。**

**B. projectile_base 三处早退：成立，未找到反例。**
1. `_collect_hit_pairs`（:757）：插入在 null 检查后、`hit_collect` 桶开启前——旧路径空网格时
   查询返回空缓冲、窄相循环零次、桶照开照关；新路径整段跳过。唯一读数差 = 命µs 窗值（废查
   归零即刀的目的），无其他副作用。
2. `_check_collision`（:795）：team==1 分派在前（敌弹零波及）；p_skip_query=false 时空查询
   本就 `_candidates.clear()+append(空)` → 循环空转，早退只是不清 `_candidates`——全仓 grep
   证 `_candidates` 读者仅 :602（本帧填充后的非空判）与 :822 循环（到达前必经 :819 clear 或
   调用方 :600 刚填充），**滞留值无读者，等价**。
3. `_tick_fast_player` elif 门（:593）：旧代码空网格时 precheck 查询空 → `_candidates` 清空
   → 不回落 `_check_collision`；新代码整臂跳过。precheck 内 `effective_radius()/
   sim30_effective()` 均纯读无副作用。
- **p_skip_query=true 交互专项**：全仓唯一 true 调用点 = :603，与预检查询 :601 之间零语句。
  「快照当时非空 ⇒ 此处必非空」实际上比注释论证更强：两检之间无任何代码执行，无需依赖
  「④ 内单调只增」；即便依赖之也成立——rebuild 全仓唯一生产调用点 = ④ 头（game_loop:965，
  每步各自 ④ 头，多步帧不共享），configure 仅 boot（:3299），生产无帧内 insert（insert 唯一
  生产调用者就是 rebuild 自身；w1_volley :385 直插为测试面）。**同帧内快照变空的反例不存在。**
- 边界诚实性核实：深载（敌90）网格恒非空 → 三处 is_empty() 判定本身每弹每步 1-2 次方法调用
  （≈数 ms/s 量级以下），「对主战场无收益」披露属实；收益面（清场/弹重窗口 命µs 96-134k/s
  塌缩）与 vc86 判读④的量级推算自洽。
