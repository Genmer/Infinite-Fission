## 1. 需求①：培养上限提帽

### 1.1 机制规则

- **只提帽、不降价、不加轨、不改公式**。唯一改动 = `Meta.UPGRADES` 常量表各轨 `max_lv`（scripts/meta/meta_manager.gd:243-254，8 轨结构与现值实读确认）。
- 价格曲线维持 `upgrade_cost = base_cost × (当前级+1)`（meta_manager.gd:356-360），购买口 `buy_upgrade` 零改动（meta_manager.gd:363-377：满级或结晶不足返 false）。首级价测试锁（verify_feedback_cases.gd:1207-1215）天然不破。
- **不做难度耦合帽**（否决项，理由见 1.5）：大厅无局内难度态（`run_gate_difficulty()` 未武装返 -1，meta_manager.gd:620-623），难度耦合需给 `buy_upgrade` 加难度参数（改签名，破 verify_feedback:1060-1112 写口语义锁）且养成面板需难度上下文线（`MenuScreen._sel_difficulty` menu_screen.gd:34/:558）——收益不成成本。提帽后全玩家共享新帽，实际效果即「困难玩家（唯一摸得平旧帽的人群）获得新消费端」，正面满足原话「困难需要提高上限」。
- 存档零迁移：`meta/upgrades` 字典与 `meta/crystals` 原样回读（_save meta_manager.gd:1236-1237、_load :1274-1276，无按表钳制），老档已购等级原样保留、可从旧帽继续续购（Lv5 下一级价 = base_cost×6）。

### 1.4 边界情况

1. 老档 `upgrades={"life":5}`（旧满级）→ 读档原样，可续购 Lv6 价 120💎；无任何钳制回退路径。
2. 老档 Lv>帽 不可能出现（只提帽）。
3. 购买到新帽后再点 → `buy_upgrade` 返 false，按钮「已满级」（现行为，menu_screen.gd:1721）。
4. 结晶不足中途停购 → 无状态残留（crystals 只在成功分支扣，meta_manager.gd:374-376）。
5. revive 与难度附赠叠加按现语义线性相加（game_loop.gd:1623），无上限冲突。

## 2. 需求②：祝福（开局自选词条）

### 2.1 机制规则

1. **定名**：系统名「祝福」，代码/存档前缀 `blessing_trait`，UI 文案「祝福（开局）」。与既有地图/每日词缀「祝福」（`Meta.BLESS_POOL` meta_manager.gd:471-472、选关行「祝　%s」menu_screen.gd:522-527、`bless_*` 数值表 game_loop.gd:1726-1738）**同词异义**，全链路用 blessing_trait 前缀消歧，词缀系统零改动。
2. **档位映射**：难度 → 稀有度档：普通→蓝(1)、困难→紫(2)、地狱→金(3)。新增静态口 `GameConst.blessing_rarity_tier(p_d)` = `[1,2,3][clampi(p_d,0,2)]`（scripts/core/game_const.gd，落在 :44-46 difficulty_revives 同族区）。
3. **候选池**（数据驱动过滤，无 id 硬编码）：遍历 `registry.traits`，**同时满足**：
   - a. `int(td.rarity) == blessing_rarity_tier(难度)`（按 .tres 声明档直接分池，零 roll 零缩放；rarity 实跑分布：白 0×6 / 蓝 1×26 / 紫 2×28 / 金 3×13）；
   - b. `!bool(td.params.get("threshold_only", false))`——排除 7 条 TH_* 阈值型（card_generator.gd:322 键名 / :593 卡架同滤先例）；
   - c. `String(td.params.get("requires_trait","")) == ""`——排除需局内上下文的前置组合词条（实跑全集恰 2 条：**MEC_RICOCHET_HALL（紫）与 SYN_BOUNCE_SPEC（紫），均 rarity=2**——修正 B）；
   - d. `Meta.is_trait_unlocked(tid)`（图鉴已解锁 = codex_traits，meta_manager.gd:204/:816-817）——满足原话「开局可选buff必须是图鉴解锁过的」。
   - **池容量（全解锁假想）**：蓝 26−0=**26**、紫 28−2=**26**、金 13−7=**6**（金池 6 条：ELE_REACTION_VOID / MEC_BEAM_SPECTRA / MEC_CRITICAL_MASS / MEC_CRIT_SHARD / MEC_FRACTAL / SYN_FIRST_STRIKE，实跑列名核实）。
4. **时机与流程**：选图/选难度确认后弹自选面板。挂 GameLoop 侧 `_on_menu_start`（game_loop.gd:1751-1770 实读：:1754 is_map_unlocked 门 → :1759 start_run）：门过后、`start_run` 前插入「祝福面板」一步；确认/不选后再进 start_run。**否决侦察方案 A（menu_screen._on_map_pick 插面板）**：menu_screen.gd 是 D 的独占文件（见 §5 分区），B 不得触碰；GameLoop 侧弹层有 settings_panel.open（game_loop.gd:2770）与 SublimeConfirmUI 式弹层（game_loop.gd:2742-2745）先例。
5. **每日挑战双层隔离**（第 3 轮复核中高采纳，补挂载层守卫）：
   - ①**面板层**：`_on_menu_start_daily`（game_loop.gd:1680-1688，:1685 直调 `start_run(daily_seed)`）不插祝福面板；
   - ②**挂载层**：`_apply_start_blessing()` 首行守卫 **`if _active_daily_seed >= 0: return`**——每日种子在 start_run :1580 留存（`_active_daily_seed = p_daily_seed`，常规局为 -1）、restart_run 不清它（:3640-3646 `_grant_random_dual_loadout(_active_daily_seed)` 证明跨重开留存）；每日局死亡经 R188 自动重开（game_loop.gd:1275 区域 `restart_run()`，注释明言仅 continue_endless 自拒每日局）仍带每日种子 → 守卫覆盖自动重开。
   - 两层缺一不可：仅①则直调 `start_run(daily_seed)` 的程序化路径（测试/未来入口）仍会挂载，违反「每日=固定种子全服同配置」裁定。

### 2.4 边界情况

1. 池为空（新玩家 0 解锁词条 / 该档全未解锁）→ 不弹面板、无横幅，直接 start_run（合规退化：必须图鉴解锁过）。

3. echo（随机双武装）开局：挂载时按最终 loadout 首匹配；两把都不适配才落 slot 0 披露。面板不按武器预过滤（loadout 局内才定），死卡风险以横幅披露兜底。

## 8. 风险与缓办项

**风险**
1. **遗物池稀释**：18→34 且 unique，单件获取率 ~÷1.9；权重三源 6→8 对冲后净 ÷1.44。上市观察困难局遗物获取节奏，必要时二次调权重（仍是三源同改）或给 OVERCLOCK 保底链加档。
2. **三源漂移复发风险**：权重今后再调必须三处同批（card_generator const / balance_tables.gd / balance_tables.tres），R17 已把三源一致性断言化，防「单改 const 静默失效」复发。
3. **seed=42 选卡流值漂移**：引力井收窄候选集与权重 8.0 改变分布（消费次数不变）；pkg4/pkg5 具体值断言可能红——复跑后逐条迁值，禁止为保绿改回实现。
4. **重力井与祝福/echo 三件定轴件叠加**：开局定轴+货架显影可能过度收敛（构筑多样性下降）；引力井只锁首张词条位，观察后可参数化 `first_slot_bias` 降档。
5. **M1 上限可达性**：50ms 为 P1+P2+P3+P4 合力后的设计目标，非基线实测——修后复跑若不达，按 §4.5-M1 分档回调并披露实测，不允许虚改测量口径。
6. **真机性能未测**：全部基线为桌面 headless 探针；移动端 fsync/贴图更慢，P5/P6 为真机保险但无实测数字——发布前真机抽测（人工步骤，不在三员范围）。
7. **24 套件复跑成本**：合并门禁全量复跑一次（约与 R250 批同量级）；三员各自先跑本域清单收敛再合。
8. **页面改名外溢**：「词条→祝福」页签名断言全仓三处已盘清（rxn_codex :222-238、r191 :1224-1226、r245 :442-443 不受影响）且全部入迁移表；教程/成就文案中的「词条」称谓语义一致性由文案面自查（本批不改其余文案）。
9. **血税/利息等经济遗物与黑市叠加**：金币吞吐放大可能通胀——params 全数据驱动，热调零代码（但注意权重类热调仍走三源）。
10. **伤害向占比张力**（第 3 轮复核低采纳）：16 件中 9 件终局效果为伤害乘区/AoE（#1/#3/#4/#5/#7/#8/#9/#10/#15，最接近纯条件数值的是 #5），逐件均带机制骨架（资源转化/风险契约/处决/货架显影/波税）不判充数，但与用户「不想简单提升数值」原话存在张力——列为上市观察项，后续批次补控制/资源/防御类权重。
11. **P6 崩溃窗口**：面板打开期间强杀丢面板内变更（见 §4.2-P6），已判定接受；若 QA 反弹，回退方案=只对设置滑条 defer（drag_ended 收口）。
