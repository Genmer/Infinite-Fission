# R230「高峰 dc 根治轮」设计方案（2026-10-04）

> v2（2026-10-04，按分析意见修订后放行版）：①§1.2 哨兵清单补 fx_quality 对齐与色差中和两项；②K2 穿插件子刀改口径（自绘件不合批定律，改 sprite 化/并发帽二选一或降 backlog）；③§1.4 P1/P3 补逐帧族掩码重放、FG3 容差与掩码强度挂钩；④K4 删静态行合并子项；⑤§假设① 补锚段同构对照与 K1 单刀 A/B 转线预案；⑥电池基线 104+K1 预期修正 ~8-16。

## 概述

本轮先用 **PC 窗口化 gl_compatibility 渲染夹具**把真机深载 dc 700-990 分解到族（把「电脑模拟不了」变成「电脑可复现」），再按**夹具实测谱**落 ≤4 把文件集互斥的 dc 刀，vc35 出包；验收主轴=**真机深载带 dc 高峰 ≤650（硬门，拉伸 ≤550）**，fps 90-120 是否达成由 vc35 真机日志判定，本轮不预承诺。

## 项目背景

- **技术栈**：Godot 4.3-stable / GDScript；桌面渲染器 forward_plus、真机经 `project.godot:57` `renderer/rendering_method.mobile="gl_compatibility"` 覆写为 GLES3（本轮一切「渲染器差异」嫌疑的根源——此前所有桌面/headless 测量均不在真机渲染路径上）。
- **vc34 定案输入**（tracker 二ca，全部为已定案测量事实，本设计不再质疑）：
  1. fps-dc 相关性钉死：战斗活跃行 dc≤430→fps 84-120；dc 500-650→fps 45-95；dc 700-990→fps 20-35；o 同段不判别 → **高峰 fps 20-35 直接死因=渲染 dc 700-990**。
  2. 裁N=372 精确触发而 o 不降 → **o 不计隐藏静载**（R228 backlog #6 口径收口）。**推论：一切「砍隐藏静载/树件数」类刀不再兑现 fps，本轮刀只对 dc（与 GPU 成本）负责**——这是刀序重排的基准前提。
  3. headless 六族谱（粒子 30-64/特效层 30-80/HUD 40-100/跳字根 24-40/敌桶穿插件 20-60/三池本体 35-60）合计 ~180-400，与真机 700-990 缺口 ~300-600 未归因；真机 1:40 行 弹26 敌120 dc778 → 非弹主导；嫌疑=敌 120 本体子件、碎片驻场 318、特效种类堆叠、渲染器差异。
  4. 第二瓶颈独立存在：敌28-33 弹190-325 时 dc 仅 412-449 但 fps 20-45、余 12-32ms（粒子过填充嫌疑）。
  5. 主控烟测通过：PC 窗口化 `--rendering-method gl_compatibility` 可正常起本项目；`RenderingServer.get_rendering_info(TOTAL_DRAW_CALLS_IN_FRAME)` 在真渲染器下可活读（headless 恒 0 为既有对照）。
- **可复用资产**：R224 深载夹具（`repo/tests/probe_r224_deepload.gd(+_cases)`：敌 120 驻场 + grove w16 构成 + W2 L5 五词条 + HP×0.3 + 风筝 + 手动 60Hz 驱动）；R228 真机深载态哨兵注入清单（`qa_r228_ospec_cases.gd:85-92`：`Enemy.fullload_override=1`、`DamagePopup.bitmap_override=1`、`PopupGlyphAtlas.runstart_bake_override=1`、`DamagePipeline.settle_budget_override=-3`、`PerfGovernor.set_process(false)+mode_override=0+tier_override=2`）；R228 backlog 7 项带证据（主报告 §3.3）；R229 三刀既有 override 口（`burst_thin_override`、`pool_valve_override`）。
- **本轮与流水线的关系**：本设计=策划阶段产出；下游分析/实施按本刀面与门禁施工，夹具与产品刀分浪（测试文件与产品文件互斥，R228 §4.1 先例）。

## 核心循环（本轮方法论循环）

```
夹具谱（PC gl_compatibility 窗口读 dc 分族）
   → 归因（族占比，把 700-990 缺口落到族头上）
   → 刀（按谱排序取 ≤4 把，文件集互斥分浪）
   → 门禁（夹具复测降幅 + 锚段零扰动 + 全量电池）
   → 真机（vc35 日志 dc 高峰带判读）
   → 回填基线 JSON（下一轮谱=本轮刀后谱）
```

为什么有效：vc33/vc34 两轮证明「headless 谱外推定刀」会被真机负载增长与渲染器差异吃掉（R228 三刀 dc 不可分辨）；本轮把决策量换成**夹具内的族占比与刀的相对降幅**（PC 与真机 GPU 绝对值不等，但合批逻辑在引擎侧、dc 计数与 GPU 速度无关，占比可迁移——假设与残余风险见 §假设），每一步都有可测读数、单调收敛，不再有「测量不到的刀」。

**S-A 真机深载态哨兵注入全套**（抄 `qa_r228_ospec_cases.gd:85-92` 清单，必须先于 add_child——池预热在 `_ready` 期跑）：`Enemy.fullload_override=1`、`DamagePopup.bitmap_override=1`（PC 默认走 Label 臂=非真机形态，**必须注入**否则跳字族读数假阳）、`PopupGlyphAtlas.runstart_bake_override=1`、`DamagePipeline.settle_budget_override=-3`、`PerfGovernor.set_process(false)+mode_override=0+tier_override=2`，另加 `GameFeelDirector.burst_thin_override=-3`、`GameLoop.pool_valve_override=-3`（模拟真机 tier2 档=vc34 深载带形态：粒子已减薄、弹池已裁——**不注入则粒子/弹池族读数偏离真机带**）。

**真机表现态补齐两项（v2 新增，三情景 S-A/S-A'/S-B 统一生效，均夹具侧零产品码）**：

1. **boot 后 `Meta.set_setting("fx_quality", 1)`**——对齐真机 mobile 门有效值。特效层与命中粒子两处读的是 fx_quality 设置而非 tier 帽（不吃 tier 门），桌面缺省档偏高会使 **F6 粒子发射器族 / F7 特效层族读数偏离真机带约 2 倍**，直接毒化刀序裁定。
2. **每物理步后强制隐藏 `game_feel.chromatic_rect`**——桌面色差=激活期全屏拷贝+整帧批冲刷（R228 §2.3），真机已被 R203 整体禁用无此件；不中和则该全屏件污染全族读数。色差件由 feel 侧按事件反复施加，故须**逐物理步重申隐藏**（与 §1.4 掩码重放同一机制，一并实现）。

锚段口径说明：S-A' 对齐的是「同阀态下的表现档」，fx_quality 与色差中和两项在锚段同样生效（真机锚段也无色差件、fx_quality 同值）。

**1.4 dc 读数协议（自动跑完，无人工介入）**

- 逐帧 dc=上述活读（口径=上一完成帧，任何 visible 切换后**弃 3 帧**再采样——弃帧只解决「读旧帧」，不解决下述新件可见问题）。
- **逐帧族掩码重放（P1/P2/P3 共同基础设施，v2 新增）**：深载期 DeathPop/PoisonSplash/跳字/粒子等**持续新 spawn**，一次性 visible=false 后新件可见会污染后续族读数——关断态必须**每个物理步对当前树重新套用族掩码**（按 §1.3 分类表对新增节点即时归类并隐藏，含 §1.2 色差件重申隐藏）。掩码重放是读数有效性的前提，不是可选项。
- **P1 累积关断（主读数）**：基线采样 60 帧取中位 → 按 F1→F12 固定树序逐族入掩码，每族 settle 10 帧+采样 30 帧取中位 → 边际 dc_i=dc_(i-1)−dc_i。望远镜恒等：Σ边际=基线−全隐藏残差（闭环门 FG3；容差与掩码执行强度挂钩，见验收）。
- **P2 单独可见（辅读数）**：每族单独开、其余全掩（掩码同样逐帧重放，仅目标族豁免）→ 族独立 dc（含族内断批全貌；P2−P1 差=跨族合批耦合，只披露不判刀）。
- **P3 反序复跑**：P1 树序逆序跑一遍（仅 S-A 真机档），边际次序漂移入报告（合批耦合的次序敏感度量化）。
- 全程手动 `_gl._physics_process(1/60)` 驱动 + `await process_frame` 真渲染帧（R224 协议）；300 帧预热后进采样。
- 同步读 `stage_probe_us`（S-B 的 CPU 侧余桶归因主源）与各族存活件数。
- 预计总时长 <3 分钟/全量（3 情景 × (~12 族 × 40 帧 + 基线)）。

- 每行：族 | 存活件数 | 边际 dc（P1）| 单独 dc（P2）| 占比（边际/基线）| 次序漂移（P3）。

## 假设与开放问题（下游分析师重点看）

1. **PC gl_compatibility 与 Android GLES3 合批同构假设**（本轮最大假设）：dc 计数由引擎侧合批逻辑决定（纹理/material/modulate 键控），理论上是跨驱动迁移的；但桌面 OpenGL 与 Android GLES3 驱动路径仍有差异面（压缩纹理格式 S3TC vs ETC2/ASTC、驱动能力探测分支）。**残余风险=族占比迁移误差**；对策=决策量只用占比与相对降幅（§1.5 白名单），真机 vc35 日志终验。
   - **零成本同构对照（VG3 复用）**：锚段（tier3/特效优先）dc 与 vc34 同带逐位不变 + 刀段 dc 按夹具预期下降 → **同构确认**（合批行为在两端一致）；锚段不变 + 刀段**不**降 → **假设证伪**（夹具降幅在真机不兑现=渲染器差异真实存在），回报并转线。
   - **证伪时的转线预案**：真机端**没有 dc 分族键**（诊断行仅 断N/组N/桶N/跳N/拾N 五键，`debug_stats.gd:178-187`），无法真机分族归因 → 拿 **K1**（文件集最小、机制最确证：单文件+量化定律已两轮先例）做 **vc35a/vc35b 单刀 A/B 出包对拍**（a=无刀基线包，b=仅 K1 包，同设备同构筑对读跳字族贡献的 dc 差），以 A/B 差定「降幅是否迁移」，再定 R231 是否转内容差调查。
2. **FG4 校准分叉的走法**：S-A 基线 <500 时缺口指向内容差（敌方弹〔R224 QA D4 既知洞〕/棱镜/真实构筑），需夹具升级一浪——刀序顺延是否可接受（用户时效压力在案），由主控裁定：可先落不依赖缺口归因的 K1/K3 两刀再补测。
3. **S-B 第二瓶颈的真机归因局限**：粒子 GPU 过填充在 PC（4070）不可复现，本轮只能给 CPU 段（stage_probe_us）+发射器族 dc 的间接归因；K3 的 amount 减薄是对该嫌疑的**保险丝式下注**（可否决），不是定论。
4. **`-s` 窗口模式烟测**：主控烟测的是完整起项目，`-s` SceneTree 脚本+真窗口组合未验证过（headless `-s` 是惯例路径）；FG0 先行验证，失败走 §1.1 回退。
5. **S-B 构筑指纹是近似**：真机弹幕带的实际构筑（是否有 W1 弹幕态/棱镜参与）未知，弹N 落带校准门只保证「量级复现」不保证「构成复现」，S-B 结论限定在「该量级弹幕+该敌数」形态下。
6. **HUD K4 的用户感知风险**：用户对 UI 字体颜色/大小历史反馈密集（金色字体系 R31/R38/R200），任何配色收敛需保留语义色（品质金/元素色/警示红）不被量化抹平——若实施，套件须含语义色保全断言（v2 起为 K4 硬性子项）。
7. **dc ≤650 与 fps 的换算诚实性**：45-95 中带结论来自 vc34 相关性带内插，非因果保证；若深载带同时压着第二瓶颈，dc 达标而 fps 不达标的情形已在 VG2 预设为 R231 升级路径，不视为本轮失败。
