## 结论：**修改后放行**

## 二、开放问题核查（按策划稿优先级）

### ① add_weapon 全局 rng 核查（最高优先）——结论：送武链零 rng 消费，红线不动

|---|---|---|

武器类全部 randf()/randi() 全局流消费点核实均为**开火/命中期**（wave 1 之后的 PLAYING 帧）：weapon_base.gd:591（逐发元素掷取）、ballistic_weapon.gd:83-90/:133（枪口闪光/齐射散布）、orbit_weapon.gd:293（旧开窗通道 facing）、orbit_field.gd:820（命中闪光旋转）、arc_slash.gd:344 / flying_sword_weapon.gd:266 / ground_axe_weapon.gd:310（挡弹掷骰）、ground_axe_weapon.gd:637-644（落斧裂纹 FX，setup_fx 在效果生成时掷）。

断言面核查：B9（r252_blessing_cases.gd:428-447）断言的是 `card_generator.rng.state` 与 `spawner.rng.state`——两条**局部流**，武器代码从不触碰；pkg4 卡流用例自行定种（pkg4_cases.gd:454/:466/:491），seed(42) 全局流无逐位断言。**结论：送武祝福上线下 B9/pkg4 零位移，无需隔离流或断言迁移。**

残余注意（测试卫生，非设计缺陷）：局内开火期全局流消费与「多一把武器」的行为差，对断言敏感套件的影响路径是**电池内 user:// 残留的祝福记忆**（前序套件写了武器绑定记忆 → 后续套件 start_run 白送武器改变击杀节奏）——沿用既有裁定（有副作用套件置电池末位）+ 套件 setup 显式清 Meta.blessing_trait_id；G12 用例本身按 B9 双局部流断言照抄。

### ② 池精确值 62——静态枚举证实（附分档勘误）

73 条 .tres 全量过三态滤（图鉴全解锁 fixture、手枪首发）：

- 73 − 7×threshold_only（TH_BANK_SHOT/DETONATION_ECHO/MIRROR_CHOIR/PRISM_CHOIR/SWARM_NOVA/RING_PRESSURE/VOLLEY_STATE）− 2×requires_trait（MEC_RICOCHET_HALL/SYN_BOUNCE_SPEC，与 TH 零交集）= **64 候选**；
- 64 = 38（fits 通过，现状池）+ 24（武器绑定：23×required_weapon + 1×required_class，全失配于手枪、全送得出）+ 2（纯形态失配：**AFF_RANGE** forms=[3]、**AFF_CDR** forms=[1,2,3]——不上池维持现状）。MEC_PARALLEL_CAL 直查 W1_pistol.tres 含 lateral_gap_levels 键 → 在池，不计失配。
- **全池 = 62 证实。**
- **分档勘误（必须改）**：24 条武器绑定逐文件实读为**蓝 7 / 紫 15 / 金 2**，设计稿写「蓝 8/紫 14」（§5.1 蓝档名单本身就只列了 7 个名字）。新池分档 = **{白 6, 蓝 24, 紫 26, 金 6}**。G1 fixture 与 §5.1 表须按此改。

### ③ 送武选择规则（确定性 vs 图鉴优先）——支持设计的确定性方案

- 映射表逐条按 .tres + 门矩阵推演验证：巨刃/谐振轨道（均绑 W8-W13 五把，MEC_GIANT_BLADE / MEC_ORBIT_LINK params 实读）→ 难度门最小 1（W8/W9 并列）→ 大关门并列 3 → id 序 W8<W9 → **W8**；临界质量（单绑 W8）/链式引爆/环绕三件套 → W8；弹反刀意（required_class=melee）候选 = form3 且 weapon_class∈melee = {W8, W13}（W9/W11/W12 为 talisman 天然排除，.tres 实读）→ W8；刀势如风（W9/W13）→ W9；W4 族 7 条 → W4；W5 族 4 条 → W5；引信涂层/蜂巢挂架 → W6（单绑实读）；定向爆破 → W7；回旋远掷 → W10。**G2 全表可按设计原文锁死。**
- 「图鉴已解锁优先」否决理由成立（付费可预期性 > 亲切感；送武随存档漂移破坏定价语义）。维持 §8-3 复议口。
- 实现注意：排序载体必须用 Array[String] 字典序（StringName↔StringName 排序静默无效——_blessing_pool :1940-1942 既有教训）；解析器建议落 **MechanicGate static**（两门矩阵所在类，BlessingPickUI 附赠标记可静态复用，避免 UI 反向依赖 GameLoop 实例）。

### ④ 胜利屏星尘预览与终值不一致——低严重度，可接受；文案缓冲列可选

时序核实：通关屏出现时 settle 未执行（defer 位 :1372）→ 预览走 `stardust_for()` 纯函数可行（_run_max_wave/_run_kills/_run_difficulty 此时均已就位：meta_manager.gd:994/:900 与 start_run :1701 注入）。选「重开/回菜单」→ settle_now 兑现值 == 预览值（一致）；仅「无尽继续」路径终值更高，且其后死亡屏会以真实入账再显示一次——不一致是**过渡态且自愈**；余额 M 同理（settle 前读值）。「至少 +N」为纯修饰，列可选。实现点：通关屏统计行由 show_summary 先写、show_victory 覆写标题（game_over_screen.gd:177-181），星尘行须两入口共用拼装，且每日屏（show_victory(false) 路径）不显示。

### ⑤ 平衡（蓝 20 白得 W8 双槽开局 / 白 10 低性价比）——可上线，观察两项，回调只动产出侧

- **每次出发消费（租用制）是关键自衡器**：普通通关产出 22（§5.3 公式实算无误），撑不起「局局蓝档」除非连胜；蓝档 W8 开局让普通局更快 → 轻微滚雪球，但每局重付 20，雪球有摩擦。W8 实参（.tres：2 orbs、orbit_radius 90、hit_cd 0.5、base_atk 10-17 级表）是近战入门款，常态判断**不超模**。
- 真实风险位：**熟练玩家速通普通刷星尘**（普通通关 <5 分钟则蓝档常驻化）。回调杠杆：D 压普通端 / V 按难度拉开——都比动定价（用户拍板锁定）干净。
- 白 10 低性价比：白档 6 条全通用、无送武，被蓝档严格支配——结构性事实，接受，本批不动。
- 遥测：stardust_total 够用；可选在结算事件环补「局结算星尘 +N」行便于 vc74 复盘。
