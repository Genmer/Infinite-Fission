## §2 WAT 基建（第四元素入场）

- `GameConst.Element` 尾追 `WAT = 4`（旧值零重编号：KIN/FIR/ICE/LTG = 0/1/2/3）。
- `ElementalState.gauges` 4 槽 → **5 槽**（KIN 槽恒 0 弃用 → FIR/ICE/LTG/WAT = 1/2/3/4）；
  `apply` 范围检查上界 LTG → WAT；`reset` 归 5 零；`is_state_active` 增 WAT 臂
  （`gauges[WAT] > 0`——水附着态，条件乘区词条可引用）。
- λ 表三处同值（schema 默认 / .tres / 本文档）：`[0.35, 0.30, 0.40, 0.38]`；
  DataValidator 校验 size == 4（文案恰 4 项）；ElementalSystem.tick 兜底同值。
- `EnemyData.resist` 默认 5 零；**8 个 resources/enemies/*.tres 逐个追加第 5 位 0.0**
  （.tres 不随 schema 迁移必须手改）；validator `resist size == 5`；
  `Enemy.resist` 默认/清零 5 位。
- `ProjectileBase.ELEMENT_COLORS` 追加 WAT 色；`Enemy.ElementRing` 升 4 扇区：
  RING_COLORS 追加 WAT（alpha 0.9）/ SECTOR = TAU/4 / _gauges 4 槽 /
  set_gauges 判 size ≥ 5 取 [1..4] / progress clampi(el−1, 0, 3) / _draw range(4)。

## §3 三剧变契约（水系）

### RXN_WAT_ICE 冻结（碎裂>过载>超导之后的第 4 优先级）
- 触发：WAT + ICE 双槽附着（帧末检测，一帧一反应）；CD 5.0s。
- 结算：清 WAT + ICE 双槽 → 查 `p_state.immune_mask & IMMUNE_FREEZE`：
  - 未拦截 → `apply_freeze_reaction(2.5)`（freeze_timer = 2.5s）+ `reaction_triggered(RXN_WAT_ICE)`
    广播 + `DebugStats reaction_freeze` 计数。**冻结本体零伤害**，伤害在破碎。
  - 拦截（Boss）→ 直接返回：CD 已记、双槽已清、**零广播**（emit/count 均在未拦截分支；
    通用 `reaction_triggered` 遥测计数仍 +1——触发尝试语义）。
- **全停语义**：冻结期（freeze_timer > 0）敌人移动/RANGED 开火（含 fire_cd 递减）/
  Boss 弹幕与召唤计时全部停止；DOT（点燃）照跳。既有 ICE 满槽冻结（1.2s 通道）同步
  升级为全停（同一 freeze_timer 通道，速度因子 sf=0 已有 + 新行为门天然覆盖）。
- **破碎（shatter）**：冻结期内累计 **3 次**直击（popup_style ∈ {NORMAL, CRIT}；REACTION/DOT/
  HEAL/XP 不计）→ 立即解冻（timer 归零）+ 记 pending + 快照（第 3 击的 panel_snapshot）；
  ElementalSystem.tick 宿主循环 `_dot_tick` 后消费 → 结算
  `0.4 × snapshot × φ`（RXN_WAT_ICE 通道，HIT_IS_REACTION）；到期未满 3 击 → 计数清零。
  二次冻结重新计数。

### RXN_WAT_LTG 导电
- 触发：WAT + LTG 双槽附着；CD 4.0s。
- 结算：主目标 `0.9 × φ × last_attach_snapshot`（RXN_WAT_LTG 独立结算）+ BFS 链
  （深度 3 / 每跳目标 3 / 半径 160 / 每跳 ×0.6 衰减 / 去重含 origin；hop0 = 0.9×φ×snapshot，
  后续逐跳 ×0.6）——镜像 _shock_chain；跳伤走 `_settle_conduct_jump`
  （element = LTG、HIT_IS_DOT、source_uid = _uid_conduct 独立分流）。清 WAT + LTG 双槽。

### RXN_WAT_FIR 汽爆
- 触发：WAT + FIR 双槽附着；CD 3.0s。
- 结算：主目标 `0.6 × φ × last_attach_snapshot` + `_spread_reaction(enemy, 80.0, ...)`
  半径扩散——★`_spread_reaction` 加第 5 参 `p_rxn: int`（既有过载调用点显式传
  RXN_FIR_LTG，数值零漂移，pkg 过载用例即恒等锚）。清 WAT + FIR 双槽。

## §4 增幅三轨升格（淬火 + 配置化）

- BalanceTables 增三 @export：`amp_melt_factor = 1.5` / `amp_vapor_factor = 2.0` /
  `amp_quench_factor = 1.5`（.tres 镜像三值）；ElementalSystem 删模块常量
  AMP_MELT_FACTOR / AMP_VAPOR_FACTOR，改 `_amp_factor(p_key, p_fallback)` 经
  GameConfig.balance 读取（null 回退 fallback = 旧常量值，行为零漂移）。
- **三轨判定**（_amplify_snapshot / consume_amplify 同序镜像）：
  - FIR 直击：`gauges[ICE] > 0` → 融化 ×1.5（★优先，保 pkg11 恒等）；
    elif `gauges[WAT] > 0` → 淬火 ×1.5×φ。
  - ICE 直击：`gauges[FIR] > 0` → 蒸发 ×2.0（不变；ICE 直击 + WAT 附着 = 恒 1.0 不增幅）。
  - 消耗分键：融化清 ICE（`amplify_melt`）→ elif 清 WAT（`amplify_quench`）；
    蒸发清 FIR（`amplify_vapor`）不变。
- 淬火通道 = FIR 直击，天然在 projectile_base 既有增益门内（零改动）。

## §5 元素盾

- **数据**：`EnemyData.shield: Dictionary = {}`（注释 `{element:int(0..4),
  capacity_ratio:float(0,1]}`；空 = 无盾）；validator：非空则双键必填 /
  element ∈ 0..4 / ratio ∈ (0, 1]（error 级）。赋盾 .tres：E6_boss2 雷盾 0.30 /
  E6_boss3 水盾 0.30 / E5_elite 冰盾 0.25。
- **克制环**：`GameConst.SHIELD_COUNTER: Array[int] = [-1, 2, 1, 4, 3]`
  （盾元素 → 克制它的攻击元素：FIR1↔ICE2 / WAT4↔LTG3；真源本文）+
  `static func shield_hit_factor(p_shield_element, p_hit_element) -> float`
  （越界 1.0；counter 命中 2.0 否则 1.0）。
- **运行期**（enemy.gd）：字段 shield_element = -1 / shield_hp / shield_max /
  _shield_ring: ShieldRing；spawn max_hp 定型后：data.shield 非空 →
  shield_max = shield_hp = max_hp × capacity_ratio + 环 setup(element, hitbox_r + 11.0) +
  visible + set_progress(1.0)。
- **召唤剥盾**：enemy_spawner summon 分支 spawn 后 `enemy.strip_shield()`
  （三字段清 -1/0/0 + 环隐藏——同 hp_override 先例）。
- **拦截层**（take_result 内、冻结计数之后）：`_absorb_by_shield(p_result) -> bool`：
  - 无盾/盾空 → false；hit_el 判定：★popup_style != REACTION 才读 element
    （ReactionType 中性 ID 与 Element 值域相撞，反应结算不误判），clampi(0, 4) 否则 -1；
  - `shield_hp -= final_value × shield_hit_factor(shield_element, hit_el)`；
    ≤ 0 → 归 0 + `_break_shield()`（环 flash + `DebugStats shield_broken`），
    **无溢出穿透**（余量不落血）；否则环 set_progress；
  - `DebugStats shield_absorbed`；return true（不扣血不闪白、killed 恒 false、
    result 不改——跳字显终值，盾环表吸收）。
- **观测口**：shield_progress() -> float / shield_active() -> bool；_reset_state 三字段 + 环清零。
- **ShieldRing**（enemy.gd 内类，镜像 FuseRing/ElementRing）：FLASH_TIME = 0.06 /
  RING_COLORS 五色（与 ProjectileBase.ELEMENT_COLORS 同值镜像）/ setup / set_progress
  (clamp + redraw) / flash() / tick(delta)（flash 递减；flash 尽且 progress ≤ 0 → 隐藏）；
  _draw：底衬淡整圆 alpha 0.25 + 实心弧 sweep = TAU×progress 元素色 alpha 0.9 宽 3 +
  flash 期整环白；enemy.tick 增 _shield_ring tick 驱动。
- **增幅照常**：盾期增幅乘区照乘、附着照常（盾只拦落血，不拦元素通道）；
  破盾后不可再生（无回充通道）；V51 锁定。

## §8 边界裁定

- **damage_pipeline.gd 零改动**（含注释——本版该文件一笔不碰；pkg12 V54 源码守卫：
  小写不含 "shield" 字样）。
- 盾拦截不读 REACTION 通道的 element（ReactionType ID 撞 Element 值域：
  RXN_WAT_LTG = 4 打 WAT 盾不吃克制 ×2——V51 锁定）。
- 冻结计数只认 NORMAL/CRIT 直击（REACTION/DOT 不计——V45）。
- 破碎结算在帧末（ElementalSystem.tick 宿主循环），不在直击当场——盾拦截层插桩在
  take_result 内于冻结计数之后（冻结计数先入账 → 再判盾吸收；吸收命中同样计破碎击数，
  与冻结方案 W5/W6「冻结计数后插」口径一致）。
- summon（Boss 召唤物）不继承盾（strip_shield）。
- `trait_effect_elemental.gd` 零改动：ELE_TIDE params element = 4 自动走通
  （ON_SPAWN 标记 + ON_HIT 附着请求通用通道）。
