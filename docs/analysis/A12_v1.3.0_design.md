## §1 R1 元素共鸣

### 1.1 常量（ElementalSystem，A12 冻结值）

| 常量 | 值 | 语义 |
|---|---|---|
| `RESONANCE_ATTACH_MULT` | 1.25 | ≥2 把同元素：该元素附着强度乘区 |
| `RESONANCE_REACTION_MULT` | 1.15 | ≥3 把同元素：该元素反应结算乘区（附着不吃） |
| `RESONANCE_ELEMENT_NAMES` | ["动","火","冰","雷","水"] | HUD 显示名（Element 枚举序直索引） |

### 1.2 单源扫描器（每武器恰计 1 元素）

`static weapon_element_counts(p_player) -> Array[int]`：
- null player / 非 Array `weapon_slots` → 全 0；
- 逐武器（`is WeaponBase` 且 `is_instance_valid` 且 `trait_stack != null`）扫词条：
  `pool == ELEM` 且 `params["element"]` 为 **int** 且 ∈ [FIR..WAT]（KIN 不在域内）的词条中，
  **层数最高者**胜出；平层 tie **后挂胜**（挂载序遍历用 `>=` 替换 best）；
- `_weapon_element(w) -> int`（私有静态，-1 = 无归属）为扫描原子，
  `resonance_suffix`（static，HUD 用）与 `rebuild_registries` 共用同一口径。

`static resonance_suffix(p_player) -> String`：counts[e]≥2 的元素按 FIR..WAT 序拼
「火×2」，「·」连接，前缀「 共鸣:」；空 → ""。

### 1.3 全量重算收口 `rebuild_registries(p_player)`

三表**清空重建**：`_reaction_mults` / `_mastery_reg`+`_mastery_step`（后写覆盖；镜像
register_mastery 的零/负防御）/ `_resonance_counts`。null player → 仅清空。

**触发点（四处，统一收口）**：
1. `WeaponBase.attach_trait`：ELEM 词条挂载成功 → `elemental.rebuild_registries(player)`
   （替代 v1.1.0 增量注册两段 + `_trait_layers` 删除；`register_reaction_mult` /
   `register_mastery` 直调通道**原样保留**——冻结夹具 V32/V34/XE4/XE7 依赖）。
2. `Player.add_weapon` / `equip_weapon` 成功臂 → `deps.elemental` 为 ElementalSystem 时
   `rebuild_registries(self)`。
3. `GameLoop._reset_run_state`：首发武器装载后显式重算（重开三表归零，XE1 残留语义收口）。
4. `GameLoop._on_shop_utility` strip 成功臂（`primary.invalidate_panel()` 后）——ELEM 词条
   摘层的注销路径（v1.1.0 E-AMP-1「无注销通道」假设随本版废除）。

### 1.4 消费点（三处，无共鸣 ×1.0 逐位恒等）

| 消费点 | 公式 | 共鸣来源元素 |
|---|---|---|
| ① `apply_attach` | `value ×= resonance_attach_factor(element)`（chip 乘区**之后**） | 附着元素自身 |
| ② `_trigger_reaction` 四伤害臂 | `coef ×= _pair_resonance(a, b)`（= res(a)×res(b)，H2 连乘） | 碎裂(FIR,ICE) / 过载(FIR,LTG) / 导电(WAT,LTG) / 汽爆(WAT,FIR) |
| ②′ `tick` 冻结破碎结算 | `shatter_coef × φ × _pair_resonance(WAT, ICE)` | 同上（WAT,ICE） |
| ③ `_amplify_snapshot` 三返回 | `× resonance_reaction_factor(p_hit_element)` | 火直击 melt/quench 吃火共鸣；冰直击 vapor 吃冰共鸣 |

超导 / 冻结主臂无伤害**不乘**（零伤害臂不引入共鸣）。`_pair_resonance` 双元素连乘见 H2。

## §3 R2 元素水晶

### 3.1 出现（WaveDirector）

| 常量 | 值 |
|---|---|
| `CRYSTAL_START_WAVE` | 8 |
| `CRYSTAL_CHANCE` | 0.40 |
| `CRYSTAL_RNG_SEED` | 1001 |
| `CRYSTAL_MARGIN_X` | 80.0 |
| `CRYSTAL_Y_MIN` / `CRYSTAL_Y_MAX` | 160.0 / 720.0 |

- 独立 rng 流 `_crystal_rng`（`_ready` 播种 / `reset_event_state` 重播种——事件流 777 同口径，
  不跨局）。
- `_maybe_roll_crystal(p_wave)` 于 `start_wave` 尾部、`emit_wave_started` **前**调用：
  w<8 或 `_boss_wave` → return **不消耗** rng；金币关**不排除**；`randf() >= 0.40` → return
  （未中也消耗一次 draw）；命中 → x=randf_range(80, res.x−80)、y=randf_range(160, 720)
  （再消费两次 draw）→ `crystal_spawn_requested(pos)`。
- GameLoop 仲裁 `_on_crystal_spawn_requested`：先消散旧水晶（同屏至多 1 颗）→
  `Crystal.new()` 代码组装（非池化）→ `activate(elemental, enemy_grid)`。

### 3.2 Crystal（`scripts/entities/crystal/crystal.gd`，class_name Crystal extends Node2D）

| 常量 | 值 | 分支 |
|---|---|---|
| HIT_RADIUS | 26.0 | 弹-晶碰撞半径（+弹 effective_radius） |
| FIR_RADIUS / FIR_RATIO | 90.0 / 0.8 | FIR：来源武器 `settle_aoe(pos, 90, panel×0.8, secondary=true)` |
| ICE_RADIUS / ICE_ATTACH | 100.0 / 50.0 | ICE：半径圆查逐敌 `apply_attach(ICE, 50, {snapshot: panel})` |
| WAT_RADIUS / WAT_ATTACH | 100.0 / 50.0 | WAT：同 ICE（元素 WAT） |
| KIN_RADIUS / KIN_RATIO | 90.0 / 0.4 | KIN：`settle_aoe(pos, 90, panel×0.4, true)` |
| LTG 臂 | — | `shock_chain_from_crystal(self, base)`；base = 弹 `last_hit_damage`>0 ? 之 : panel（H1） |

- `panel` 真源 = 命中弹 `panel_snapshot.base_atk`；FIR/KIN 臂 weapon_ref 失效守卫（null 跳过）。
- ICE/WAT 臂几何镜像 `ElementalSystem._spread_reaction`：网格保守超集 → 窄相
  `distance ≤ radius + hitbox_r`，dead 跳过；经 `apply_attach` 入口（芯片/共鸣乘区系统侧统一生效）。
- LTG 臂借 `_shock_chain` BFS（element_states.shock 表：35% 首跳 / 0.6 衰减 / 160px），
  每跳 3 目标；`shock_chain_from_crystal` 入口 `<=0` 短路。
- 结算尾 `DebugStats.count(&"crystal_shatter")` + 无条件 `dissolve()`。
- 渲染：`_draw` 紫晶 (0.66,0.42,1.0,0.92) r26 + 白核 r8；z_index=3；`static var active`
  同屏唯一引用；`_exit_tree` 兜底摘除。

### 3.3 弹侧契约（ProjectileBase）

- `last_hit_damage`：最近一跳结算伤害回填（`_on_settled` p_result≠null）；spawn/_reset_state 清零。
- `_check_crystal_hit()`：team==0 敌循环结算后 `if _live:` 调用（敌先结算保 LTG 当跳伤害新鲜）；
  active/valid/alive 三守卫；一帧一水晶一条（`hits_this_frame[c.uid]`，E-03 同构）；
  距离 > `effective_radius() + HIT_RADIUS` → 不中；命中 → `shatter(self)`。
- ★ **弹不耗穿透、不回收、继续飞**（水晶非敌实体，不占穿透预算）；team1（敌弹）零改动。

### 3.4 消散出口（三处 + 顶替）

1. 击破尾 `dissolve()`；2. 波末 `EventBus.wave_cleared → GameLoop._dissolve_crystal`（订阅区追加，
  消散不读敌态、无连接序依赖）；3. `_clear_battlefield` 尾部（重开清场统一收）；4. 新水晶顶替。
**GAME_OVER 不清**（H3：结算屏后台残留无副作用，重开 `_reset_run_state` → `_clear_battlefield` 统一收）。

## §5 R4 MetaStore 类型守卫

`static _int_or(p_value, p_default, p_key) -> int`：TYPE_INT 直用；TYPE_FLOAT 且
`f == floorf(f)` 且 `|f| < 2^53`（IEEE 安全整数域）→ int；其余脏型 → push_warning +
`p_default` **单键回退**（不整档作废、不写回——与损坏判定树「全回退不写回」口径一致）。
替换四处：save_version(:65) / crystal(:76) / levels(:86) / stats(:243)；后续 clamp / 负值
分支不变（M1~M24 全绿即恒等证据）。

## §8 假设清单（H1~H3，未决风险显式化）

- **H1 水晶 LTG base**：雷击连锁基数 = 命中弹 `last_hit_damage`（>0）否则回退
  `panel_snapshot.base_atk`。依据：分裂子代/穿透末跳 `final_value` 更代表"当跳"强度；
  风险：跳字观感与设计预期偏差 → 试玩回收。
- **H2 双元素连乘**：反应双元素各自判定共鸣后**连乘**（res(a)×res(b)，上限 1.15²≈1.3225）。
  依据：双元素臂语义对称；未见对单元素判定的方案级裁定。乘区红线由管线 cap_prod 8.0 兜底。
- **H3 水晶副作用面**：激光/近战 AOE（非 ProjectileBase 通道）与敌弹（team1）不触发水晶；
  GAME_OVER 态不清水晶（结算屏后台残留无逻辑副作用——水晶不 tick 不索敌），重开统一收。
  依据：弹侧唯一检查点在 `_check_collision` team0 路径；副作用面收敛。
