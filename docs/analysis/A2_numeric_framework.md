## 0. 设计总纲：五层防崩坏体系

用户红线："**绝不能让数值在吃一两个基础 Buff 后直接崩坏**"。本文全部规则收束为一个五层防御纵深，任何词条、遗物、反应的伤害路径都必须依次穿透以下五层：

| 层 | 名称 | 机制 | 落点章节 |
|---|---|---|---|
| L1 | **归类守门** | 词条进哪个池由注册表声明，池枚举封闭；跨池绝不合并、未声明不得参与结算 | §1.9 |
| L2 | **堆叠衰减** | 加算池同 ID 叠层边际几何递减；乘区池同条件合并为单一虚拟乘区（亚指数化） | §1.3、§2.1、§2.3 |
| L3 | **结构钳制** | 单区贡献上限 `cap_pool_p`、单结算乘区数上限、Flat 比例钳制、CDR/射速上限 | §2.1~2.2 |
| L4 | **总量封顶** | 乘区段整体钳制 `cap_prod`（软上限）；单发比率告警线 `R_alarm` + 保险钳制 | §2.2 |
| L5 | **结算幂等与审计** | 帧级去重、死亡短路、防御性去重、全程审计日志与遥测指标 | §2.5、§7.3 |

设计哲学：**玩家的"质变感"来自覆盖率与机制突变的提升，而非瞬时倍率的无界增长**。倍率天花板是恒定的（L4），玩家成长体现在"多接近天花板"与"多久维持在天花板附近"。

## 1. 伤害公式完整形式化

### 1.1 主公式

用户给定公式的完整落地形式（编号 F1）：

$$
\text{Final} = \underbrace{\Big(\text{BaseATK} \times \big(1 + \Sigma_{\text{add}}\big) + \Sigma_{\text{flat}}\Big)}_{\text{面板段 } A} \times \underbrace{\prod_{p=1}^{P} M_p}_{\text{乘区段}} \times \underbrace{\prod_{l} L_l}_{\text{私有乘区段}} \times \underbrace{C}_{\text{暴击因子}} \times \underbrace{(1 - r_{\text{type}})}_{\text{目标侧抗性}}
\tag{F1}
$$

各段语义与约束（后文逐段展开）：

| 符号 | 语义 | 约束 |
|---|---|---|
| `BaseATK` | 武器基础攻击（来源链见 §1.2） | 表驱动，唯一真源 |
| `Σ_add` | 加算池有效总贡献（同 ID 叠层衰减后、跨 ID 线性求和，见 §1.3） | 池级总量钳制 `cap_add_*` |
| `Σ_flat` | Flat 池（固定伤害加值）总和 | ≤ `f_flat` × BaseATK（比例钳制） |
| `M_p` | 第 p 个**虚拟乘区**（同条件同类合并后的聚合区，见 §1.5） | p ≤ `cap_mul_count`；∏ M_p ≤ `cap_prod` |
| `L_l` | 武器私有乘区（如光束灼焦叠层，见 §1.6） | 不占乘区名额、不受 `cap_prod`，自有 `cap_local` |
| `C` | 暴击因子（roll 或期望，见 §1.7） | ∈ {1, 1 + `d_crit`}，不受任何池约束 |
| `r_type` | 目标对该伤害类型的抗性 | ∈ [`r_min`, `r_max`]（负值 = 增伤） |

> **公式结构测试锚点**（对应 AC-12.1）：注入 BaseATK=100、两个不同 ID 的加算词条（+20%、+30%，各 1 层，首层全额）、Flat=+10、两个不同条件乘区 ×1.5 与 ×1.4、非暴击、零抗性 → $(100 \times 1.5 + 10) \times 1.5 \times 1.4 = 336$。若任一加算被误入乘区（$100 \times 1.2 \times 1.3 \times 1.5 \times 1.4 + \dots$）结果偏离 336，测试失败。**该用例的两个加算词条是不同 ID 且各 1 层，因此不触发叠层衰减**——这是公式结构测试，衰减正确性由 §2.1 的独立用例族覆盖。

### 1.2 BaseATK 来源链

BaseATK 是**单一标量**，其合成链固定为两级（F2）：

$$
\text{BaseATK} = \text{weapon\_base\_atk}(\text{weapon\_id},\ \text{weapon\_lv}) \times g_{\text{global}}
\tag{F2}
$$

- **第一级 `weapon_base_atk`**：武器表（WeaponData）按武器等级直接给出的**终值**（A3 的 `upgrade_table[L1..L5]` 形态）。武器等级由"武器精通"卡驱动。**表驱动优先于公式**：等级成长不另设公式，避免双真源。
- **第二级 `g_global`**：全局攻击成长系数（当前版本 $g_{\text{global}} = 1$，即无此来源；预留位）。若未来引入玩家账号级/局外成长，**必须以乘法小因子形式** $\prod (1 + g_i)$ 进入 BaseATK，且来源数 ≤ 3、每源 g_i ≤ `cap_g`。禁止并入加算池（确定性收益不应被叠层衰减稀释），禁止并入乘区池（基础面板不应挤占乘区名额与乘积预算）。
- **玩家局内属性成长卡**（如卡池耗尽 fallback 的"+5% 攻击"）：**并入 Add_ATK 池**，接受叠层衰减——它们在定位上就是"平庸词条"（用户原文对加算池的定位）。

### 1.3 Additive 加算池

**语义**：数值小、无条件常驻（或触发条件近乎恒真）的"平庸"增益。用户原文点名要求边际递减。

**归类规则**：满足以下全部条件的词条进加算池——
1. 效果是"属性百分比/数值修正"（攻击%、射速%、移速%、HP、暴击率、暴伤加成、拾取半径……）；
2. 无条件触发，或条件覆盖率在设计期望上 > 90%（近常驻）；
3. 单张卡的期望输出贡献低于稀有度对应门槛（紫卡以下量级）。

**衰减模型（本框架核心裁定之一）**——词条级边际几何衰减，跨 ID 线性求和：

$$
\Sigma_{\text{add}} = \sum_{i \in \text{pool}} T_i(n_i), \qquad
T_i(n) = \sum_{j=1}^{n} c_i \cdot \delta_i^{\,j-1} = c_i \cdot \frac{1-\delta_i^{\,n}}{1-\delta_i}
\tag{F3}
$$

- `c_i`：词条 i 单层基础值（A3 落数）；
- `δ_i`：该词条的层衰减率（A3 落数，**约束 δ ≤ 0.92**，见下）；
- `n_i`：该词条当前叠层数。

**满足 AC-12.3 验收口径**（本文显式定义口径，供测试断言）：
- 首层全额：$T_i(1) = c_i$；
- 边际严格递减：$\Delta T_i(j) = c_i \delta_i^{j-1}$ 关于 j 严格递减（δ<1 恒成立）；
- n ≥ 2 时严格 $T_i(n) < n \cdot c_i$；
- $T_i(5) \le 4.3\, c_i$：由 $(1-\delta^5)/(1-\delta) \le 4.3$（即 $\delta^5 - 4.3\delta + 3.3 \le 0$）数值解得 **δ ≤ 0.92**（保守取整；精确根 ≈ 0.9245，A3 填表时的硬约束）。

**关键设计区分**：衰减作用于**同 ID 叠层**（玩家重复拿同一张卡），**不同 ID 词条之间线性求和**。这既满足用户"堆叠平庸词条递减"的意图，又保证 AC-12.1 公式结构测试（两个不同词条线性）的数值不变。

**池级兜底**（第五层防御，正常游玩不可达）：同池所有 ID 的有效贡献总和再受一个宽松的渐近钳制：

$$
\Sigma_{\text{add}} \le \text{cap\_add}_{\text{pool}}
\tag{F4}
$$

（如 `cap_add_atk`、`cap_add_rof`……占位符，A3 落数。语义是"数据膨胀保险丝"，卡池规模天然约束下玩家永远达不到，仅为未来上百张卡的内容膨胀预留。）

**负贡献例外**：诅咒类词条（如"ATK −10%"）产生负 raw，**线性全额生效、不衰减**——衰减的目的是抑制增益堆叠，负面效果必须全额才有惩罚语义（裁定 #10）。

### 1.4 Flat 池

**语义**：固定伤害加值（"+X 伤害"），在乘区**之前**并入面板段——公式位置决定它会被所有乘区放大，因此是危险池。

**规则**：
- 来源：词条 `flat_atk`、遗物固定加值；
- 比例钳制（L3）：$\Sigma_{\text{flat}} \le f_{\text{flat}} \times \text{BaseATK}$（`f_flat` 占位符，A3 落数；当次结算的 BaseATK 为基准）；
- **天然相对递减**：BaseATK 随武器等级指数成长，而 Flat 是绝对值，占比自动随时间缩小——Flat 不需要额外的叠层衰减曲线；
- Flat 不参与暴击期望之外的特殊处理（它就是面板段的一部分）。

### 1.5 Independent 独立乘区（虚拟乘区模型）

**语义**：条件触发的协同乘数（"对冰冻目标 ×1.5""反弹后 ×1.4""每穿透一层 +0.2"）。本作的核心卖点与核心风险同源，故本池是护栏最重的池。

**数据模型**：每个乘区词条实例在结算时向 ModifierStack 推入一条记录：

$$
(\text{pool\_id},\ \text{source\_uid},\ \text{contrib})
\tag{F5}
$$

- `pool_id`：**封闭枚举**的乘区标识（如 `frost_dmg`、`burn_dmg`、`bounce_dmg`、`pierce_dmg`、`fury_dmg`、`opening_dmg`、`elite_dmg`、`vuln`……全集见 §7.4 注册表范式）；
- `source_uid`：词条/遗物**实例**的唯一标识（区分"同一实例重复触发"与"两个不同实例"）；
- `contrib`：贡献值，可为**上下文变量的函数**（如 `pierce_dmg` 区贡献 = `k_pierce × (pierce_index − 1)`，实现"每穿透累进"语义）。

**聚合规则（防叠乘核心，详见 §2.3）**：按 `pool_id` 分组合并为**单一虚拟乘区**：

$$
M_p = 1 + \min\Big(\sum_{j \in p} \text{contrib}_j,\ \text{cap\_pool}_p\Big)
\tag{F6}
$$

- 同池多实例（两张同名卡、词条 + 遗物）→ 贡献**加算合并**；
- 单区贡献和受 `cap_pool_p` 硬顶（L3，每池独立声明，A3 落数）；
- 不同 `pool_id` 的虚拟乘区之间**连乘**。

**条件求值时机**：贡献值在**命中瞬间**基于 DamageContext 快照求值（`ctx` 中的 `bounce_count`、`pierce_index`、`target_states`、`player_hp_pct`、`wave_first_hit` 等，见 §7.1）。穿透多目标时每个目标独立结算一次（幂等键含 target_uid），`pierce_index` 逐目标递增——累进乘区由此获得"越串越痛"的语义。

### 1.6 Local 私有乘区（裁定 #5 引入的正式池）

**语义**：武器**行为机制**自带的、随使用状态增长的乘区（当前唯一实例：脉冲光束灼焦叠层）。它不是玩家构筑强度，而是武器手感曲线。

**规则**：
- 独立于全局乘区段，**单独连乘**：$\prod_l L_l$；
- **不占**乘区数量名额（`cap_mul_count`）、**不受** `cap_prod` 约束；
- 自有硬顶：$L_l \le \text{cap\_local}_l$（灼焦即"最大层数 × 每层值"，A3 已按此给表）；
- 总放大上界 = `cap_prod` × ∏`cap_local`，仍是有界闭式（如 8.0 × 1.64），不破坏 L4 的总量可控性。

**入全局池与否的判据**（供未来新武器判断）：增益来源是"玩家花卡牌预算买的" → 全局池；增益来源是"武器自身使用行为" → Local 池。

### 1.7 CritFactor 暴击因子

**双语义**（必须严格区分）：

- **实际结算（roll 语义）**：每次命中独立掷骰 Bernoulli(`p_crit`)，
  $$C = \begin{cases} 1 + d_{\text{crit}} & \text{暴击} \\ 1 & \text{非暴击} \end{cases} \tag{F7}$$
  掷骰用可注入种子的独立 RNG 流（AC-12.5，固定种子可复现确定序列）。
- **平衡计算（期望语义）**：面板与 DPS 模型一律用
  $$E[C] = 1 + p_{\text{crit}} \times d_{\text{crit}} \tag{F8}$$

**参数链**：
- $p_{\text{crit}} = p_0 + T_{\text{crit-rate}}(n)$，其中 `p_0` 为武器表基率，暴击率词条走 §1.3 的加算衰减，上限 `cap_crit_rate`（=1.0）；
- $d_{\text{crit}} = d_0 + T_{\text{crit-dmg}}(n)$，其中 `d_0` = 基础暴伤加成（暴击倍率 − 1），暴伤词条同样走加算衰减。

**位置裁定（裁定 #2）**：C 在乘区段与 Local 段**之后、抗性之前**，作为最外层独立因子——**不进任何池、不占乘区名额、不受 `cap_prod` 约束**。理由：① 用户原文公式即将其置于最外层；② 暴击是"命中瞬间的反馈事件"（GameFeel 分级的触发器），不是构筑强度，不应被乘区预算压缩；③ 期望语义乘法交换律下位置不影响 E[DPS]，但独立位置使审计口径（构筑强度告警线，§2.2）不被暴击波动污染。

**排除项**：DOT 跳伤与元素反应结算**不掷暴击**（裁定，见 §4.5）——它们有独立的 GameFeel 通道（反应触发质变级反馈），且期望模型因此保持线性可加。

### 1.8 目标侧修正：抗性与易伤

- **抗性**：$r_{\text{type}} \in [r_{\min}, r_{\max}]$（占位符，允许负值 = 增伤，如超导击破）。实现 `Final = raw × C × (1 − r)`，抗性在乘区段之后生效，**不占名额、不受 cap_prod**（它是敌我关系修正，不是玩家构筑强度；值域有界即天然护栏）。
- **易伤**（冰冻寒滞等）：实现为**目标侧乘区**，`pool_id = vuln`，进全局乘区段参与连乘与 `cap_prod`——它来自玩家的元素构筑投入，本质是构筑强度的一部分，必须吃 L4 总量约束。
- **本作无护甲系统**（用户需求未定义）；抗性槽位即等价扩展点，未来若引入护甲/减伤，在 $(1-r)$ 同层扩展乘法修正并声明值域钳制即可，不动主公式结构。

### 1.9 归类总则（守门规则，L1）

**同类型词条只进同池，跨池绝不合并。** 落地为三条工程性守门：

1. **词典范式**：每条词条/遗物数据（.tres）必须声明 `(pool_class, pool_id)`，其中 `pool_class ∈ {ADD, MULT, LOCAL, REACTION, MECHANIC, ELEMENTAL}`；`pool_id` 取自**封闭枚举注册表**（§7.4）。未声明或枚举外 ID 的词条在 M-14 启动校验期**直接剔除并报错**——数据驱动不允许"绕过护栏私开新池"。
2. **单向转换**：数值在结算管线内只能沿"加算池 → 面板段 → 乘区段 → Local 段 → 暴击 → 抗性"的单向顺序流动；任何反向引用（乘区结果影响加算池等）视为结构违规。
3. **新增乘区池需框架评审**：新 `pool_id` 意味着新的连乘维度，必须同时声明 `cap_pool_p` 并通过 §2.2 的乘积预算压力测试，方可进枚举。

## 2. 池级护栏（数值不崩坏的硬约束）

### 2.1 各池护栏总表

| 池 | 来源上限（单结算） | 同 ID 堆叠上限 | 堆叠衰减 | 池级硬顶 |
|---|---|---|---|---|
| Add_ATK | 全部生效词条 | `max_stack_i`（词条级，A3 定） | 同 ID 边际几何衰减 δ_i ≤ 0.92（F3） | `cap_add_atk`（保险丝） |
| Add_ROF / Add_CDR | 同上 | 同上 | 同上 | `cap_rof`（绝对射速上限，性能双护栏）/ `cap_cdr` |
| Add_Crit / Add_CritDmg | 同上 | 同上 | 同上 | `cap_crit_rate` = 1.0 / `cap_crit_dmg` |
| Flat | 全部生效 | 词条级 | 无（相对通胀自动递减） | `f_flat` × BaseATK |
| MULT（每 pool_id） | 同池合并为 1 区 | `max_stack_i` | **线性合并不衰减**（乘区定位=条件高价值，与加算池的"平庸递减"形成用户原文要求的定位差异） | `cap_pool_p`（单区贡献和硬顶，**每池必填**） |
| MULT（总段） | ≤ `cap_mul_count` 个区 | — | 超出取贡献最大的 N 个 | ∏ M_p ≤ `cap_prod` |
| LOCAL（每 local_id） | 武器实例自有 | 层数上限 | 线性 | `cap_local_l` |
| REACTION | 独立结算通道 | 反应 CD | 系数 χ 乘区独立通道 | `R_rxn` × 快照（告警线） |

> 加算池衰减与乘区池不衰减的**理论依据**：用户原文对两池的定位差异——加算池是"平庸词条且随层数递减边际效应"，乘区池是"特定条件触发"的高价值协同。乘区的防崩不靠曲线而靠合并（亚指数）+ 名额 + 单区硬顶 + 总量封顶四层，见 §2.3。

### 2.2 全局乘区数量上限、总乘积软上限与工程实现

**数量上限（AC-12.4）**：单结算参与乘区数 $P \le N_{\text{mul}}$（A1 定 8，含目标侧易伤 `vuln` 区）。超出时按 $(M_p - 1)$ 降序取前 `N_mul` 个，被截断区记入审计日志。

**总量软上限（裁定 #6）**：乘区段整体钳制 + 审计：

$$
\prod_{p} M_p \;\longrightarrow\; \min\Big(\prod_{p} M_p,\ \text{cap\_prod}\Big)
\tag{F9}
$$

超限处理选型论证（brief 给了"压缩或 cap"两个选项，本文裁定）：
- **比例压缩**（各区等比缩放，保持构筑间差异）：需迭代求解压缩因子，实现复杂；且触顶本身是设计外的罕见事件（A3 §9.1 压力手算峰值 ×7.03 < 8.0，触顶率目标 < 0.5%），触顶瞬间"保持区际差异"的体验收益趋近于零；
- **整体钳制（采纳）**：一行实现、精确、可预测、审计友好。M2+ 若数据显示触顶率超阈值，再升级为比例压缩（预留接口）。

**单发比率告警线（AC-12.6，第二道闸）**：

$$
\frac{A \times \prod M_p \times \prod L_l \times C}{\text{BaseATK}} \le R_{\text{alarm}}
\tag{F10}
$$

- 口径：**抗性前**（只测玩家构筑强度，不被敌我关系修正污染）；
- 超限行为：**告警日志（同类构筑一局内只告警一次）+ 计数 + 保险钳制到 `R_alarm`**——正常路径数学上不可达（BaseATK×(1+cap_add)+f_flat·BaseATK 的面板段 ≤ ~2.5×，乘区段 ≤ 8.0，Local ≤ 1.64，暴击 ≤ 3.0 → 理论全顶 ~×100 远低于 500），触达即说明 L1~L4 某层失效，钳制是防崩的最后保险，计数是回归定位的线索。

**工程实现契约**（对应 M-12 职责边界）：
- 所有钳制发生在**结算前**的统一 clamp 阶段，顺序固定（池聚合 → 单区 cap → 数量截断 → 乘积 cap → Flat 钳制 → 暴击 → 抗性 → R_alarm）；
- 每次钳制写入 `DamageAudit` 结构随 `DamageResolved` 事件广播（§7.2），DebugStats 面板与 headless 回归（§6）消费同一数据源；
- **审计不改变结算结果**（只记录），保证确定性与可复现。

### 2.3 防叠乘规则（推荐裁定，含理由）

**规则**：**同条件同类型乘区合并为单一虚拟乘区（区值 = 1 + Σ贡献，受 `cap_pool_p` 钳制）；不同条件乘区独立连乘。**

例（引用 A3 词条）：两张"冰渊裁决 ×1.5" → 单区 $M_{\text{frost}} = 1 + 0.5 + 0.5 = 2.0$；"冰渊 ×1.5" + "烈焰吞噬 ×1.35"（双状态同时附着时）→ $M_{\text{frost}} \times M_{\text{burn}} = 1.5 \times 1.35$。

**四点理由**：

1. **指数抑制**：连乘的增长是超线性的（两张 ×1.5 连乘 = ×2.25，第三张 = ×3.375……指数爆炸），合并加算把同源堆叠的增长率压到线性，且被 `cap_pool_p` 截断——"吃两个同类 Buff"的增量有先验上界，直接回应"吃一两个 Buff 不崩坏"的用户红线。
2. **名额经济学**：乘区数量名额（8）是稀缺资源。合并让"同条件深化"只占 1 个名额，玩家在"深度（堆同条件）× 宽度（拓新条件）"间做真实权衡，构筑方差的上限天然受控。
3. **心智可预测**：玩家可心算"第二张冰渊 → 区内 +0.5 → ×2.0"；而"两张各自独立 ×1.5×1.5 = ×2.25 还占两个名额"的模型既难心算又难平衡。
4. **平衡可控性**：每个 `pool_id` 的最坏情形有闭式上界（`cap_pool_p`），平衡团队可对每个条件乘区预计算极端增量，回归测试可按池断言（§6.1 乘区审计指标）。

**双层去重规则（调和 A1 AC-12.2 与 A3 堆叠设计的关键裁定）**：

| 层 | 触发场景 | 规则 | 验收锚点 |
|---|---|---|---|
| **聚合层（合法路径）** | 玩家合法持有同 pool 的**多个不同实例**（两张卡、词条+遗物） | 合并加算（F6） | A3 构筑手算：两张冰渊 → ×2.0 |
| **防御层（异常路径）** | 同一结算中同 `(pool_id, source_uid)` 推入多条（E-03 同帧重入、实现 bug、直接注入） | **去重取最大** + 审计计数 | AC-12.2：注入两条同 ID ×1.5 → 150 而非 225 |

正常代码路径下聚合层保证一次结算每个 `pool_id` 只有**一条**虚拟乘区记录，防御层永不触发；AC-12.2 的测试用例语义因此澄清为"**绕过聚合层直接向结算管线注入两条同 ID 记录**"（测试注入层差异，非设计冲突，详见 §9 融合备忘第 1 条）。

### 2.4 帧级幂等与死亡短路（L5，对应 AC-12.7 / E-03 / E-06）

- **幂等键**：`(source_uid, target_uid, frame)`。同一投射物同一帧对同一敌人只结算一次（穿透多目标时每目标一次，键中 target_uid 不同故各自合法）；重复请求丢弃并计数。
- **投射物侧帧聚合**：一帧内的多次 overlap 回调先聚合、后统一提交（一帧一目标一条），词条层加"本帧已触发"标记。
- **死亡短路**：首次致死结算后目标立即置 dead 标志，本帧后续请求丢弃并计数；死亡表现只执行一次。

### 2.5 乘区审计指标（遥测口径）

每次结算产出以下审计字段（§7.2），聚合为全局指标，供 §6 KPI 消费：

| 指标 | 定义 | 健康线 |
|---|---|---|
| `mul_count_dist` | 单结算乘区参与数分布（P50/P95） | P95 < `cap_mul_count` × 0.75 |
| `mul_product_p95` | 乘积分布 P95 / `cap_prod` | < 0.85 |
| `compress_rate` | 乘积触顶（F9 生效）结算占比 | M1 = 0；M2+ < 0.5% |
| `dedup_defense_count` | 防御层去重触发计数 | = 0（>0 即 bug） |
| `truncate_count` | 数量截断触发计数 | 接近 0（频繁触发说明乘区词条过量） |
| `alarm_count` | R_alarm 告警计数 | = 0 |

## 3. 衍生公式族

### 3.1 射速与冷却

$$
\text{rate} = \min\big(\text{rate}_0 \times (1 + \Sigma_{\text{add,rof}}),\ \text{cap\_rof}\big)
\tag{F11}
$$

$$
\text{cd} = \text{cd}_0 \times \big(1 - \min(\Sigma_{\text{add,cdr}},\ \text{cap\_cdr})\big)
\tag{F12}
$$

- `Σ_add,rof / Σ_add,cdr` 均为 §1.3 衰减后的池和（CDR 是减算池，衰减 + 上限双钳制）；
- `cap_rof` 兼任**性能护栏**（射速 × 分裂数 = 弹幕生成速率，与 M-13 池容量联动）；
- 加特林类变体：$\text{rate}(t)$ 为分段函数（预热斜坡 → 满热平台 → 冷却重置），DPS 期望用时间加权平均 $\bar{r} = \frac{1}{T}\int_0^T \text{rate}(t)\,dt$。

### 3.2 DPS 期望模型（平衡演算的核心工具）

$$
E[\text{DPS}] = \underbrace{\text{rate}}_{\text{频率}} \times \underbrace{E[n_{\text{hit}}]}_{\text{单发命中期望}} \times \underbrace{E[\text{Final}]}_{\text{单次结算期望}}
\tag{F13}
$$

其中单次结算期望引入**覆盖率模型**——条件乘区按期望覆盖率 γ 折算：

$$
E[\text{Final}] = \Big(\text{BaseATK}\,(1+\Sigma_{\text{add}}) + \Sigma_{\text{flat}}\Big) \times \prod_p \big(1 + \gamma_p \cdot c_p\big) \times \prod_l L_l \times \big(1 + p_{\text{crit}} d_{\text{crit}}\big) \times (1 - \bar{r})
\tag{F14}
$$

- $\gamma_p \in [0,1]$：乘区 p 的条件覆盖率（状态覆盖率 × 命中时序覆盖率，由 §4.6 附着期望模型导出；A3 构筑手算中冰冻 75% 覆盖即此参数）；
- $c_p$：该区满额贡献（衰减/钳制后）；
- $\bar r$：抗性期望（按敌人构成加权）。

> 覆盖率模型是"瞬时倍率有界、质变感来自覆盖率提升"设计哲学的数学化：构筑成长的主要通道是抬升 γ_p（更快附着、更长状态、更多反弹回流），而非抬高 c_p（受 cap 钳制）。

### 3.3 单发命中期望与群体效率系数 k_aoe

$$
E[n_{\text{hit}}] = n_{\text{pellet}} \times p_{\text{aim}} \times \big(1 + \bar{n}_{\text{pierce}}\big) \times \big(1 + \beta_{\text{bounce}}\big) \times \big(1 + \sigma_{\text{split}}\big) \times \rho_{\text{aoe}}
\tag{F15}
$$

| 因子 | 语义 | 参数来源 |
|---|---|---|
| `n_pellet` | 单次开火投射物数（霰弹/多重装填） | 武器表 + 词条 |
| `p_aim` | 命中概率（散射 × 弹速 × 目标密度，蒙特卡洛标定） | §6 模拟回归 |
| `1 + n̄_pierce` | 穿透附加命中倍数 | 武器 pierce + 词条 |
| `1 + β_bounce` | 反弹回流比（反弹后再次命中期望，含折射寻的） | 词条 + 走位模型 |
| `1 + σ_split` | 分裂增殖系数（子代期望命中 × 继承比例 × 代际分布） | 词条，代际 ×0.5 递减（A3 Q-9） |
| `ρ_aoe` | 溅射/范围覆盖（爆炸半径内敌均数） | 武器 blast_r × 敌密度 |

定义 $k_{\text{aoe}} \equiv E[n_{\text{hit}}]$（群体效率系数），与 A3 §1.5 的 k_aoe(w) 表对接——A3 的表值即本式的实测/模拟标定值。

**工程天花板**：$E[n_{\text{hit}}] \times \text{rate} \times \sigma_{\text{split}}$ 的连乘受同屏投射物硬上限（M-13 池 2000）与 `cap_rof` 隐式钳制，理论 DPS 存在闭式工程上界（回归测试断言用）。

### 3.4 有效 HP（EHP）

**敌方侧**（相对玩家某元素口径的有效血量，TTK 的分母）：

$$
\text{EHP}_e = \frac{\text{HP}}{(1 - r_{\text{type}}) \times M_{\text{vuln}}}
\qquad\Rightarrow\qquad
\text{TTK} = \frac{\text{EHP}_e}{E[\text{DPS}]}
\tag{F16}
$$

**玩家侧**（本作无减伤/护甲，Q-16 简化受击路径）：

$$
\text{EHP}_p = \text{HP}_{\max} \times \big(1 + n_{\text{shield}}\big), \qquad
\tau_{\text{stand}}(w) = \frac{\text{HP}_{\max}}{D_{\text{contact}}(w)} \times t_{\text{tick}}
\tag{F17}
$$

- $\tau_{\text{stand}}$ = 站桩致死时间（接触伤害按无敌帧节拍 $t_{\text{tick}}$ 结算）；
- 成长关系：$D_{\text{contact}}(w)$ 指数（`c_dmg`）快于 $\text{HP}_{\max}(w)$（近似 `c_php` < `c_dmg`）→ $\tau_{\text{stand}}$ 单调缩短 → 逼迫走位与生存卡投资（弹幕防守的体验内核，A3 §8.2 已验证该形态）。

### 3.5 清屏时间与压力系数

$$
T_{\text{clear}}(w) = \frac{\text{HP}_{\text{wave}}(w)}{E[\text{DPS}](w) \times u}, \qquad
P(w) = \frac{T_{\text{clear}}(w)}{T_{\text{window}}(w) + T_{\text{buffer}}}
\tag{F18}
$$

- `u` = 有效输出占比（uptime：走位、瞄准空过、预热、升级暂停损失的时间折算，设计校验用 `u_design` 占位）；
- **压力系数 P(w) 的三条硬约束**（回归断言）：
  1. $P(w) \le 1 - \delta_{\text{margin}}$（任意波，数学死锁防线）；
  2. P(w) **单调非减**（允许平台，禁止中途压力骤降——难度体验的一致性）；
  3. $P(w_{\text{cap}}) \to 1 - \delta_{\text{margin}}$（无尽模式后期收敛到压力满格 = 自然死亡窗口）。
- 与 A3 的关系：A3 §8.3 的"清屏余量 41% → 9%"即 $P = 0.59 \to 0.91$，P 的递增即设计意图（压力渐满），本式为其形式化（裁定 #9）。

## 4. 元素系统规则框架

### 4.1 模型总览：附着—衰减—触发—消耗

每个敌人持有三个元素槽（FIR / ICE / LTG），各槽独立维护**附着计量 G**：

$$
\frac{dG}{dt} = a - \lambda_{\text{ele}} \cdot G, \qquad G \in [0, G_{\max}]
\tag{F19}
$$

- **附着强度**：$a = \text{attach\_val} \times f_{\text{hit}}$（每次元素命中积累 `attach_val`，$f_{\text{hit}}$ 为该元素命中频率）；
- **衰减速率**：比例衰减 $\lambda_{\text{ele}} G$（各元素可异参）。**选比例而非线性衰减的裁定理由**：比例衰减存在**稳态免疫线** $G^* = a/\lambda$——若 $G^* \le G_{\max}$ 则永远无法满槽。这天然实现"低频刮痧不触发状态"（杂兵蹭两下火不该点燃），低投入元素构筑被自动过滤，防呆且防崩；
- **触发条件**：$G \ge G_{\max}$ → 触发对应状态 → **消耗**（清空该槽）；
- **填充时间闭式解**（平衡演算用）：
  $$T_{\text{fill}} = -\frac{1}{\lambda}\ln\Big(1 - \frac{\lambda G_{\max}}{a}\Big) \quad (a > \lambda G_{\max}) \tag{F20}$$
- **重复附着**：状态存续中再次命中 → 刷新状态时长（不叠计量，槽已清空重新积累）。

### 4.2 状态效果定义（框架层）

| 状态 | 类型 | 数值通道 |
|---|---|---|
| 点燃 FIR | DOT（独立结算，§4.5） | 每跳 = 快照面板 × `coef_dot`，跳数 = 时长 / 跳间隔 |
| 寒滞/冰冻 ICE | 行为修正 + 易伤 | 减速 = 移速乘 `slow_factor`；易伤 = 目标侧乘区 `pool_id = vuln`；完全冻结（定身）受免疫矩阵约束 |
| 感电 LTG | 连锁传导（独立结算） | 每跳 = 触发伤害 × `coef_chain` × `decay_chain^(j-1)`，深度 `depth_chain`，同结算周期同目标去重 |

**免疫矩阵（裁定 #7 的形式化）**：状态效果 × 敌人 tag 的可配置免疫掩码 `immune_mask`（如 Boss 免疫"定身"但不免疫"减速/易伤"）。数值依据：定身是**行为中断**，对 Boss 的 TTK 是乘法性缩短（定身期间 DPS 全额倾泻 = 变相压缩 32s 锚点）；减速/易伤是**标量修正**，值域有界、可进 TTK 期望线性折算。框架支持任意状态 × 任意 tag 的组合配置，玩法侧自由裁剪。

### 4.3 两两反应（混合引爆）

**触发检测**（E-07 竞态处理）：敌人状态容器的**帧末统一检测**，固定优先级（按设计意图声明，当前：FIR+ICE > FIR+LTG > ICE+LTG），一帧至多触发一个反应，结果可复现（事件日志含顺序号）。

**反应类型框架**（效果数值全为 A3 自由度，框架只锁结构）：

| reaction_id | 元素对 | 效果类型 | 结算结构 |
|---|---|---|---|
| `RXN_FIR_ICE` | 火+冰 | 引爆型：立即结算点燃剩余 DOT 总额 × `χ_1` | 独立结算（F21） |
| `RXN_FIR_LTG` | 火雷 | 爆炸型：半径 `R` 范围 `χ_2` × 面板快照 | 独立结算 + AOE |
| `RXN_ICE_LTG` | 冰雷 | 削抗型：目标全抗性 − `χ_3`，持续 `t` | 抗性值修改（§1.8 通道，非伤害） |

- **消耗**：触发后清空参与双槽；
- **反应 CD**：同目标同反应 `cd_rxn` 内不重复触发（占位符，A1 推荐 2s 为初值锚点）；
- 中性命名 `RXN_<ELE>_<ELE>` 规避 A1/A3 的命名分歧（碎裂 vs 融化等，见 §9）。

### 4.4 三重反应（框架定义，默认关闭）

**触发条件**：三槽同时非空且各槽 $G \ge \theta_{\text{tri}} \cdot G_{\max}$（`θ_tri` 占位，建议高门槛如 0.6+）。

**效果类型定义（三相湮灭）**：按固定优先级依次结算全部三个两两反应（系数统一 × `χ_tri` 修正），清空三槽，冷却 `cd_tri` > `cd_rxn`。

**默认 `enabled = false` 的裁定理由**：① 卡牌预算下三系满铺的构筑在 28 词条池中概率极低，设计复杂度与触达率不成比；② 两两反应已覆盖元素对的全组合；③ 框架层定义 + 开关预留，M2+ 若元素卡池扩充可零成本启用。**本期验收不含三重反应**（A1 AC-11.4 亦仅覆盖两两）。

### 4.5 反应伤害的公式定位（推荐裁定 + 论证）

**裁定：独立结算，不进乘区管线。**

$$
D_{\text{rxn}} = \chi_{\text{rxn}} \times \phi \times S_{\text{snap}}, \qquad S_{\text{snap}} = \text{BaseATK}(1+\Sigma_{\text{add}}) + \Sigma_{\text{flat}}
\tag{F21}
$$

- `S_snap`：触发时刻的**攻击者面板快照**（含加算池，不含任何条件乘区、Local、暴击）；
- `χ_rxn`：反应系数（A3 表值）；`φ`：反应强化乘区（独立通道——"元素裂变"类词条只乘 χ，不进命中乘区池）；
- 上界：$D_{\text{rxn}} \le R_{\text{rxn}} \times S_{\text{snap}}$（独立告警线，同 R_alarm 机制）。

**四点论证**：

1. **解耦防二次放大螺旋**：若反应伤害进乘区管线（作为一次"命中"），构筑乘区会放大反应、反应又触发更多附着 → 乘区×反应的交叉放大无先验上界。独立结算使反应强度只由 χ 与快照决定，与玩家乘区堆叠**正交**，最坏情形闭式有界。
2. **乘区名额经济学**：8 个名额是玩家构筑的核心资源，反应是元素系统的被动产出，不应挤占名额（否则元素流构筑的乘区带宽被系统性压窄）。
3. **结算语义清晰**：反应是一次性事件（独立引爆），与持续命中流的结构不同——独立结算天然映射独立 GameFeel 分级（AC-11.5 质变级反馈），且不受 `cap_prod` 压缩（玩家花大价钱凑齐双状态附着，回报不该被总量封顶吞掉）。
4. **快照而非实时**：取触发瞬间面板快照，避免"先堆满状态再开爆发"的时序 exploits，也使期望模型（F14）可直接叠加反应项 $E[D_{\text{rxn}}] / T_{\text{cycle}}$ 而无需嵌套。

**同规则延伸**：DOT 跳伤、感电传导跳、死亡新星等"派生伤害"全部走独立结算通道（快照 × 系数），且**均不掷暴击**（§1.7 排除项）。

### 4.6 元素状态覆盖率（γ_p 的导出）

$$
\gamma_{\text{state}} = \frac{T_{\text{status}}}{T_{\text{fill}} + T_{\text{status}} + T_{\text{cd}}}
\tag{F22}
$$

- $T_{\text{fill}}$ 由 F20 给出，$T_{\text{status}}$ 为状态时长，$T_{\text{cd}}$ 为免疫/反应冷却空窗；
- 该式是乘区覆盖率 γ_p（F14）与附着投入（词条数、命中频率）之间的桥梁：元素词条投资的边际回报曲线由此可解析计算——这是 A3 构筑手算中"75% 冰覆盖"的公式化来源。

## 5. 成长与通胀模型

### 5.1 双曲线形态论证与一般式

**敌我两侧必须同为指数形态**，论证：设玩家 DPS 为 $D_0 c_{\text{dps}}^w$、敌 HP 为 $H_0 c_{\text{hp}}^w$，则

$$
\text{TTK}(w) = \text{TTK}_0 \cdot \Big(\frac{c_{\text{hp}}}{c_{\text{dps}}}\Big)^{w}
\tag{F23}
$$

- Roguelike 卡牌的每张输出卡本质是**乘法性**贡献（+X% 攻击、新乘区、新武器槽），玩家 DPS 天然指数增长；
- 若敌 HP 用线性（A1 Q-5 初推荐 `HP ×(1+0.15n)`）或幂次（`H0·n^1.35`），TTK 按 $\frac{n^{1.35}}{c^w}$ **坍缩至零**——中期开始所有敌人被瞬时蒸发，弹幕防御失去存在意义；
- 故 **TTK 恒定的充要条件是 `c_hp = c_dps`**（A3 的 1.12 双锚点即此实现）。**A1 Q-5 的线性 HP 模型在融合中被推翻，回写**（§9）。

**分段指数一般式**（为数字通胀与后期断崖预留调节阀）：

$$
X(w) = X_0 \prod_{i} c_i^{\Delta w_i}
\tag{F24}
$$

即按波次区间切换斜率：`[1, w_a]` 用 `c_1`（成长期），`[w_a, w_b]` 用 `c_2`，无尽段用 `c_∞`（可下调如 1.12 → 1.08，缓解数字位数膨胀与"少拿一张卡就断崖"的方差敏感）。**斜率同步约束**：任意区间的 `c_hp,i / c_dps,i` 偏差 ε 满足

$$
\big|\epsilon_i^{\Delta w_i}\big| \le \Delta_{\text{ttk}} \quad\Rightarrow\quad |\epsilon_i| \le \Delta_{\text{ttk}}^{1/\Delta w_i}
\tag{F25}
$$

（如 30 波区间容忍 TTK 漂移 ±10% → |ε| ≤ 1.1^(1/30) ≈ 1.0032——**双斜率必须高度同步**，这是设计红线，也是 §6 自动化回归盯防的核心指标。）

### 5.2 玩家 DPS 增长的来源分解（c_dps 的结构）

$$
c_{\text{dps}} = c_{\text{card}} \times c_{\text{slot}}^{\text{(稀疏跳升)}} \times c_{\text{mastery}}
\tag{F26}
$$

| 来源 | 形态 | 框架约束 |
|---|---|---|
| `c_card` 卡牌流 | 每波期望 `n_card(w)` 张 × 每张期望输出系数（按 §6.1 卡池构成权重加权） | 期望输出系数按 §1~§4 全公式族计算（含衰减、覆盖率、cap）——**手算线性近似禁止用于锚定校准** |
| `c_slot` 武器槽跳升 | 稀疏阶跃（新槽解锁波） | 跳升当波允许高出平滑曲线 `h_slot`（如 +8~12%），随后 `c_card` 摊薄回落；跳升点即 DPS 曲线的分段节点（F24） |
| `c_mastery` 武器精通 | 表驱动阶跃（L1→L5） | 终值表即全部真源，无公式 |

校准方向恒等式（A3 已采用的锚点，框架确认）：$\text{HP}_{\text{小怪}}(w) = \text{TTK}_{\text{小怪}}^{\text{target}} \times E[\text{DPS}](w)$——敌 HP 表**由**玩家期望 DPS 曲线**生成**，而非独立拍定（保证 TTK 恒等式成立的结构性方法）。

### 5.3 敌方成长曲线族

$$
\begin{aligned}
\text{HP}_e(w) &= \text{hp}_{\text{base}} \times c_{\text{hp}}^{w-1} \\
D_{\text{contact}}(w) &= \text{dmg}_{\text{base}} \times c_{\text{dmg}}^{w-1} && (c_{\text{dmg}} < c_{\text{hp}})\\
v_e(w) &= v_{\text{base}} \times \big(1 + s_{\text{spd}}(w-1)\big) && \text{(线性，设饱和上限)}\\
\text{EXP}_e(w) &= \text{exp}_{\text{base}} \times c_{\text{exp}}^{w-1} && (c_{\text{exp}} < c_{\text{hp}} \text{，经验通胀慢于 HP 保证卡牌节奏不失控)}
\end{aligned}
\tag{F27}
$$

### 5.4 波次—时间—资源产出关系

$$
t(w) = \sum_{i \le w} \big(T_{\text{window}}(i) + T_{\text{buffer}}\big), \qquad
n_{\text{card}}(w) = \frac{\text{EXP}_{\text{wave}}(w)}{\text{exp\_need}(\text{lv}(w))}
\tag{F28}
$$

- `exp_need(lv)`：升级经验曲线，形态 $e_0 \cdot \text{lv}^{\alpha}$（α 占位，A3 取 1.4）；
- 时间映射用于把"波次域"的数值锚点换算为 brief 点名的"20 分钟中期 / 60 分钟后期"体验域；
- 资源三通道（EXP/卡、金币/商店、掉落/武器槽）各自与波次的关系式均以 F24 分段指数形态声明，参数 A3 落数。

### 5.5 构筑完成度 vs 压力：20min / 60min 设计区间

定义**构筑完成度**：

$$
C(w) = \frac{\text{已获取关键词条数（含叠层）}}{\text{理论满配关键词条数}}
\tag{F29}
$$

（"关键词条"= 该构筑流派的核心乘区/机制词条集合，由 A3 按流派标注。）

**设计区间（brief 点名要求的验收带）**：

| 时点 | 波次域（A3 当前映射） | C(w) 构筑完成度 | P(w) 压力系数 | 体验目标 |
|---|---|---|---|---|
| 20 min（中期） | ~w30（30 波终局 Boss 后无尽初期） | [0.50, 0.75] | [0.65, 0.85] | 核心协同链成型 1~2 条，质变初体验，仍有明确成长空间 |
| 60 min（后期） | ~w60+（无尽深水区） | [0.85, 1.00] | [0.85, 1.00] | 接近满配，压力逼近满格，自然死亡窗口开启 |

- C 与 P 的**耦合约束**：$P(w) \le P_{\max}(C(w))$（完成度不足时压力必须留带宽——防止"没抽到关键卡"与"压力满格"同时发生的双重挫败）；上限函数 $P_{\max}$ 单调增、A3 标定；
- 死亡模型：$P \to 1$ 时清屏失败 → 敌堆积 → 接触压力上升 → 死亡，闭环自洽（无尽模式的自然终点）。

### 7.1 DamageContext（一次结算请求的完整输入）

```text
class DamageContext:
    # ── 标识与幂等（L5）──
    source_uid: int            # 投射物/光束/武器/反应源 实例 UID
    target_uid: int
    frame: int                 # 幂等键 = (source_uid, target_uid, frame)
    rng_stream_id: int         # 暴击掷骰的独立 RNG 流（种子可注入，AC-12.5）

    # ── 面板段（§1.1~1.4）──
    base_atk: float            # F2 结果（表驱动，唯一真源）
    add_entries: Array[AddEntry]   # 每项 {pool_id, trait_id, layer, contrib}（衰减前 raw）
    flat_sum: float            # Σ_flat（钳制前）

    # ── 乘区段（§1.5~1.6）──
    mult_entries: Array[MultEntry] # 每项 {pool_id, source_uid, contrib_expr, priority}
    local_entries: Array[LocalEntry]  # 每项 {local_id, contrib}（武器私有）

    # ── 暴击（§1.7）──
    crit_rate: float           # p_0 + T_crit(n)，结算前聚合完成
    crit_bonus: float          # d_0 + T_critdmg(n)

    # ── 类型与目标（§1.8）──
    damage_type: Enum {KIN, FIR, ICE, LTG}
    target_resist: float       # 快照读取（含超导削抗后的当前值）
    tags: BitSet {IS_DOT, IS_REACTION, IS_AOE_SECONDARY, IS_SPLIT_CHILD, ...}

    # ── 条件求值上下文（§1.5，乘区 contrib 求值用）──
    ctx: {
        bounce_count: int, pierce_index: int, wave_first_hit: bool,
        target_states: Set{FIR, ICE_CHILL, ICE_FREEZE, LTG, ...},
        player_hp_pct: float, generation: int,   # 分裂代数（继承判定用）
        ...
    }
```

class ModifierStack:

### 7.3 结算管线步骤序（M-12 实现契约）

```text
function resolve(ctx: DamageContext) -> DamageResult:
    1. 幂等检查        # (source,target,frame) 去重；目标 dead 短路 → 丢弃计数
    2. 池聚合          # add：同 ID 叠层过 F3 衰减 → 跨 ID 线性求和 → F4 池钳
                       # mult：按 pool_id 分组求和 → 单区 cap_pool_p 钳制
                       #        防御层：同 (pool_id, source_uid) 多条 → 取最大 + 审计
    3. 数量截断        # 乘区按 (M_p - 1) 降序取 top-N_mul，截断记审计
    4. 乘积封顶        # F9 整体钳制 → cap_prod，触顶记审计
    5. 面板段          # A = BaseATK × (1 + Σ_add) + clamp(Σ_flat, f_flat × BaseATK)
    6. 暴击掷骰        # 独立 RNG 流 roll → C ∈ {1, 1 + d_crit}（F7）
    7. 目标侧修正      # × (1 − r_type)（§1.8）
    8. 告警与保险      # F10 比率检查 → 超限告警（一局一次）+ 计数 + 保险钳制
    9. 广播            # DamageResolved {final, breakdown, audit}（跳字/遥测/GameFeel 共源）
```

> 步骤顺序即护栏顺序（L5→L2→L3→L4→…），任何实现不得重排（确定性要求：同输入必同输出，配合固定种子支撑 §6 回归）。

### 7.4 词条注册表范式（L1 守门的数据契约）

```text
class TraitData extends Resource:

    pool_class: Enum {ADD, MULT, LOCAL, REACTION, MECHANIC, ELEMENTAL}
    pool_id: StringName          # 封闭枚举（ADD/MULT/LOCAL 类必填；MECHANIC/ELEMENTAL 可空）
    contribution: float | Expr   # 表达式可引用 ctx 变量（如 "0.2 * (ctx.pierce_index - 1)"）
    max_stack: int               # 叠层上限（卡牌流过滤依据，AC-12.4 词条 ≤12 亦在此过滤）

# 启动校验：pool_id ∉ 注册表枚举 / ADD 类缺 decay_delta / δ>0.92 → 剔除条目 + 错误清单（E-08）
```
