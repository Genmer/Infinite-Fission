# R269 保帧模式 + 物理残差定谳键 + 渲染降载批 — 可行性分析

- 分析轮：R269（2026-10-14，对照设计 `docs/design/2026-10-14-R269-design.md`）。
- 方法：全部〔实证〕标记为本轮 Read/grep 亲证（含行号）；开放问题 1 以临时探针脚本（headless + 真实窗口双跑，跑完即删）在本机实测。项目 Godot 4.3.stable.official.77dcf97d8。
- 上游输入：vc78 真机日志（`archive/repo_logs/r269_vc78_user_diag.txt`，头部口径声明已先读）+ 主会话定谳 + 裁剪意见六条。vc78 数据行与设计引用对拍一致（fps 20-34 / 渲ms 15.0-17.2 / 物步µs 59k-143k / dc 438-958 / 尖峰 46-161ms / 敌 0 间歇行渲ms 8.6-12.6 fps76-120 / 晚段 dc 940-958 伴随敌 25-50、快N 21-27、弹N 129-148——§3.5 校准段属实）。

## 结论

**修改后放行。**

理由：①全批最大技术假设（content_scale_size 运行期热切）已在真实 GPU 窗口实测成立（720×1280→612×1088→复原，两帧内生效、渲染非黑、无异常）——A 轨最大杠杆不再是纸面推断，残余风险收敛为 Android GLES3 真机冒烟一项；②设计引用的代码锚点经逐条核实绝大多数精确命中，机制与既有体系（R220 冻结面/R225 装饰门/R230 帽/R267-268 预热）对账成立；③但发现 **2 处机制性错误**（ElementalFxLayer 根本不经 fx_quality_cap，「fx 钉 0 元素层预算自动落 0」不成立；MAX_ONSCREEN 常量符号被 r212_poolwarm 引用，「const→函数」直接替换会断编译）、**2 处主会话裁定未落地**（音效门独立；team-1 计数键不在 B 轨键清单）、**1 处首启垫值缺口**——五项均为小改，不伤架构，改完即可进实施。④工期：必做 3-4.5 人日（双人并行约 2-2.5 日历日），落在任务书 2-4 人日带上沿，前提是 C2 烘焙维持可选不做（与裁剪意见一致）。

## 可玩性评估

- **上手门槛：好。**「保帧模式」一行三态循环（关→开85→开75→关），一次设置终身受益；mobile 默认开=目标用户（vc78 机主）零操作拿到收益；可关=策略不越权。存疑小点：一行三态与双键（perf_boost/boost_res）的写口关系设计未写死（见修改意见 7），实现若含糊会造成「设置页显示态与诊断行 促%d 不一致」的新报障源。
- **反馈密度：好。**开模式后 fps/渲ms 是用户可直接感知的即时反馈——正对「30 次改了没感觉」的挫败点；跳字 12 帽保 CRIT/REACTION/超导/W8 必显通道（popup_manager.gd:37-39 契约），暴击与元素反应反馈不降级；音效门独立（必改 2）后战斗听感保留。促%d 状态键直接防「模式没生效」类报障（R230 帽N 零激活盲区教训已吸收）。
- **挑战节奏：中，渐进可接受。**敌 120→90 攻压密度 -25%、清波时间 +10-20%（对玩家偏易、无尽挂机循环变慢）——设计已披露且单一开关可回滚；敌弹 320 帽对常态 team-1（vc78 弹N 总量峰值 250-357 含玩家弹）无感。真机观感留给 vc80，判定为「存疑但不阻塞」。
- **双循环判定：**玩家循环=针对当前挫败的正解（有趣）；诊断循环=B 轨把「59k-143kµs 残差」从 30 次改不动的模糊答案变成可指名的桶——**本批最高价值面**（有趣），且与 A 轨互不阻塞。

### 机制核实——发现的问题（详见「给策划的修改意见」）

1. **ElementalFxLayer 不经调速器帽**：elemental_fx_layer.gd:83-90 `_fx_quality()` 直读 `Meta.settings("fx_quality")` + mobile 降档，**不调 PerfGovernor.fx_quality_cap()**。fx 钉 0 后：enemy.gd 侧（_fx_q→cap）落 0 成立；但元素层 DOT 火花(:311)/电光花(:214) 预算读的仍是设置档（mobile=1）——§3.3「ElementalFxLayer 既有 tier 预算表自动落到 0 档」**不成立**，需在 :83-90 加 boost 分支（必改 1）。
2. **A-2/A-4 部分吸收**：DeathPop 唯一发射点 :1170 被 :1167 `_fx_q()>0` 前置门整挡（含 Boss）——boost 内 fx=0 时死亡弹爆已全隐，A-4 的帽 4 只对 PoisonSplash（:1215，无 _fx_q 门）有增量；Boss 死亡爆闪随 fx 钉 0 全隐未在 §6 披露。
3. **fx 钉 0 的覆盖面边界**（披露补，非改刀）：玩家侧特效读口（orbit_field.gd:1106 / arc_slash.gd:577 / projectile_base.gd:1365）各自直读 fx_quality 设置——boost 不钉它们；其中玩家弹拖尾正是 §3.5 认定的晚段 dc 疑凶，boost 对该轴无直接作用（留给 B 轨定谳+下批）。
4. **B 轨行格式迁移面确认**：qa_r228_diagfreeze 剥离正则锚 `$`、`挡\d+` 为末可选组（qa_r228_diagfreeze_cases.gd:143）——六新键插在挡与尖峰之间**必然**触发正则迁移（设计已声明该迁移点，成立）；r229/r230 尾锚按设计预检。
5. **诊断行结构**：挡 在 debug_stats.gd:457、尖峰段 :458-468——新键插入位真实存在；_diag_render_ms_sum 秒窗累计器先例 :167、_diag_reset_window_acc :231、diag_export :555——B 轨载体全部就位。
6. **B 轳与 R268 口径零冲突**：六键全为新增累计器；物步µs 公式=监视器−段和，计时 wrap 落在延迟冲刷执行路径（不在段和内）——减项表零触碰成立；代价=每事件 2×Time.get_ticks_usec 的固定开销（量级可忽略，套件可断言）。
7. **预热红线**：C2 为本批可选/不做；若启动，TextureFactory 程序化烘焙+boot 预热队列（:656/:688 双泵+R267 出发帧预热）路径真实存在，「禁战斗期惰性首焙」可执行。
8. **护 ua_r218 双锚**：⑤a 断言（qa_r218_probe_cases.gd:446-447）与 r218_simbound_cases.gd:220-221 均为 `contains` 子串断言——boost 追加行不迁移锚文本，两套件预期全绿（后者须补进复跑清单）。

## 给策划的修改意见（实施前必须先改）
