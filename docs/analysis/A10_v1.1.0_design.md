# A10 · v1.1.0 设计留痕：元素反应二期（增幅双轨 / 元素精通 / 反应 CD 分立）

> 状态：已交付（与实现同步收尾）。上游：冻结方案（主控下发，架构已定照此落地）。
> 版本事实源 = `PROGRESS.md`；本文档为 v1.1.0 数值与裁定留痕（docs/analysis A 系列新增，入库）。

## §0 范围与三剧变零语义声明

- **范围**：①增幅双轨（融化/蒸发：直击通道吃反向附着，×1.5/×2.0）；②元素精通
  （ELE_MASTERY，+25%/层，全局 ≤3 层，剧变与增幅同乘）；③反应 CD 分立（碎裂 2s /
  过载 3s / 超导 6s，`reaction_table` 各 rule 携带 `cd` 键，缺键回退 `cd_rxn`）。
  顺手项：超导拼写修正（supercoduct→superconduct）、碎裂昵称清理（≠融化）、
  damage_pipeline.gd 注释现状化（唯一授权管线 diff，注释行）。
- **三剧变零语义声明**：碎裂 / 过载 / 超导的触发条件、结算通道、优先级（碎裂>过载>
  超导）、一帧一反应（每敌）、清槽行为、resolve_reaction 独立结算与快照口径
  **全部不变**。本版只改三件事：各自的 CD 值来源（全局 → rule 分立）、反应结算值
  乘区的聚合式（源上多了精通因子）、以及新增一条与剧变并行的直击增幅通道（不占
  剧变判定——增幅走弹侧直击 ctx，剧变走帧末检测，互不短路）。

## §1 术语表

| 术语 | 含义 |
|---|---|
| 剧变（三剧变） | 碎裂 / 过载 / 超导——帧末 `detect_reactions` 统一检测，双槽附着触发 |
| 碎裂 | FIR 槽 + ICE 槽双附着触发的剧变，结算基数 = 点燃剩余 DOT 总额 ×2.0 |
| 融化 | **碎裂的旧俗称，已废弃**。命名史注：A3/B_spec 时期「碎裂（融化）」混用，
  v1.1.0 统一为「碎裂」——与原神式「融化=增幅反应」划清界限，避免与本期增幅双轨
  中的蒸发/增幅概念撞名（源码注释与遥测键已同步清理） |
| 增幅（amplify） | 直击通道乘区：FIR 直击吃目标 ICE 附着 → 融化增幅 ×1.5；ICE 直击吃 FIR 附着 →
  蒸发增幅 ×2.0。以 `pool_id=&"amplify"` 注入乘区名额（contrib = factor−1） |
| 元素精通（mastery） | ELE_MASTERY 词条：每层 φ 额外 ×(1+0.25)，全局 ≤3 层（跨武器合计封顶） |
| φ（反应强化聚合） | `ElementalSystem.reaction_mult()` = ∏VOID mult × (1 + step×精通层数)；
  剧变系数与增幅因子同源消费 |

## §2 增幅双轨契约

- **判定（只读）**：`ElementalSystem.try_amplify_factor(target, hit_element)`
  - FIR 直击且 `gauges[ICE] > 0` → ×1.5×φ（融化增幅）；ICE 直击且 `gauges[FIR] > 0`
    → ×2.0×φ（蒸发增幅）；其余（KIN/LTG 直击、无反向附着、null/无状态宿主）→ 1.0。
  - **immune_mask 不查**（增幅吃附着计量，与满槽状态免疫无关）。
- **注入**：`ProjectileBase._build_damage_ctx` 内，`element ∈ {FIR, ICE}` 且
  `elemental != null` → factor > 1.0 时 `ctx.mult_pools` 追加
  `{"pool_id": &"amplify", "source_uid": uid, "contrib": factor−1,
  "cap_pool": factor−1, "priority": 0}`（字段逐字对齐 vuln 池先例）。
- **消耗（幂等）**：`consume_amplify(target, hit_element)`——重判同条件（已清则
  no-op）→ `clear_element(反向)` 全清 + `DebugStats` 分键计数。插点三处，均在
  「结算成功（result != null）且目标未 dead」之后、附着（_apply_elemental）之前：
  ①`projectile_base._on_settled`（主路径/穿透链逐目标）；②`homing_projectile._on_settled`
  主目标；③`homing_projectile._blast_secondaries` 次级循环（目标换 cand）。
- **天然排除面**：KIN/光束（laser_beam 自建 ctx，无注入位）/近战/settle_aoe/DOT 跳伤/
  感电连锁跳（后三者自建 ctx 且 `HIT_IS_DOT` 通道）——均不注入 amplify。
- **穿透链**：各目标独立判定、独立消耗（E-03 帧聚合按 target_uid 分行，互不影响）。

## §3 时序图（单次直击命中）

```
弹 tick → _submit_hit(target)
  → _build_damage_ctx：
      ctx.element = element
      [v1.1.0] elemental.try_amplify_factor(target, element)   # 只读快照
        └ factor>1.0 → ctx.mult_pools += amplify 池（contrib=factor−1）
  → 词条乘区预聚合 / vuln 池 / ON_HIT 派发
  → pipeline.resolve(ctx)          # 九步：amplify 入乘区名额（top-8 / 联合钳 8.0 照常）
  → _on_settled：
      _apply_result_to（落血双轨口径不变）
      killed 标记回填
      [v1.1.0] result!=null 且 !killed → elemental.consume_amplify(target, element)
        └ 重判同条件 → clear_element(反向) 全清 + 遥测分键
      _apply_elemental（本弹附着照常——碎裂后 FIR 直击留下 FIR 附着 = 融→蒸连段基础）
      穿透/回收判定
帧末（敌人阶段后）→ detect_reactions()   # 剧变判定与增幅互不感知；reaction_triggered 不因增幅虚增
```

## §4 反应 CD 表（分立）

| rule 键 | 反应 | coef/效果 | cd（新） | 旧口径 |
|---|---|---|---|---|
| RXN_FIR_ICE | 碎裂 | coef 2.0 | **2.0** | cd_rxn=2.0（同值） |
| RXN_FIR_LTG | 过载 | coef 1.2 / radius 90 | **3.0** | cd_rxn=2.0（改动） |
| RXN_ICE_LTG | 超导 | resist −0.3 / 6s | **6.0** | cd_rxn=2.0（改动） |

- 双源镜像：`balance_tables.gd`（schema 默认）与 `data/balance/balance_tables.tres`
  显式同值（改一处必改两处铁律）。
- 读取：`detect_reactions()` 触发前 `tables.get(reaction_key(rxn), {})` →
  `maxf(float(rule.get("cd", cd_fallback)), 0.01)`；`cd_fallback = GameConfig.balance.cd_rxn`
  （null/未就绪回退 2.0）。`reaction_key()`：ReactionType → rule 键唯一映射口。
- 校验：`DataValidator.validate_balance` 增非致命告警——rule `cd` 键存在但 ≤0 →
  「reaction_table cd 键若存在必须 > 0（v1.1.0 CD 分立）」。`cd_rxn` 字段保留（回退真源）。

## §5 元素精通公式

- **定义**：ELE_MASTERY（pool=ELEM，effect=EF_ELEMENTAL，params `{"mastery_step": 0.25}`，
  stack_max=3，event_hooks=[]（常驻——不派发、不覆写弹元素、不发附着请求），
  rarity=2，其余字段镜像 ELE_REACTION_VOID 结构）。
- **注册**：`WeaponBase.attach_trait` 扩展——`params.has("mastery_step")` →
  `elemental.register_mastery(uid, _trait_layers(trait.id), step)`。每次 attach 重报
  全量层数（幂等覆盖）；无注销通道（见 §7 E-AMP-1）。
- **聚合**（唯一裁定点）：
  `φ = reaction_mult() = ∏_reaction_mults × (1 + mastery_step × mini(Σ跨武器层数, 3))`
  - 层数合计跨武器求和，全局封顶 3 为唯一裁定点（`mastery_layers()`）。
  - 剧变：`resolve_reaction` 的 coefficient = χ_rxn × φ（既有通道，自动同乘）。
  - 增幅：`try_amplify_factor` 内 factor = 基数 × φ（同源消费，自动同乘）。
  - 仅 VOID 注册（精通 0 层）→ φ 恒等 1.8（pkg3 ×1.8 面零冲击，回归共证）。

## §7 假设清单（E-AMP-1 ~ E-AMP-4）

- **E-AMP-1 武器不可卸载，故 mastery 不注销**：当前无武器卸下通道，`register_mastery`
  只增改不删；若未来开放卸武器，需补 `unregister_mastery(uid)` 并在移除位调用
  （层数字典按 source_uid 隔离，天然支持）。
- **E-AMP-2 增幅系数为模块常量**：`AMP_MELT_FACTOR=1.5 / AMP_VAPOR_FACTOR=2.0 /
  MASTERY_LAYER_CAP=3` 落 `ElementalSystem` 常量而非 BalanceTables——待数值试玩回收后
  升格为 BalanceTables 字段（届时 .tres 镜像 + validator 同步）。
- **E-AMP-3 截断不标注**：amplify 池被 top-8 名额截断或联合钳 8.0 压缩时，跳字不加
  任何「截断」标记（与既有乘区截断口径一致，audit.truncated_mults/compressed 可查）。
- **E-AMP-4 融→蒸同帧连段合法**：碎裂增幅消耗 ICE 后同帧直击附着 FIR，第二个 ICE
  直击可立即触发蒸发增幅（同帧二次消耗合法，不设每敌每帧增幅次数上限——消耗即
  天然节流：反向附着被清空后同向不再触发）。

## §9 审查后修复与裁定补录（2026-09-01）

1. **Critical 修复（重开链注册表残留）**：ElementalSystem 为 boot 期跨局常驻单例，
   `_reaction_mults`（×1.8，v1.1.0 前既有缺口）与 `_mastery_reg/_mastery_step`（本版新增）
   均无清理通道——重开后旧武器 uid 死键残留，reaction_mult 虚增（XE1 坐实：新局 1.5、HUD
   却 MP:0）。修复 = ElementalSystem.reset_run() 清三表，game_loop._reset_run_state 与
   relic/chip/curse/blessing reset 同位调用；清零责任在重开链而非武器析构。
2. **E-AMP-5（top-8 截断时的附着消耗裁定）**：amplify 池被 top-8 挤出（该次直击未获增幅）
   时反向附着**仍被消耗**——与碎裂"触发即消耗"语义一致、极端构筑才可达，维持现状不改。
