# R230「高峰 dc 根治轮」设计 — 可行性分析

分析人：游戏分析师（第二阶段）｜对照代码库：repo @ R230 设计稿当日状态｜2026-10-04

## 结论

**修改后放行**。方法论主轴（PC 窗口化 gl_compatibility 夹具分族读差 → 按谱定刀 → vc35 真机终验）对照代码库全部成立：R224/R228 夹具先例、七件套哨兵注入口、五把候选刀的改动点与行号、电池 python 驱动、族根锚位逐项核实无误，且「同贴图+同 modulate 才合批」的项目定律有跨四轮真机实证支撑，4.3-stable 确有兼容渲染器 2D 合批。放行前**必须先改两处**（阻塞级，见「给策划的修改意见」）：

1. **§1.2 哨兵清单缺两项**（fx_quality=1 对齐、色差 ColorRect 中和）——不补则 F6/F7 族谱在 PC 上读数偏离真机带 ~2 倍，直接污染刀序裁定；
2. **K2 穿插件子刀机制错误**——DeathPop/PoisonSplash/法术圈是 `_draw` 自绘件（`enemy.gd:3211/:2878`，`queue_redraw()` 驱动），不参与纹理合批，alpha 量化对它们 dc 收益为零；须改为 sprite 化/并发帽口径或明确降出刀面。

另有两处强建议（不阻塞）：K4 去掉「行合并」子项只留配色量化；FG3 闭环容差与逐帧掩码执行绑定。

## 可玩性评估

本轮为性能根治轮，无新玩法系统，三问按「玩家感知面」评：

- **上手门槛（无感）**：零新 UI/新机制。玩家唯一可感面=视觉量化阶梯（K1 跳字渐隐 4 档、K2 甲板桶、K5 电链形态）与深载期特效减薄（K3）——R217/R229 同类 4 档量化已过评审，先例在案。
- **反馈密度（存疑但已有保险）**：核心打击反馈链（顿帧/震屏/跳字/血条/死亡爆闪）在代码上与刀面解耦——K3 唯一动 `game_feel_director.gd` 的文件集里同时住着顿帧/震屏/色差逻辑（`:111-124/:205-241`），实施纪律必须「只碰粒子路径」，且该文件按行号区隔可精确圈定；R229 锚法（`burst_thin` 门后施加点之前零触碰）已是既证先例。K3 可感点（老爆闪早熄）有三重门 + override=-2 否决 + 设置口（VG4）三路可否决，用户代理权完备。
- **挑战节奏（无感）**：R226 口径续锁，零成长数值改动；K3 帽=保险丝非成长帽（`particle_pool.gd` 抢占回收口径既有），敌/弹行为不动。

### B. 引擎侧核证（开放问题①：PC↔Android 合批同构——本轮最大假设）

**核证方法与局限（如实披露）**：分析当日 GitHub 源码直读不通（网络故障），未能逐行核对 4.3 `rasterizer_canvas_gles3.cpp` 的入批键源码；改以「版本事实 + 项目真机实证链」双源论证：

1. **4.3-stable 确有兼容渲染器 2D 合批**（4.3 Dev 3/4 dev snapshot 并入，官方文档口径「2D batching…same texture 合一批」；4.4 的 PR #91641「Fast 2D batching」是后续加强，不影响本分支）。项目锁 4.3-stable（`tools/Godot_v4.3-stable_win64_console.exe`），刀面机制建立在项目实测而非 4.4 行为上。
2. **「同贴图+同 modulate 才合批」有跨四轮真机实证**，非脑补：R214 桶遥测定案（同贴图相邻→合并，`tex_bucket_host.gd` 头注 vc21-vc23 证据）；vc33 位图跳字 dc 未降（同图集但根 alpha 逐张唯一→不合并，tracker 二ca 收口「跳字根逐张唯一 modulate.a 自成一批」）；R216 烤色（把碎片连续 modulate 烤进贴图恢复合批）；R217 桶内断批根修。四条证据在**同一引擎二进制、同一真机 GLES3 路径**上闭环。
3. **dc 计数是引擎侧的**：`RenderingServer.get_rendering_info(TOTAL_DRAW_CALLS_IN_FRAME)`（项目消费点 `autoload/debug_stats.gd:129`，vc34 真机 dc 700-990 即出自此 API 在 Android gl_compatibility 下的读数）——计数发生在引擎发绘制调用时，与 GPU 速度无关；兼容渲染器 canvas 合批模块（renderer_gl）在桌面 GL 3.3 与 Android GLES3 是**同一份代码**，平台差异在上下文/纹理格式层不在合批判定层。
4. **残余差异面（真实存在，量级小）**：字体回退链（PC 雅黑 vs Android Noto）→ 字形图集页数可能不同 → 纯文本族绝对 dc 微差；S3TC vs ETC2 压缩格式（`project.godot:58`）→ 合批键是贴图身份非格式，无影响。

**裁定**：「族占比与相对降幅在 PC 成立、绝对值不互比」的决策量设计**稳**。设计已把绝对 dc 排除出白名单（§1.5）并有 VG2→R231 升级路径。**补充一个零成本同构对照组**：vc35 真机锚段（tier3/特效优先，阀门全关）dc 与 vc34 同带逐位对拍（VG3 本就要求）——若锚段逐位不变而刀段不降，则「刀未兑现」与「假设证伪」可分离：前者指向实施，后者才触发转线。转线预案建议（若真出现「夹具兑现真机不降」）：vc35 诊断行无 dc 分族键（断N/组N/桶N/跳N/拾N 五键，`debug_stats.gd:178-187`），真机端无法直接分族——转线首选拿 K1（文件集最小、机制最确证）做 vc35a/vc35b 单刀出包 A/B 对拍定同构性，再决定 R231 是否转「内容差调查」（DebugStats 加 dc 分族键=改产品码 autoload，代价高，留作最后手段）。

### C. FG0（开放问题④：`-s` + 真窗口 + gl_compatibility）

**判定：可行，风险低**。依据：①项目全部 `-s` 探针（R224/R225/R227/R228 系）都以 SceneTree 脚本跑通，`-s` 与渲染方法旗标（`--rendering-method`）是引擎正交的标准旗标，去掉 `--headless` 不改变脚本 MainLoop 语义；②R224 头注「`-s` 入口编译期先于 autoload 注册——入口零工程类名直引（全鸭子），用例体运行时加载」——autoload 确会注册（qa_r228_ospec_cases 直接引用 `Enemy`/`PerfGovernor` 等全局类），窗口模式下同样成立；③主控烟测已证本机 RTX4070 GL 3.3 下项目可起，`-s` 不改渲染路径。**残余风险**：窗口化后 `process_frame` 受 vsync 节拍（夹具的墙钟泵协议 `_pump_process_budget` 天然适配，见 R228 cases :233-241）与异常退出残留窗口进程——设计已列「任何路径最终 quit()+导出前查杀」红线，保留。**回退方案评估**：设计的回退（参数注入驱动 main 场景内探针节点）可行且优于自定义 MainLoop 方案（后者绕开 SceneTree/autoload 语义，与全部既有探针体例不兼容，不建议）。

### D. 分族关断读差法（开放问题③核查前半）

- **族根锚位全部核实**：F1 敌桶（`game_loop.gd:1900` `_attach_bucket_host(enemy_pool)`，行号精确）；F2 敌子件建名区（`enemy.gd:401-406` FuseRing ✓、`:2051-2103` ArmorPlate/Crown/GroundShadow/Sparkles ✓）；F3 穿插件四点（`:909` DeathPop.pop ✓ / `:952` PoisonSplash.pop ✓ / `:1036` SpellRing ✓ / `:1135` BlinkRing ✓）；F4/F5 弹/碎片桶（:1899/:1901）；F6 粒子池；F7 `ElementalFxLayer`（`game_loop.gd:2154-2155`，z=5 ✓）；F8 `PopupPool`（:1862-1865）；F9 HUD（`hud.gd:11-12` extends CanvasLayer ✓）+BossBar；F10 `CloudBackdrop`（:2123-2124）；F12 `LaserPool`（:1870-1873）。
- **结构性难点（设计未写明，须实现须知）**：①**族嵌套**——F2 敌子件是敌容器（已被 F1 桶收编）的子级，F1/F3 共存于同一桶子树，「层级根开关」关不掉单族，必须**逐 item 分类**（R228 `_census`/`_classify_root` 已是现成的逐件分类器，`qa_r228_ospec_cases.gd:246-329`）+ 逐件 visible 开关；②**新生件泄漏**——P1 累积关断期间 DeathPop/法术圈持续新spawn（深载杀率高，DeathPop 并发实测 ~80，`enemy.gd:3215` 池帽 96），一次关断后新件可见会污染后续族读数，须**每物理步重放族掩码**再采样；「弃 3 帧」只解决读旧帧，不解决新件。好消息：FG3 望远镜恒等式（Σ边际+残差=基线 ±5）恰好是这类泄漏的自动探测器——建议容差与掩码执行强度联动（若 spawn churn 高考虑放宽到 ±8 并披露）。
- **零烤图红线**：`runstart_bake_override=1` 的烤图发生在 run 开始（R227 补烤哨兵语义，真机 mobile 自动门同点），非战斗期——**不触红线**；夹具波与刀波均无新增战斗期烤图路径。✅

### F. 哨兵保真缺口（本轮分析最重要发现，阻塞级）

设计 §1.2 哨兵清单（R228 七件套 + burst_thin=-3 + pool_valve=-3）**缺两项**，不补则 PC 夹具偏离真机深载带：

1. **fx_quality 档位**：真机 mobile 门内 `fx_quality` 有效值恒 ≤1——三处独立 mini(q,1)：`elemental_fx_layer.gd:80-83`、`game_feel_director.gd:131-135`、`enemy.gd:315-330`。PC 非 mobile 时：enemy 侧有 tier 帽经 tier_override=2 直驱到 1（对齐），但**特效层与命中粒子两处不吃 tier 帽**、读 2 → F7 特效层件数 ~2 倍膨胀（DOT 火星 [0,2,4] 读 4、电花 [0,1,3] 读 3）、F6 命中粒子流偏离。**修法（零产品码）**：boot 后 `Meta.set_setting("fx_quality", 1)`（`meta_manager.gd:259` 公开口；enemy 侧缓存订阅 settings_changed 自动跟随）。
2. **色差 ColorRect**：`game_feel_director.gd:300-303` 桌面启用 / mobile 整体禁用（R203）——PC 夹具深载暴击流会周期性拉起全屏 hint_screen_texture 拷贝（+1 dc 且整帧批冲刷），真机无此件。**修法（零产品码）**：每步 `_gl._physics_process()` 返回后、泵帧前鸭式强制 `_gl.game_feel.chromatic_rect.visible = false`（tick 在物理步内置位，渲染在其后，时序成立）。

## 阻塞项①（哨兵）复审详情
