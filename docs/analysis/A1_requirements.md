## 1. 需求复述（确认无理解偏差）

用我自己的话完整复述一遍用户需求，作为双方对齐基线：

1. **要做一款什么**：名为 **Infinite Fission** 的**竖屏、高刷新率（目标 120Hz）** Roguelike 弹幕防御射击游戏。玩家在屏幕下方区域活动，敌人从上方涌来，玩家自动/手动开火抵御无尽波次。第一性目标是**核心系统**：高扩展性架构 + 高性能弹幕 + 极强视觉打击感，而非完整游戏内容。

2. **核心卖点**：一套**多乘区 + 高度模块化的词缀协同（Synergy）系统**。玩家通过 Roguelike 卡牌选择把词条堆到武器和投射物上，词条在投射物生命周期事件上链式触发，产生"质变构筑"（体积极大→冲击波、几何分裂→弹幕海、反弹折射、元素混爆）。**防数值崩坏是最高设计约束**：吃一两个基础 Buff 绝不允许直接破坏平衡——这要求伤害公式严格区分"加算池"与"独立乘区"。

3. **武器层**：统一 `WeaponBase` / `ProjectileBase` 抽象，四形态——普通弹道（手枪/加特林/霰弹：初速、射程、散射角、穿透数）、持续光束（RayCast2D、叠层、高频跳字、折射分叉）、智能追踪（角速度寻敌、加速度、范围爆炸、二段延时启动）、近战环绕/挥斩（浮游力场或弧形挥斩、击退/消弹/格挡）。形态之上由词缀做正交叠加。

4. **词缀层**：每个投射物维护 Trait 列表，在 `OnSpawn / OnTick / OnHit / OnPierce / OnBounce / OnExpire` 六个生命周期事件上触发。四大核心词缀家族：体积极限（等比放大碰撞盒与精灵，极大时质变为冲击波/压制范围）、几何分裂（击中/穿透耗尽/消亡时按夹角或环形分裂次级弹，继承比例攻击力与部分词缀）、边界与目标反弹（撞屏边或敌人后寻新目标折射，反弹后加增伤乘区）、元素附着与反应（点燃 DOT / 冰冻减速易伤 / 感电连锁，混合触发独立引爆）。

5. **数值层**：伤害公式 = `(基础攻击 × (1 + Σ加算词条) + 平坦加成) × Π(1 + 独立乘区) × 暴击因子`。加算池是平庸词条且边际递减；独立乘区是条件触发的协同乘数。公式是防崩坏的机制核心。

6. **工程层**：全数据驱动（Custom Resource：WeaponData / RelicData / SynergyRule 等 .tres，支撑未来成百上千张升级卡无代码扩展）；高性能 2D 对象池（杜绝运行时 `instantiate()`/`queue_free()`，低端移动端也要跑满高帧率）；GameFeel 预留接口（微秒级击中顿帧、暴击/质变全屏震动与色差着色器触发接口、统一 GPUParticles2D 管理）。

7. **交付顺序**：先输出模块依赖关系设计、核心架构伪代码/类定义、Resource 数据结构与伤害结算管道——即"架构先行，数值与内容后融"。

8. **范围与授权**：项目全权交给 AI 团队，不急、慢工出细活，可并行派发子任务（需求分析 / 数值框架 / 具体数字并发，之后融合）。本期只做**核心系统 + 可运行游戏闭环**（验证手感与数值），美术正式化、关卡、存档、音频等留后续迭代。

**我对需求的理解确认**：这是一份"引擎级游戏核心框架 + 最小可玩闭环"的需求，验收重心在①架构可扩展性、②弹幕性能、③打击感、④数值防崩坏四条主线上，"内容量"（敌人种类数、卡牌张数）只需达到验证系统的最小规模，不在本期验收范围。

## 2. 系统模块清单（最小可交付模块）

> 依赖方向自底向上：`M-18/M-19（总线/配置）` → `M-12~M-14（结算/池/数据）` → `M-09~M-11（投射物/词缀/元素）` → `M-03~M-08（实体/武器）` → `M-01/M-16/M-17（循环/UI/卡牌流）`。**禁止反向依赖**（下层不得 import 上层；跨层通信一律走事件总线或显式注入）。

### M-01 核心战斗循环 / 主场景（GameLoop）
- **职责边界**：竖屏逻辑分辨率与 viewport 缩放设置；战斗主场景的节点组织与帧处理顺序固定化（输入 → 玩家 → 武器开火 → 投射物运动/碰撞 → 敌人 AI/状态 → 波次生成 → 特效 → UI 刷新）；游戏状态机（Boot → Menu → Playing → Paused → LevelUp → GameOver）；全局时间缩放的唯一持有者（顿帧、升级暂停都通过它，禁止各系统私自改 time_scale）。
- **不做**：任何具体玩法逻辑、伤害计算、渲染特效细节。
- **依赖**：M-18（状态切换广播）、M-19（分辨率/帧序配置）。
- **被依赖**：全部战斗模块的宿主场景；M-15（时间缩放协调）、M-17（暂停宿主）。

### M-02 玩家实体（Player）
- **职责边界**：拖动/相对移动（含屏幕边界钳制）；HP、受击、无敌帧；武器槽持有与自动开火调度；经验值与等级；玩家侧命中盒。
- **不做**：具体武器行为、卡牌逻辑；玩家受击走简化结算（敌人接触伤害直接扣 HP），不经 M-12 乘区管线。
- **依赖**：M-05~M-08（武器形态）、M-18（受击/升级事件）、M-16（HUD 数据源）。
- **被依赖**：M-04（敌人索敌目标）、M-17（升级主体）、M-16（HUD 绑定）。

### M-03 敌人实体（Enemy）
- **职责边界**：敌人运行时实体（由 M-14 的 EnemyData 实例化）；基础行为（追击/远程投射/环绕等行为枚举，M1 只需追击+远程两种）；HP/速度/接触伤害/经验掉落；**状态效果容器**（点燃/冰冻/易伤/感电的叠层与计时挂载点）；死亡广播与死亡表现入口。
- **不做**：生成节奏（归 M-04）、伤害计算（归 M-12）。
- **依赖**：M-14（数据）、M-18（死亡/受击事件）、M-11（状态效果读写）、M-13（尸体对象池复用）。
- **被依赖**：M-04（生成）、M-09/M-12（命中目标）、M-11（状态宿主）、M-16（Boss 血条）。

### M-04 敌波管理（WaveDirector）
- **职责边界**：无尽波次编排（波次预算、生成间隔、单帧生成节流、同屏上限排队）；精英波/Boss 波调度（逢 5 精英、逢 10 Boss，互斥）；难度曲线从数值表读取（公式可热替换）；"波次开始/清空"事件广播。
- **不做**：敌人个体行为；掉落物生成（经验碎片由敌人死亡事件驱动，属 M-03/M-02 链路）。
- **依赖**：M-03、M-19（曲线表）、M-18、M-13（生成节流）。
- **被依赖**：M-16（波次 HUD）、M-01（GameOver 触发链）。

### M-05 武器基类 + 形态 A：普通弹道（WeaponBase / Ballistic）
- **职责边界**：WeaponBase 抽象（射速、弹药/冷却、散射、穿透基数、目标策略、开火入口、词条挂载点）；Ballistic 实现：初速度、射程（超程过期）、散射角、穿透计数。手枪/加特林/霰弹 = 同一形态的不同 .tres 参数（霰弹=一次多投射物+大散射角）。
- **依赖**：M-09（投射物生成请求）、M-10（词条挂载）、M-14（WeaponData）。
- **被依赖**：M-02（武器槽）。

### M-06 形态 B：持续光束（Laser/Beam）
- **职责边界**：基于 RayCast2D 的持续射线；照射叠层（对同一目标叠层增伤，层数上限）；接触点高频跳字（节流）；折射分叉（命中后按角度分出子射线，分叉深度上限 2）；线段渲染。
- **不做**：投射物运动学（光束不是 M-09 投射物，是独立实体，但共享 M-10 词条与 M-12 结算）。
- **依赖**：M-05（WeaponBase）、M-12、M-10、M-16（跳字）、M-13（光束实例池化）。
- **被依赖**：M-02。

### M-07 形态 C：智能追踪（Homing Missile）
- **职责边界**：角速度转向插值寻敌；加速度推进（初慢后快）；二段延时启动（直飞/无追踪阶段后开启追踪）；命中碰撞范围爆炸（AOE 结算）。
- **依赖**：M-05、M-09（作为投射物实例）、M-03（索敌查询）、M-12（AOE 结算入口）。
- **被依赖**：M-02。

### M-08 形态 D：近战环绕/挥斩（Melee/Orbit）
- **职责边界**：环绕浮游力场（绕玩家旋转、周期性范围判定、击退、消弹/格挡判定：可销毁敌方弹幕）；固定角度周期性弧形挥斩（扇形判定、击退）。
- **不做**：远程投射（本形态不产生 M-09 投射物，但挥斩可被词条"分裂"改造成发射弧形波——该组合留 M2，接口预留）。
- **依赖**：M-05、M-12（周期结算）、M-10。
- **被依赖**：M-02。

### M-09 投射物系统（ProjectileBase + 生命周期）
- **职责边界**：投射物运动学（速度矢量/加速度/寿命计时/出界判定）；穿透与反弹计数器；**六大生命周期事件的唯一派发点**（OnSpawn/OnTick/OnHit/OnPierce/OnBounce/OnExpire，派发顺序=词条挂载顺序，确定性）；元素负载携带；分裂产物生成请求接口；死亡/回收路径统一（正常过期、穿透耗尽、反弹耗尽、被消弹、池强制回收——全部收束到同一回收函数）。
- **不做**：词条效果本身（M-10）、伤害数值（M-12）。
- **依赖**：M-13（实例获取/归还）、M-10（事件订阅者）、M-12（命中结算调用）。
- **被依赖**：M-05/M-07、M-10、M-11。

### M-10 Trait / 词缀引擎（Chained Modifiers）
- **职责边界**：Trait 抽象（事件订阅声明、层数/冷却/触发概率等运行时状态、可继承标记）；词条列表的挂载/复制/分裂继承规则（继承标记 + 代际衰减）；事件触发顺序保证（按挂载序）；词条互斥/叠层上限注册表；词条触发自身的事件再触发（链式反应）深度上限与重入保护。
- **不做**：具体某张卡的效果数值（数值在 .tres / A3 表）。
- **依赖**：M-09（事件源）、M-12（结算钩子）、M-13（分裂产物实例）、M-11（元素附着接口）、M-14（TraitData）。
- **被依赖**：M-05~M-09、M-17（卡牌应用入口）。

### M-11 元素系统（Elemental）
- **职责边界**：三种基础元素（点燃/冰冻/感电）的附着、叠层、衰减、独立计时；状态效果执行（DOT 跳伤、减速、易伤、连锁闪电传导）；**混合反应检测与独立引爆**（火+冰=碎裂、火+电=过载、冰+电=超导，反应内置冷却）；元素视觉入口（粒子/着色请求，只发事件不做表现）。
- **不做**：伤害公式本身（调 M-12）、元素相关词条的挂载逻辑（M-10）。
- **依赖**：M-12（DOT/连锁/引爆结算）、M-18（反应触发事件）、M-03（状态容器宿主）。
- **被依赖**：M-10（元素词缀）、M-15（反应触发特效）。

### M-12 伤害结算管线（Damage Pipeline）
- **职责边界**：统一伤害请求结构（来源、目标、基础攻击、加算词条列表、平坦加成、乘区列表（含乘区 ID）、暴击参数、伤害类型标记）；公式实现（加算池 → 平加 → 乘区去重与上限 → 暴击掷骰 → 终值）；**对同一目标同一帧同来源结算的幂等/去重**；结算结果广播（命中/暴击/击杀，含最终数值与乘区明细供跳字与遥测）；单跳伤害上限的防御性钳制。
- **不做**：任何触发时机判断（何时调用它由 M-09/M-10/M-11 决定）。
- **依赖**：M-18（结果广播）。
- **被依赖**：M-06~M-11、M-16（跳字数据源）、A3 数值验证（唯一公式真源）。

### M-13 对象池（Object Pooling）
- **职责边界**：通用池（投射物/敌人尸体实例/光束/跳字/粒子发射器/经验碎片）；启动预热到配置容量；获取/归还契约（归还前状态清零：速度、词条列表、订阅、计时器）；软/硬上限与降级（满池丢弃生成请求并计数，不阻塞不崩溃）；池污染检测（开发期断言：取出的实例必须处于"干净"状态）。
- **不做**：池中对象的行为。
- **依赖**：M-19（容量配置）。
- **被依赖**：M-03、M-06、M-09、M-15、M-16、M-17。

### M-14 Data-driven Resource 层
- **职责边界**：Resource 类定义（WeaponData / TraitData / CardData / RelicData / SynergyRule / EnemyData / ElementalRule / GameFeelProfile）；.tres 实例库与注册表（按 ID 索引）；字段校验（必填、范围、引用完整性，启动期输出错误清单）；加载失败降级（单条失败剔除该条目，游戏可继续）；数据版本字段。
- **不做**：数值平衡（A3 产出 .tres 内容）。
- **依赖**：M-19（加载器与目录扫描）。
- **被依赖**：M-03、M-05~M-08、M-10、M-11、M-15、M-17。

### M-15 GameFeel（顿帧/震屏/色差/粒子）
- **职责边界**：击中顿帧（向 M-01 申请时间缩放，时长按伤害事件分级）；震屏（trauma 模型：输入伤害事件级别，输出相机偏移/旋转，带衰减）；色差（全屏 shader 的 uniform 触发接口，强度与时长分级）；GPUParticles2D 统一生成管理（池化发射器、优先级裁剪、同屏上限）。
- **不做**：触发判定（监听 M-12/M-11 的结果事件）。
- **依赖**：M-13（粒子发射器池）、M-18（事件订阅）、M-01（时间缩放申请）、M-14（GameFeelProfile 数值）。
- **被依赖**：M-01（帧序中的特效阶段）。

### M-16 UI（HUD / 跳字 / 暂停 / Boss 血条）
- **职责边界**：HP/经验条/等级/波次/击杀数/计时 HUD；伤害跳字（池化、样式分级、同目标短窗合并、同屏上限）；Boss 血条；暂停菜单与游戏结束界面（含本局统计：击杀数/波次/造成的总伤害/乘区峰值）。
- **不做**：升级卡牌界面（M-17）。
- **依赖**：M-18（数据事件）、M-13（跳字池）、M-12（跳字数值源）。
- **被依赖**：M-01（状态呈现）、M-17（界面宿主复用其样式）。

### M-17 Roguelike 升级卡牌选择流
- **职责边界**：升级触发（经验满级）→ 申请暂停 → 3 选 1 卡牌生成（候选池规则：新武器形态/已有武器词条/全局遗物；稀有度权重；同武器词条叠层上限过滤）；选择应用（词条挂载到武器与投射物模板、遗物全局生效、属性永久成长）；卡池耗尽 fallback（转为属性小幅成长卡）；界面关闭并恢复。
- **不做**：卡牌数值设计（A3）、经验掉落（M-03/M-02 链路）。
- **依赖**：M-14（CardData/RelicData）、M-10（词条应用）、M-02（属性成长）、M-18、M-16（界面样式）、M-01（暂停申请）。
- **被依赖**：无下游（终端玩家交互）。

### M-18 事件总线（EventBus）
- **职责边界**：类型化全局事件（EnemyKilled / PlayerHit / DamageResolved / CritLanded / TraitProc / ReactionTriggered / WaveStarted / WaveCleared / LevelUp / CardChosen / PoolExhausted …）；订阅/退订 API 与弱引用清理（订阅者销毁时自动退订，防悬挂调用）。
- **不做**：任何业务逻辑。
- **依赖**：无（最底层）。
- **被依赖**：除 M-13/M-14/M-18/M-19 外的几乎所有模块。

### M-19 配置 / 数值表加载（GameConfig & BalanceTables）
- **职责边界**：GameConfig（逻辑分辨率、viewport 策略、各池容量、各类上限常量、性能预算）；BalanceTables（波次曲线、敌人成长、经验曲线、稀有度权重）；启动期全量加载 + 校验 + 注入注册表；加载顺序最优先（其它模块启动的前置）；校验失败的处理策略（致命配置→拒绝启动并报清单；非致命→默认值+告警）。
- **依赖**：无（最底层）。
- **被依赖**：M-01、M-03、M-04、M-13、M-14、M-15、M-17。

## 3. 每条需求的验收标准（可直接当测试用例）

> 通用测量口径：性能数据在 **Apple Silicon M1、Godot 4.3+、release 导出模板** 下采集（debug 模式数据仅作参考不进验收）；帧时间用固定种子 + 脚本化自动战斗场景（自动移动、自动瞄准、无人工输入）运行 60 秒，导出逐帧时间序列，判定指标为 **P95**。所有计数类断言通过开发期 DebugStats 面板（autoload）读取，验收后该面板在 release 中自动剥离。

### R-01 游戏定位与性能预算
- **AC-01.1**：游戏以竖屏运行，逻辑分辨率 1080×1920（见 Q-1 默认值），窗口任意拉伸下画面比例不变、无裁切（拉伸策略 `canvas_items` + `keep`）。
- **AC-01.2**：负载场景"500 活跃投射物 + 100 活跃敌人 + 60 粒子发射器 + 40 跳字"持续 60s，帧时间 P95 < 8.3ms（120Hz），P99 < 10ms。
- **AC-01.3**：极限压力场景"2000 投射物 + 150 敌人"持续 30s，帧时间 P95 < 16.6ms（60Hz 保底），且无崩溃、无内存持续增长（30s 内 RSS 增幅 < 3%）。
- **AC-01.4**：冷启动（双击图标到主菜单可交互）< 3s（M1）。
- **AC-01.5**：稳态内存 < 400MB（500 弹幕 + 100 敌人场景下）。

### R-02 WeaponBase / ProjectileBase 抽象
- **AC-02.1**：四形态武器均由同一 WeaponBase 派生，公共参数（射速、散射、穿透基数、词条挂载点）在基类定义；新增第五形态不需要修改任何既有形态代码（以"实现一个测试用 Dummy 形态"验证，仅新增文件）。
- **AC-02.2**：任一 WeaponData .tres 的参数重写（改射速/散射角/穿透数）后进入游戏，行为与参数一致（射速 ±5% 实测误差内，散射角/穿透数精确）。
- **AC-02.3**：词条可挂载到任一形态武器并在其投射物上生效（用"体积极限"词条分别挂到手枪与霰弹枪，两者投射物均等比放大）。

### R-03 形态 A：普通弹道（Ballistic）
- **AC-03.1**：手枪：单发、初速按表、直线、超射程后过期回收；穿透=0 时命中首个敌人即回收。
- **AC-03.2**：霰弹枪：单次开火生成 N 个投射物、总散射角内均匀分布、各弹独立结算。
- **AC-03.3**：穿透=2 的弹依次穿过 3 个敌人：前 2 次触发 OnPierce，第 3 次触发 OnExpire（穿透耗尽路径），3 次都触发 OnHit。

### R-04 形态 B：持续光束（Laser/Beam）
- **AC-04.1**：光束每帧 RayCast2D 检测首个命中敌，持续照射同一敌人叠层（1 层/0.25s，上限 8 层），叠层增益进独立乘区。
- **AC-04.2**：接触点跳字频率 ≤ 15Hz/目标（节流验证：60s 连续照射，跳字数 ≤ 900）。
- **AC-04.3**：折射分叉：命中带"折射"词条目标后分出 2 条子射线，子射线可再折射 1 次，分叉深度 > 2 的请求被拒绝并计数（不出第 3 代射线）。
- **AC-04.4**：光束实例走对象池，切换目标/关闭重开无 instantiate 调用。

### R-05 形态 C：智能追踪（Homing）
- **AC-05.1**：投射物发射后 0.3s 直飞（无追踪），随后以最大角速度（表值）向锁定目标转向插值，轨迹曲率不超过角速度上限（录制轨迹抽样验证）。
- **AC-05.2**：初速 60% 表值，1s 内线性加速到 100%，实测末段速度误差 < 5%。
- **AC-05.3**：命中时以碰撞半径 R（表值）做范围爆炸，半径内全部敌人各结算一次伤害。
- **AC-05.4**：锁定目标死亡后 0.2s 内重新索敌（无目标时直飞至过期）。

### R-06 形态 D：近战环绕/挥斩（Melee/Orbit）
- **AC-06.1**：浮游力场绕玩家公转（角速度表值），对半径内敌人周期性结算（0.2s/次），并施加击退（位移/帧实测）。
- **AC-06.2**：带"格挡"词条的力场与敌方弹幕重叠时销毁该弹幕（敌方弹幕销毁走 OnExpire 路径，触发其 OnExpire 词条）。
- **AC-06.3**：弧形挥斩在固定角度窗口内出现判定（持续 0.15s），窗口外无伤害（用假敌人放在窗口边界 ±1° 验证）。

### R-07 Trait 引擎与六大生命周期事件
- **AC-07.1**：六事件（OnSpawn/OnTick/OnHit/OnPierce/OnBounce/OnExpire）全部可被词条订阅并被正确触发（每事件至少一个测试词条验证触发次数与时机）。
- **AC-07.2**：同一投射物挂 3 个词条时，事件派发顺序 = 挂载顺序（用记录调用序的测试词条验证，每次运行顺序一致）。
- **AC-07.3**：词条链式再触发深度上限 4：第 5 层链式触发被拒绝并计数（防词条互触发死循环）。
- **AC-07.4**：词条运行时状态（层数/冷却）独立于词条数据（.tres），同一 TraitData 被多个投射物引用互不污染（两个投射物各自叠层验证）。

### R-08 体积极限词缀
- **AC-08.1**：碰撞盒与精灵等比放大（视觉与判定尺寸比值恒定，3 个放大档位实测误差 < 5%）。
- **AC-08.2**：体积极大（≥ 3.0×）时命中附加冲击波：以命中点为圆心 R（表值）范围伤害 + 震屏升级（trauma 由 0.15 → 0.4）。
- **AC-08.3**：放大后投射物与敌人的碰撞对数量增加，500 弹幕全部 3.0× 时仍满足 AC-01.2 帧预算。

### R-09 几何分裂词缀
- **AC-09.1**：击中/穿透耗尽/消亡三种触发路径（词条可配）各自正确分裂出次级弹；分裂夹角/环形模式按词条配置生效。
- **AC-09.2**：次级弹攻击力 = 父弹当前结算攻击力 × 继承比例（默认 50%），孙代再乘 50%（代际递减实测）。
- **AC-09.3**：分裂代数上限 3：第 3 代弹不再分裂（OnExpire 不再产出）。
- **AC-09.4**：单投射物单次分裂子数上限 8；全场投射物达硬上限 2000 时新分裂请求被拒绝并计数（PoolExhausted 事件），不崩溃。
- **AC-09.5**：次级弹只继承标记 `inheritable=true` 的词条；继承的词条层数/冷却重置。

### R-10 反弹/折射词缀
- **AC-10.1**：投射物撞击屏幕四边各反弹一次（反射角=入射角镜像，实测误差 < 2°）。
- **AC-10.2**：反弹计数耗尽后投射物按普通路径消亡；反弹后命中新目标时携带增伤乘区（×1.4，进独立乘区池）。
- **AC-10.3**：撞敌方单位后折射寻新目标：新目标为原目标 250px 半径内最近且 ≠ 原目标；无候选则直飞。

### R-11 元素附着与混合反应
- **AC-11.1**：点燃：附着后每 0.5s 一跳、每跳 30% 结算攻击力、持续 3s、最多叠 5 层（第 6 次附着被拒绝）；敌人死亡时剩余 DOT 清除且不再结算。
- **AC-11.2**：冰冻：减速 40% 实测（敌人位移速度采样）；叠满 3 层触发易伤（+15% 独立乘区，持续 3s）。
- **AC-11.3**：感电：命中后连锁至多 3 个 250px 内敌人，每跳伤害衰减 70%，同一结算周期同一目标仅被连锁命中一次。
- **AC-11.4**：混合反应独立引爆：火+冰=碎裂（立即引爆点燃剩余 DOT 总量 ×1.5，清除两元素）；火+电=过载（250px 范围 200% 攻击力爆炸）；冰+电=超导（范围冰冻扩散+易伤）。反应触发后两元素清除，同目标 2s 内不重复触发同反应。
- **AC-11.5**：反应触发暴击/质变级 GameFeel（顿帧 50ms + 震屏 trauma 0.4 + 色差）。

### R-12 伤害公式与防崩坏
- **AC-12.1**：公式真源测试——Base=100，加算词条 +20%、+30%，平坦 +10，乘区 1.5 与 1.4，非暴击 → 期望 (100×1.5+10)×1.5×1.4 = 336。若加算被误入乘区得 100×1.2×1.3×1.5×1.4+… ≠ 336，测试即失败。
- **AC-12.2**：乘区去重——同一乘区 ID（如 frozen_bonus）一次结算出现 2 次取最大：Base=100、两个 ×1.5 同 ID → 结果 150 而非 225。
- **AC-12.3**：加算边际递减——同一加算词条 n 层总加成 T(n) 满足 T(n) < n × 单层基础值（严格递减），且 T(5) ≤ 4.3 × 单层基础值（具体衰减公式由 A2 定，本条锁不等式验收口径）。
- **AC-12.4**：单结算乘区参与数上限 8（超出取数值最大的 8 个）；单投射物词条数上限 12（卡牌选择时被过滤）。
- **AC-12.5**：暴击独立掷骰（可注入固定随机种子复现确定序列）；暴击因子 = 暴击时 ×(1+暴伤加成)，默认 5% 基率 / ×1.5。
- **AC-12.6**：防崩坏压力用例——"霰弹枪 + 分裂 3 代 + 反弹增伤 ×1.4 + 对冰冻 ×1.5 + 每穿透 ×1.2" 极限构筑运行 10 分钟，单发最终伤害不超过基础伤害 ×500（超限日志告警一次并计数，游戏不崩溃、帧率仍满足 AC-01.2）。
- **AC-12.7**：结算幂等——同一投射物同一帧对同一敌人仅结算一次（穿透多目标时每目标一次）；敌人已死亡的本帧后续结算请求被丢弃并计数。

### R-13 数据驱动 Resource 层与扩展性
- **AC-13.1**：新增一张完整 .tres 武器卡（复制现有 WeaponData 改字段），不改任何代码，该武器出现在卡池、可选、可用。
- **AC-13.2**：字段校验——注入负射速、0 池容量、缺失必填字段的 .tres，启动期输出含文件名与字段名的错误清单，该条目被剔除，游戏正常进入主菜单。
- **AC-13.3**：引用完整性——.tres 引用不存在的 TraitData ID 时启动报错并剔除宿主条目。
- **AC-13.4**：加载 1000 张卡牌 .tres 的启动耗时 < 1s（在 AC-01.4 的 3s 总预算内）。
- **AC-13.5**：数据版本字段存在且不匹配时输出迁移告警（本期仅告警不迁移）。

### R-14 对象池
- **AC-14.1**：10 分钟自动战斗（含波次推进、卡牌选择、分裂/反弹/元素全链路）期间，运行时对战斗实体（投射物/敌人/跳字/粒子发射器/经验碎片）的 `instantiate()` 与 `queue_free()` 调用计数 = 0（DebugStats 计数器断言；UI 场景切换不在本条范围）。
- **AC-14.2**：进 Playing 状态前各池完成预热（预热耗时计入启动预算，不产生首波卡顿：首个 5 秒帧时间 P95 < 10ms）。
- **AC-14.3**：归还清洁度——从池取出的实例词条列表为空、速度/计时器归零、无残留订阅（开发期断言，违反即报错定位）。
- **AC-14.4**：池满降级——硬上限满时生成请求被拒绝、PoolExhausted 计数 +1、无报错弹窗、无帧尖刺（单帧处理 < 0.1ms）。

### R-15 GameFeel（顿帧/震屏/色差/粒子）
- **AC-15.1**：顿帧分级：普通命中 0ms / 暴击 30ms / 质变 50ms / Boss 死亡 120ms；触发后 ≤1 帧内全局时间缩放降为 0.05，时长结束 ±1 帧内恢复 1.0；顿帧期间 DOT 计时、投射物运动同步冻结（无"时间债"跳变）。
- **AC-15.2**：连续顿帧合并：30ms 内多个触发取最大时长不叠加（60 连发暴击 10s，time_scale 曲线无 >50ms 的持续冻结段）。
- **AC-15.3**：震屏 trauma 模型：输入分级事件，最大偏移 8px、最大旋转 1.5°，0.4s 内衰减到 0；玩家死亡场景不超过配置上限。
- **AC-15.4**：色差：暴击/质变触发 shader uniform，强度 0.004 起跳按级别放大，0.15s 内线性归零；全屏后处理开启时满足 AC-01.2 帧预算。
- **AC-15.5**：粒子：同屏发射器 ≤ 64，超出按优先级裁剪（击杀 > 暴击命中 > 普通命中 > 环境）；发射器 100% 池化（并入 AC-14.1 计数）。

### R-16 Roguelike 闭环（波次/经验/卡牌/游戏结束）
- **AC-16.1**：完整一局链路：开始 → 波次推进 → 击杀获得经验碎片 → 磁吸拾取（半径 120px 内自动飞向玩家）→ 升级弹 3 选 1 → 应用后投射物行为立即变化 → 玩家死亡 → 结算界面（击杀/波次/总伤害）→ 可重开。全程无人工介入外的报错。
- **AC-16.2**：升级界面打开时战斗逻辑完全冻结（投射物位置逐帧比较静止），关闭后恢复；升级期间敌人不生成、计时暂停。
- **AC-16.3**：波次规则：波 n 敌人总预算 8+4n、HP ×(1+0.15n)；逢 5 精英波、逢 10 Boss 波（互斥，Boss 波显示血条）；单帧生成 ≤ 8、同屏敌人 ≤ 120（超出排队，波次不卡死）。
- **AC-16.4**：卡池耗尽 fallback：所有候选被叠层上限过滤后转为"+5% 攻击"类属性卡，界面永不空。
- **AC-16.5**：一局平均 8~12 分钟到首次死亡（数值体验基线，A3 校准）。

### R-17 交付顺序（过程性需求）
- **AC-17.1**：实现启动前，存在并评审通过：模块依赖关系设计（对应本文档第 2 节的架构版）、核心类定义/伪代码、Resource 数据结构定义、伤害结算管道设计——四份文档先于第一行业务代码交付（用户"交付顺序要求"的落地）。
- **AC-17.2**：A2（数值框架）与 A3（具体数字）产出后，与本报告的推荐默认值冲突项显式列出并给出融合结论（融合记录落档）。

## 4. 需求漏洞与边界分析（逐条风险与处理建议）

| ID | 类别 | 风险描述 | 处理建议（本期落地） |
|---|---|---|---|
| E-01 | 极端构筑 | **无限分裂递归**：分裂词条被继承且"消亡时分裂"可无限自我复制，投射物指数爆炸 | 三重闸门：代数上限 3（M-10）、单次子数上限 8、全场硬上限 2000 拒绝生成（M-13）；`inheritable` 标记默认对"分裂"词条自身为 false（分裂词条默认不随子代继承，仅显式开启） |
| E-02 | 极端构筑 | **乘区堆叠爆炸**：独立乘区无上限相乘（1.5×1.4×1.2×…）终值天文数字 | 乘区按 ID 去重取最大（AC-12.2）；单结算乘区数 ≤ 8；单投射物词条 ≤ 12；AC-12.6 的 ×500 压力上限作为回归测试常驻 |
| E-03 | 并发 | **同帧多次 OnHit 重入**：一帧内同一投射物命中多敌人（穿透）、或碰撞体多次 overlap 回调，词条乘区（"每穿透×1.2"）重复入池 | 伤害请求在投射物侧按帧聚合后统一提交（一帧一目标一条）；词条层加"本帧已触发"标记；OnHit 派发序确定性（挂载序）保证复现 |
| E-04 | 生命周期 | **投射物回收时 Trait 触发顺序**：OnExpire 在池归还前 or 后触发？先触发可能生成新弹（占用池），后触发则读到了已清零状态 | 固定契约：回收函数 = 先派发 OnExpire（此时状态完整，允许申请分裂实例）→ 派发完成后执行清零 → 归还入池；池满时分裂申请失败不阻断回收；清零后任何词条回调被断言拦截 |
| E-05 | 生命周期 | **池污染**：复用实例残留词条/订阅/速度，下一发子弹"继承"上一发状态 | 归还清洁度断言（AC-14.3）+ 取出时二次校验；词条订阅绑定"投射物实例→引擎"的注册表随清零一并拆除 |
| E-06 | 生命周期 | **敌人死亡同帧被重复结算**：DOT 跳伤与多投射物命中同帧到达已死敌人 | 敌人死亡置 dead 标志于首次致死结算后立即生效；后续请求丢弃计数（AC-12.7）；死亡表现（爆炸/掉落）只执行一次 |
| E-07 | 并发 | **元素反应竞态**：同帧火+冰+电三元素同时满足两组反应条件，判定顺序不定 | 反应检测在敌人状态容器的帧末统一执行，固定优先级（碎裂 > 过载 > 超导），一帧至多触发一个反应；结果可复现（事件日志含顺序号） |
| E-08 | 数据边界 | **.tres 加载失败/字段非法/引用悬空**：负射速、0 池容量、循环引用 | M-14 启动期全量校验（AC-13.2/13.3）；致命配置（池容量 0）→ 拒绝启动报清单；非致命 → 剔除条目 + 告警；运行期不再加载 .tres（全部启动期注入） |
| E-09 | 性能边界 | **同屏实体超限**：敌人无上限生成、跳字/粒子刷屏 | 同屏敌人 ≤ 120（生成排队）；跳字 ≤ 80（超限合并到已有跳字）；粒子发射器 ≤ 64（优先级裁剪）；全部数值走 GameConfig 可调 |
| E-10 | 性能边界 | **Area2D 查询 O(n²)**：2000 弹 × 100 敌 = 20 万碰撞对/物理帧 | 弹幕与敌人碰撞用空间分区网格（哈希网格，推荐格边 128px）自行查询，不用物理引擎的 Area2D overlap 回调做弹-敌判定（物理层只留给玩家/拾取等少量实体）；敌人间分离力也走网格，频率降至 10Hz |
| E-11 | 时间一致性 | **顿帧与 DOT 计时**：time_scale 冻结期间 DOT/冷却/寿命若用 process 帧计数会跳变 | 所有计时统一用受 time_scale 影响的 delta 累计（顿帧时 delta≈0 自然冻结）；UI 动画用不受缩放的通道；顿帧合并策略（AC-15.2）防持续冻结 |
| E-12 | 生命周期 | **事件总线订阅泄漏**：词条/敌人死亡后未退订，悬挂引用累积 | 总线持弱引用，订阅者失效自动剔除；每次场景重开断言总线订阅数回落到基线（泄漏回归测试） |
| E-13 | 组合爆炸 | **分裂继承词条的内存/复制成本**：12 词条 × 2000 弹的列表深拷贝每帧发生 | 词条列表共享不可变部分（数据引用）+ 仅运行时状态独立（AC-07.4 的结构保证）；分裂继承做"引用复制 + 状态重置"而非深拷贝 |
| E-14 | 卡牌流 | **卡池空候选**：全部词条达叠层上限后 3 选 1 无卡可选 | fallback 属性卡（AC-16.4）；候选生成时先过滤再抽样，不足 3 张补属性卡 |
| E-15 | 输入边界 | **空输入/极端输入**：多指触控抢焦点、拖出屏幕、指针静止 | 单指针锁定（第一个触点生效）；位置钳制在玩家活动区（下 40% 屏）；静止 = 玩家不动但自动开火持续（游戏永不停摆） |
| E-16 | 状态竞态 | **死亡同帧升级**：玩家受致死伤同帧经验拾取满级，GameOver 与 LevelUp 状态冲突 | 状态机单线程仲裁：死亡事件优先级最高，LevelUp 请求在 GameOver 状态下丢弃并计数；事件按帧序处理（同帧内固定先后） |
| E-17 | 性能边界 | **光束高频跳字 + 折射分叉组合**：多目标 × 折射 × 15Hz 跳字刷屏 | 跳字全局上限并入 E-09 的 80；折射深度 ≤ 2（AC-04.3）；跳字合并窗口 0.12s |

## 6. 范围裁剪建议

### 本期必做（核心系统，验收对象）
- **M-01 ~ M-19 全部模块的最小可用实现**（每个模块按第 2 节职责边界裁剪，不含边界外功能）
- 可运行闭环：1 张主菜单 + 1 个战斗场景 + 1 个结算界面
- 内容最小集：武器 5 种（手枪/加特林/霰弹/激光/环绕力场，覆盖四形态——导弹可 M2 后补）、词条 ≥ 16 张（四大词缀家族全覆盖 + 通用属性卡）、敌人 4 种（追击小兵/快兵/远程/精英 + 1 个 Boss）、元素 3 + 反应 3
- DebugStats 面板（性能/计数验收的测量工具，随验收一起交付）
- 占位美术：纯色/几何图形 + 1 个统一粒子方案（验证打击感接口，不做正式美术）

### 本期不做（后续迭代，本期只留接口或完全不做）
| 项 | 处理 | 理由 |
|---|---|---|
| 存档/进度系统 | 完全不做（数据层已 Resource 化，天然可序列化） | 用户明示延后 |
| 关卡/剧情/多场景 | 只做无尽单场景 | 核心系统验证不需要 |
| 正式美术/动画/音频/BGM | 不做；粒子与震屏用占位验证接口 | 用户明示延后 |
| 移动端导出与触控深度适配 | 只做输入统一抽象 | 桌面 M1 为验收基准 |
| 成就/任务/多语言/设置界面 | 不做（暂停菜单仅"继续/重开"） | 非核心 |
| 第五种及更多武器形态 | 只验证"新增形态不改旧代码"的扩展性（AC-02.1 用 Dummy 形态测） | 扩展性 > 数量 |
| 数值精调（数百张卡） | 只做验证系统的最小卡池 | A3 产出结构，量产后置 |
| 网络/遥测上传 | 不做（DebugStats 本地导出 CSV 即可） | 无此需求 |
