## 0. 范围与核心语义

- **MetaStore**（`scripts/loop/meta_store.gd`）：结晶货币（crystal）+ 五条目强化等级 + 累计
  战绩（total_runs/total_kills/best_wave）的局外存档层。ConfigFile 持久化
  `user://meta_save.cfg`（SAVE_VERSION=1）；损坏判定树全回退路径【不写回】。
- **结转 = 死亡结算**：`player_died` 仲裁内 `_settle_run()`（一次闸 `_settled_this_run`）——
  本局金币全额（maxi(gold,0)）折结晶 + record_run + save。回菜单/胜利不结转（本作无胜利态）。
- **MetaPanel**（MENU 态宿主）：不占状态机迁移；与 MenuScreen 互斥实现 = 全屏 dim
  MOUSE_FILTER_STOP（add_child 晚于 menu_screen → 同层绘制在上遮挡开始钮）。
  state_changed 非 MENU 强制 close。购买仲裁权在 GameLoop（仅 MENU 且面板开启）。
- **核心红线**：全 0 级与 v0.9.0 行为逐位恒等（pkg10 M23 锚定：max_hp 100 / _add_gold 无
  缩放 / 快照 0.0 / xp fixed-seed 基线）。

### 定价序列（★逐级迭代，非 pow 一次算）

`price = 100 起逐级 ×1.6 后 round`——`p := 100; for i in level: p = int(round(float(p) × 1.6))`。
**round(100×1.6^4) = round(655.36) = 655 ≠ 冻结 656**（pow 一次算与逐级迭代在 L4 分叉，
故冻结逐级口径）。满级 → -1。

| 级（0 起） | 0 | 1 | 2 | 3 | 4 | 满级 |
|---|---|---|---|---|---|---|
| hpg/atk/greed/xp 下一级价 | 100 | 160 | 256 | 410 | 656 | -1 |
| seed_gold 下一级价 | 100 | 160 | 256 | — | — | -1 |

### 存档键布局（save() 契约）

```
[meta]  save_version=1 / crystal
[levels] String(id) 五键（表序）
[stats] total_runs / total_kills / best_wave
```

损坏判定树：`cfg.load` ERR_FILE_NOT_FOUND → 静默默认；其他错误 → warning+默认；
save_version 缺失 → warning 按 1 继续；>1 → warning 全默认不降读；<1 → 损坏默认；
crystal 缺失 → 0+warning、负 → 钳 0+warning；levels 逐条目缺失 → 0（静默，旧档兼容）、
越界 → clampi(0,max_level)+warning；stats 三键同规则。任何回退不写回。
wipe：内存全默认 + 删档（本无档静默——`DirAccess.remove_absolute` 对不存在文件在 macOS
返回 FAILED 而非 ERR_FILE_NOT_FOUND，实现以 `FileAccess.file_exists` 预检保证恒静默）。

## §2 注入四通道契约（GameLoop 接线，时序冻结）

| # | 通道 | 接线点 | 语义 |
|---|---|---|---|
| ① | hpg → `curse_handler.meta_hp_flat` | `_reset_run_state` curse reset 块**之前**注入 | reset 内 `recompute_max_hp` 收口生效；不存 player 字段 → respawn 不清零（每局重注入） |
| ② | atk/greed → `chip_handler.set_meta_stats(meta_stats_snapshot())` | `_reset_run_state` `_add_gold(-gold)` 之后（先载入覆盖上一局残留） | ★`reset_run` **不清** meta_stats（与 blessing_stats 关键差异）；消费在 stat_bonus 赐福段之后加和，atk 同 ⑥b 段共享 cap_chip_zone；快照仅此二键（xp/seed/hpg 不入——防双算） |
| ③ | seed_gold → `gold += starting_gold()` | ② 之后；`>0` 才注入 + emit_gold_changed | ★**直注入不经 `_add_gold`**——greed 不放大开局金（冻结语义，pkg10 M17 固化） |
| ④ | xp → `value *= meta_store.xp_mult()` | xp 链 遗物×角色×(1+K_chip) 之后 | 第 4 因子；与芯片 xp_gain 分立防双算；0 级 ×1.0 恒等 |

**结转**：`_on_player_died` 早退守卫后、`change_state(GAME_OVER)` 前插 `_settle_run()`——
一次闸；`gain = maxi(gold,0)`；meta_store 缺失 → `set_crystal_gain(0)` 降级不入档；
否则 add_crystal + record_run(hud.kills, hud.wave) + save（失败仅告警）+ 结算行回写 +
菜单统计行刷新。`_settled_this_run` 由 `_reset_run_state` 尾部复位。

**MetaStore 组装序**：`_boot_build_actors` 首位（先于一切战斗子系统；boot 即 load_save）。

## §4 A9 假设清单（主控冻结裁定，改动需重新评估）

| # | 假设 | 裁定内容 |
|---|---|---|
| A9-1 | **通胀控制不做** | 结晶产出无衰减/无递减曲线（每局金币全额折结晶）；定价复利 1.6 为唯一回收阀。实测通胀失控再立项 |
| A9-2 | **wipe 无用户入口** | 存档清空仅测试/运维可用（MetaStore.wipe / set_save_path），无 UI 入口——用户误触清档风险归零，代价是弃档用户无自救通道 |
| A9-3 | **五条目封闭** | UPGRADES 为封闭常量表；新增条目 = 表尾追加（旧档缺键 → 0 静默兼容），禁止重排序（行序/存档键序/镜像三处同序） |
| A9-4 | **总局数仅死亡计** | total_runs 只在 `_settle_run`（player_died 仲裁路径）+1；重开中途放弃（无死亡直接回菜单——本作状态机无此路径）不计 |
| A9-5 | **局中金币不落盘** | 金币只在死亡结算时一次性折结晶入档；局中任意时刻杀进程 = 本局金币结晶全损（无自动存档/断点续传） |
| A9-6 | **测试档隔离** | pkg10 独立档 `user://pkg10_meta_test.cfg`（boot 后首件事 set_save_path+wipe；收尾仅 wipe 自身档，不触碰默认路径）；**〔审查 Important 修复 2026-09-01〕headless 回归自动隔离**——产品 boot 期 `DisplayServer.get_name()=="headless"` 时 MetaStore 自动改写 `user://meta_save_headless.cfg`，pkg0~pkg9 死亡用例的 settle 落独立档，真实档（窗口模式 `user://meta_save.cfg`）永不被测试写侧污染，原「回归机须无档」前提取消 |
