# R232 结算链瘦身刀单（GDD-lite）

## 概述

本轮把单次伤害结算成本从 **50.1µs/结（MICRO 权威，PC）压到 <25µs**，并把结算预算帽从「PC 口径常量」复核为「真机标定常量」，目标是深载饱和行真机 fps p50 **27→45+** 且弃N 显著下降。主刀=resolve 链与命中链（ctx 构建/词条预聚合）的单次成本瘦身；全部为纯成本刀，**伤害数值/顺序/词条触发逐位等价是第一门禁**，R223 预算系统 DPS 守恒语义零改动。

## 项目背景与测量事实（已定案，直接采信，不重新推导）

- 工程：Godot 4.3 GDScript 竖屏割草肉鸽（`repo/`）。用户硬需求=真机深载 fps 90-120（现 19-43）。
- R231 已收口（git a7acfa3，vc36 交付）：弹段三刀真机兑现（弹段 35-74→12ms p50、快N 覆盖 52%、深载 fps 中位 +30-50% 至 38）。
- **vc36 真机判读（`docs/qa/2026-10-05-vc36真机日志.txt`，tracker 二cd）**：fps 塌方行归因=结算链饱和——顺>2000 行 fps p50=27（弹段仅 16ms 非瓶颈）；顺<800 行 fps p50=59；同 dc 段 3.5 倍 fps 差（fps70@dc933顺346 vs fps20@dc991顺3595）。结N 饱和 ~2100/s。**弃N 深载 max 1554/s、饱和行 500-1500/s=真实伤害被预算系统永久丢弃**（须缓解）。
- **T0 分离测量（`docs/qa/2026-10-05-R231-T0分离测量.log`）**：单次结算 MICRO 权威 **50.1µs/结**（批 48/96/192 线性比 1.13）；深载 ~51 结/步 PC ≈2.6ms/帧，真机 ×2-4 估 5-10ms/帧（放大系数是估，vc37 前不做承诺）。
- 因果模型（自洽性检查，标注为推导非结论）：饱和带 fps 25-27 时结N≈2400/s ≈ 帽96×fps27，与观测 ~2100/s 吻合——结算链吃满预算是 fps 塌方与弃N 高的共同根因。若真机单结 100-200µs，96 结/帧=9.6-19.2ms/帧，与 fps 20-27 量级自洽。单结成本减半 → 同帽下帧时长降（fps 升）→ 帽可上调（弃降）——两级兑现路径。
- 代码事实（已核实）：
  - 结算链入口 `projectile_base.gd:591 _submit_hit`（§4.4 时序：①ctx 构建 `_build_damage_ctx`:726 → ②词条乘区预聚合 `_prepare_hit_traits`:654（TraitStack.collect_mult_pools 逐词条 SynergyRules.evaluate 条件自评+易伤/遗物乘区注入）→ ③ON_HIT 派发（挂载序）→ ④`pipeline.resolve` → ⑤`_on_settled` 附着/穿透/回收后处理）。
  - `damage_pipeline.gd`：resolve 前置闸（sanitize→幂等→存活→-4 档→预算闸）+ `_resolve_core` 九步（顺序禁止重排）。R223 预算：tier1 帽48/tier2 帽96，超帽 FIFO 顺延同对 base/flat 累积（期望 DPS 守恒）、帧头按预算冲刷、12 帧过期强冲、硬帽 256 诚实丢弃；R220 已有 ModifierStack 复用（刀8③）与 damage_resolved 批化派发（刀11）。
  - **MICRO 臂量程口径**：`probe_r225_separation_cases.gd` 计时窗外预构建 ctx（「量 resolve 不量构建」）——50.1µs **不含** ctx 构建与词条预聚合；真实机成本=①+②+④ 全链，本轮须建立 FULL 口径（见 ③）。
  - resolve 热路径残余 Variant 反射（R220 刀4 漏网）：`_target_alive` 的 `target.get("dead")`、`_read_status_vuln` 的 `.get("status_vuln")`、`_inject_vuln_pool` 的 `.get("elemental")`——每命中各 1 次 String 属性读，ARM 放大（R210 先例量级）。
  - 每命中分配点：DamageContext.new（①侧）+ TraitContext.new（②侧）+ DamageAudit.new/DamageResult.new（④侧，R220 评审裁定**不池化**——随 result 逃逸到五订阅者，复用=跨命中污染，红线继承）+ `_populate_result` 的 breakdown 字典（消费面=`relic_handler.gd:491-493` has 检查×3 + `_broadcast` burn_dmg 检查 + HUD 峰值统计）。
  - 顺延持有面：`_defer_settle` 把 ctx 对象存进 `_pending_pair` **跨帧持有**并逐次 `held.base_atk +=`——这是 ctx 池化的最大障碍，也是刀1b/刀2 的交汇点。
  - 词条条件分类（`synergy_rules.gd` 已核实）：条件输入=目标元素态/目标血线（活）＋ ctx.hit_flags/pierce_index（每命中变）＋ player_hp_pct/is_first_hit_of_wave（帧稳定）；贡献值 contribution 为词条数据纯函数（待分析全条件复核）。
  - **「同弹同敌重复命中」前提修正**：非 boomerang 弹生命周期级 `_hit_uids` 去重（一弹一敌一命中），重复命中仅存在于回旋刃（ICD 0.4s）与激光/orbit tick 通道——缓存轴定为**同弹跨命中**（栈随弹冻结），不是同弹同敌。
- 测量资产：`probe_r225_separation`（RES/TICK/MICRO 三臂，MICRO=每结算 µs 权威）；深载探针 `probe_r224_deepload`；电池 `python _batt_r215.py`（110 套件）。
- R231 坑纪律（沿用）：性能前提**当日同进程复测后才立项**；探针基线轮转按运行轮转（已修正）；cases 文件禁 `test_` 前缀防电池 glob 误收；套件总项数也要断言（防哨兵类型错位静默假绿）。

## ② 刀单定案

### 刀序总览

**刀0（测量先行）→ 刀1a（反射清扫）→ 刀1b（ctx 复用+pending 袋）→ 刀1c（词条预聚合缓存）→ 刀1d（resolve 小项，按 STEP 表挑）→ 刀2（量化，默认不动刀）→ 刀3（参数复核，条件刀）→ 刀4（条件刀，默认不做）**。每把刀独立提交、独立可回退；刀0 是全部立项前提（R231「当日同进程」纪律制度化）。

### 刀0 步骤级分解测量（必做，先行）

**一句话**：给 resolve 九步+前置闸逐项打点耗时、给全链（①②④）建立 FULL 口径、给顺延 churn 建立量化口径——三件测量在同一新探针 `probe_r232` 内完成，复用 r225 的 boot 构筑与目标池框架。

**改动点**：新建 `tests/probe_r232_knife.gd` + `probe_r232_knife_cases.gd`（-s 入口零工程类名直引纪律沿用；cases 禁 test_ 前缀）。四臂：
1. **STEP 臂**：MICRO 框架内对 resolve 逐段计时（sanitize/幂等/预算闸/聚合 ③-⑥/掷骰⑦/populate/目标侧⑧/finalize+broadcast/cache），输出 µs 构成表；
2. **FULL 臂**：计时窗=①ctx 构建+②词条预聚合（collect_mult_pools+易伤/遗物注入）+④resolve；**③ON_HIT 效果派发与⑤后处理不入窗**（其成本归 RES 臂弹段，ON_HIT 副作用会污染合成测量——口径在 JSON disclosure 披露，分析阶段定案实现细节 AC-1）；
3. **CHURN 臂**：override 强制小帽（如 -3+tier 注入帽 8）驱动饱和顺延，测每顺延项入队/同对累积/帧末维护扫描的单项 µs 与每帧维护总耗时；
4. MICRO 臂（r225 同构复刻，保证与 50.1 基线可比）。

**产出**：`docs/qa/probe_r232_knife_baseline.json`（轮转 _prev1 只留一代）+ 步骤耗时表。**后续每刀落完同进程复跑 A/B**。

### 刀1a resolve/命中链 Variant 反射清扫（必做，首发小刀）

**一句话**：把 R220 刀4 漏网的三处 String 属性读补上 Enemy 类型分支直调，桩路径保留。

**改动点**（逐处，开发可直接开工粒度）：
1. `damage_pipeline._target_alive`：`p_ctx.target.get("dead")` → `if p_ctx.target is Enemy: return not (p_ctx.target as Enemy).dead`，else 保留 Variant 路径（R210 双轨先例）；
2. `damage_pipeline._read_status_vuln`：`.get("status_vuln")` → Enemy 分支直读字段（字段名以 enemy.gd 实测为准，分析确认后落码；Enemy 无该字段则维持 .get 并披露）；
3. `projectile_base._inject_vuln_pool`：`p_target.get("elemental")` → Enemy 分支直读。

**预期收益**：每命中省 3 次 String 反射，估 −2-6µs/结（ARM 放大在真机兑现，PC STEP 表定数）。
**伤害等价论证**：typed 直读与 Variant .get 同值同型（R220 刀4 / R210 双轨先例已证模式）；测试桩走 else 分支原路径。
**风险与回退**：单点函数级改动，逐处独立 revert；风险=Enemy 字段名/访问器与 .get 口径不一致（如 getter 有副作用），分析阶段对拍后落码。

### 刀1b DamageContext 复用 + pending 字段袋（必做，主刀之一）

**一句话**：弹侧成员级复用 ctx（借出即全字段重置，ModifierStack 复用同款纪律），顺延积压从「持有 ctx 对象」改为「纯值字段袋」，解除跨帧持有对池化的封锁。

**改动点**：
1. `projectile_base`：持成员 `_ctx_scratch: DamageContext`，`_build_damage_ctx` 改为重置+覆写（重置清单=DamageContext 全部 19 字段，头注列明——R220 `_acquire_stack` 同款「借出即清」清单纪律）；add_entries 改 `clear()+逐项 append` 复用数组（不整批换引用——类型化数组不收 Array 直赋的现网注释保留）；
2. `damage_pipeline._defer_settle`：`_pending_pair` 存「字段袋」（source/target uid、base_atk、flat_bonus、element、hit_flags、rng_stream_id、frame_stamp、target_resist、crit 参数、kill_backlink、pierce_index/generation 等冲刷必需字段——完备清单由分析销账 AC-6）；同对累积改对袋累加（语义等价：现网就是 `held.base_atk +=`）；冲刷 `_flush_entry` 用另一只**pipeline 侧**复用 ctx 从袋重建再走 `_resolve_core`（重建取顺延时快照值——现网 held ctx 即顺延时值，口径逐位保持）；
3. 袋对象池化：pending 项冲刷/丢弃即还池（上限=硬帽 256 同量级预建）。

**伤害等价论证**：resolve 的输入是 ctx 字段值——复用只要「每次命中前全字段重置」则逐位同值；顺延路径从「持有对象」变「持有值」，冲刷重建后九步输入相同。**前置条件（分析销账 AC-3）**：ctx 引用逃逸面全量清点——①pending（本刀解除）；②TraitContext.damage_ctx（ON_HIT 派发期词条 handle 是否持有越过返回）；③`_on_settled`/`_apply_elemental` 是否再读 ctx（初查读 result/tctx 不读 ctx）。若②存在持有者，降级为保守档：仅 add_entries 数组复用+字段直写，不做对象复用，收益重估并回报主控。
**预期收益**：省每命中 1 次 RefCounted 分配+数组重建+顺延项的对象持有开销，估 −3-8µs/结（FULL 口径）；真机分配/GC 放大另有增益（不作承诺口径）。
**风险与回退**：static var 开关 `CTX_REUSE := true`（一键回退原路径，REUSE_MODIFIER_STACK 先例）；最大风险=逃逸面漏清点（跨命中读到旧字段），靠 test_r232_ctx_reuse 生命周期矩阵锁。

### 刀1c 词条乘区预聚合缓存（必做，主刀之二）

**一句话**：把 SynergyRules.evaluate 拆成「贡献值（词条数据纯函数，弹侧缓存一次）×条件判定（活评）」，MULT 词条的贡献字典也弹侧复用改值，命中期只付条件读。

**改动点**：
1. **条件分类表（设计定案，分析复核 AC-5）**：
   - 纯静态（NONE 常驻）：贡献+条件全静态 → spawn 期（或首命中惰性）一次算完，命中期零成本；
   - 静态贡献×活条件（TARGET_FROZEN/BURNING/SHOCKED/HP_BELOW）：命中期只跑条件（目标态读），贡献取缓存；
   - 静态贡献×弹内变条件（AFTER_BOUNCE/PIERCE_INDEX_GE）：条件读 ctx.hit_flags/pierce_index（活评，值已在 ctx 上零额外读），贡献取缓存；
   - 帧稳定条件（PLAYER_HP_BELOW/ABOVE、WAVE_FIRST_HIT）：按帧缓存或活评，分析定（帧内 player_hp_pct 稳定论证）。
2. 缓存挂点：弹侧（runtime TraitStack 随弹冻结于 spawn——`copy_runtime` 先例）持「预聚合池数组 + 每词条静态贡献缓存」；`collect_mult_pools` 改为遍历 MULT 子集→条件活评→命中则把缓存贡献写进**弹侧复用的 mult_pools 数组**（逐项改值不重建字典——前提：mult_pools 无 resolve 后持有者，AC-7）；
3. **失效轴**：栈版本号——飞行中栈写者（词条 handle 改 layers/value_mult/data 覆盖）清零复核（AC-4）；有写者则版本号失效重建，无写者则 spawn 后恒有效。

**伤害等价论证**：贡献值从「每命中求值」变「spawn 期求值一次复用」——只要 contribution 是词条数据纯函数则逐位同值（全 condition_id 纯度复核是落刀前提，AC-5）；条件判定路径不动（仍每命中活评，含目标态/血线/flags 读）。缓存命中时 mult_pools 字典内容与现网逐键相等（测试逐值对拍）。
**预期收益**：深载 12 词条栈 MULT 子集 4-8 次 evaluate → 静态部分归零+字典构建改复用，估 −3-10µs/结（FULL 口径，STEP/FULL 表定数）。
**风险与回退**：static var 开关 `TRAIT_PRECACHE := true`；最大风险=纯度复核漏项（某 condition 的 contribution 读 ctx/target）→ 缓存值过期，靠 test_r232_precache 全条件×随机参数对拍锁。

### 刀1d resolve 内小项（必做但按 STEP 表挑 2-3 项，不整包)

候选池（刀0 STEP 表出来后按占比挑）：
- `_sanitize` 三池逐项 `e.get("contrib")` 与聚合双遍历——保守方案仅 typed 键直读优化；「单遍融合」需先全检后聚合或回滚论证，默认不做；
- `_populate_result` 的 breakdown 字典：resolved_mults 非空才构建+预分配；池化不做（逃逸面：relic_handler×3 + HUD 峰值统计 + 测试断言，AC-10 清点后定）；消费面契约改造（has 检查→typed flags）明确不做（动 relic 契约）；
- `_balance()` 每命中 1-3 次 → `_resolve_core` 入口取一次传参；
- `DamageAudit.new()/DamageResult.new()` 每命中 2 分配：**红线不动**（R220 评审裁定继承）；STEP 表显示合计占比 >30% 时提「结算消费面减负」另立项（R188 移交清单同账），本轮不授权。

**等价论证与回退**：全部为「同值计算的路由搬运」；逐项独立开关或独立 revert。

### 刀2 顺延/冲刷 churn 成本（量化刀，默认不动刀）

**一句话**：CHURN 臂先量化三块——每帧 `_end_frame_pending_maintenance` O(pending≤256) 全表扫描、每次顺延的 pair_key+字典写、冲刷期 ctx 重建（刀1b 已天然消掉对象持有）——占比不达标不立刀。

**判据（写死）**：churn 三块合计占结算轴耗时（RES 臂口径）**>5% 才立刀**；预判（明示为预判）：256×0.1-0.3µs≈25-80µs/帧 ≪ 结算主成本 2.6ms/帧（PC）——**大概率假刀**。若立刀，唯一候选=维护扫描摊销（队头惰性检查，依赖 FIFO 帧号单调性——同对合并会刷新 frame 破坏单调，需分析论证，默认不做）。
**风险与回退**：纯测量零产品码；立刀时单独设计补充。

### 刀3 结算预算参数真机标定复核（参数刀，条件触发）

**一句话**：刀1 落地后（MICRO <25 达标为前置），用「目标结算时间份额 ÷（真机单结 µs×1.25 安全系数）」重推 SETTLE_BUDGET_T1/T2，仅动这两个常量。

**改动点与纪律**：
1. 标定输入：vc37 反推真机单结 µs（结N×单结耗时与 fps/余量对账，AC-8）；份额目标初始值 **tier2 ≤6ms/帧、tier1 ≤3ms/帧（初始值，待调参）**；
2. 只动 `SETTLE_BUDGET_T1/T2` 两常量；`SETTLE_STALE_FRAME(12)`/`SETTLE_PENDING_HARD_CAP(256)` **不动**（语义邻接——动过期窗/硬帽=改卸载形态，需行为论证另立项）；
3. 阀门纪律全量：三重门（mobile∧帧率优先∧tier≤2）+ settle_budget_override 可否决 + 真机工况标定声明（换算依据落报告）；DPS 守恒机制（FIFO 顺延同对累积）零改动——帽变大只是「少顺延少弃」，守恒路径原样；
4. 预期方向（不预设结论）：单结减半 → 同份额下帽约可 ×2（96→192/48→96 档位方向），弃N 相应下降。

**风险与回退**：override 注入即回退；风险=帽上调后饱和帧行时长反弹压制 fps——AC-V1 两判据（fps 与弃N）**同时**达标才收口，fps 劣化即回滚帽值。

### 刀4（候选，条件刀）同帧批处理共享面

**触发条件（写死）**：刀1 全落地后 FULL 臂仍 >25µs 或 AC-P3 弹段未达标且 STEP 表显示剩余大头在 ctx/预聚合——才启用。
