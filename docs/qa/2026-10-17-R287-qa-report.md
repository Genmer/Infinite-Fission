## 缺陷清单

### D1（medium）diag_export 口径声明头被 R287 句内两处未转义 `%` 打断——导出日志丢整个 header

- **位置**：`autoload/debug_stats.gd:795`（`diag_export()` header 巨型格式串）内的 R287 句：`……vc86 定谳深载〔敌90〕弹+敌+网仅占步 30-42%、其余 58-70% 散在未分窗段……`
- **根因**：`30-42%、`（`%、`）与 `58-70% 散`（`% `+汉字）两个序列未按同文件先例转义为 `%%`（对照：同串 R269 句 `开85%%/开75%%` 已正确转义）。全串扫描确认**仅此两处**未转义 `%`，且都在 R287 新句内——R287 引入无疑。Godot `%` 格式化遇不支持格式符报错并将 header 整体格式化为空串，导出文本只剩 body。
- **复现步骤**：
  1. `cd E:\Code\Agent\Infinite-Fission && ./tools/Godot_v4.3-stable_win64_console.exe --headless --path repo -s tests/qa_r287qa_probe.gd`
  2. 看 F5 项：`FAIL | F5 口径声明头 R287 句在场（六键名序列原文）（len=269 首60=v0.1.85_vc86── 玩法事件（独立环 1/120 行……`，且运行期控制台恰一条 `ERROR: unsupported format character`（两次独立运行同签名——确定性缺陷，非瞬态）。
  3. 用户路径等价复现：主菜单「导出日志」按钮（`scripts/ui/menu_screen.gd:560 _on_export_log_pressed` → `DebugStats.diag_export()`）——导出文件/剪贴板文本不含 `=== Infinite Fission 真机诊断日志 ===` 起的口径声明头。
- **期望**：验收依据①「口径声明头追加 R287 句」——header 完整含 R287 句与全部既有口径声明（格式化成功，文本以 `=== Infinite Fission 真机诊断日志 ===` 开头、数千字符量级）。
- **实际**：`diag_export()["text"]` 仅 269 字符（=纯事件环 body 残段），header 为空串；格式化报 `ERROR: unsupported format character`。**波及面**：仅导出装配路径——1Hz 实时行（`_diag_format_line`，另一条格式串）与环形缓冲行不受影响（F1/F3/R7 全绿佐证），玩法/存档零影响。
- **严重级别**：medium（用户可达的诊断导出功能部分失效——口径声明/版本/设备头整体丢失；无崩溃、无行为位移、pkg4 116/116 佐证）。
- **修复方向（供开发参考，QA 不动手）**：两处 `%` 转义为 `%%`（与同串 `85%%` 先例对齐）；修后回归本探针 F5（须绿）+ diagfreeze compare（防误伤）。
