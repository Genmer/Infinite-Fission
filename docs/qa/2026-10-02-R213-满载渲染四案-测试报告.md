## 缺陷清单

### QA-R213-001（medium）：C 案满载白乘经「门关闭 + 池复用」路径残留，重生敌持续过曝

- **严重级别**：medium（验收 1C「门切换/回落边界双通道互复位零残留」被违反；错误视觉状态可长期驻留；功能不受影响，下次受击自愈，可绕过）
- **复现步骤**（两条同根，均可自动化复现）：
  1. 跑 `--headless --path E:/Code/Agent/Infinite-Fission/repo -s probe_qa_r213_edge.gd` → S1-1 / S1-5b / S1-5c FAIL，EXIT=1。
  2. 最小真实时序（S1-5，复刻 80 阈值群杀现场）：
     `Enemy.fullload_override = 1` → 敌 `take_result` 受击（`_apply_flash(1.0)`：modulate=(3,3,3)、材质摘除）→ `Enemy.fullload_override = 0`（群杀帧 live_count 跌破 80，门关）→ `apply_damage` 致死 → `pool.release`（`_reset_state` → `_apply_flash(0.0)` 走桌面分支）→ `pool.acquire` + `spawn` 重生。
- **期望结果**：验收 1C 原文「两分支互相复位对方通道（门切换/回落边界零残留）」——重生后 `sprite.modulate == Color.WHITE`。
- **实际结果**：`modulate = (3, 3, 3, 3)`；入场渐显（0.12s）完成后仍过曝（S1-5c PASS 证实非瞬态），持续至该实例下次受击才被桌面分支 `p_amount>0` 复位（S1-3）。直调边界（套件③）与反向门序（S1-4 门开侧池复用）均干净——缺陷为单方向。
- **根因定位**（供开发循环，未修）：`scripts/entities/enemy/enemy.gd` `_apply_flash` 桌面分支 `p_amount <= 0` 路径（:2361 `elif _sprite != null and _sprite.material == _material`）只摘材质、不复位 modulate.rgb；满载分支是唯一写 modulate>1 的口（:2350），其复位只覆盖直调边界，未覆盖池复用消费口（spawn :531 / `_reset_state` :1847 均以 `_apply_flash(0.0)` 兼任摘除口）。另 `_assert_clean`（object_pool.gd:104）不检查 modulate.rgb，残留静默入池、池污染计数零告警。
- **触发窗口与频率**：死亡即停 tick（`_flash_left` 冻结），门关后归还的每个「门开期受击」实例都带残留入池；敌数在 80 阈值附近的群杀帧（AoE 清场）恰好同时满足「受击→死亡→门关」，真机满载波次清屏期可复现。

> **状态更新（2026-10-02 复测）：已验证修复。** 修复内容：`_apply_flash` 归零路径（p_amount≤0）由 elif 条件摘材质改为无条件复位 modulate + 条件摘材质（enemy.gd :2374-2381，与满载分支对称双通道互复位）。探针 S1-1/S1-5b/S1-5c 全部转好，31/31 EXIT=0。
