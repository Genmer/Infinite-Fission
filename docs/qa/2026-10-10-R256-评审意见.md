## 总评

**可交付 vc64，无 high。** 本批三刀方向正确、实现与 tracker 声明高度一致、证据链可复核（复活实证与 gate1 日志逐字吻合；翻案断言与 r221 帽契约互证成立；环境漂移判定有时间线支撑：14:17-14:18 干净窗口 perf_500 P95 7.537 PASS / perf_800 P95 7.391 PASS，14:39-14:44 QA 并行窗口三跑 12.7-14.8 全 FAIL）。序 3/4 缓办裁定诚实、依据在码。**最影响体验的一件事**：序 2 分片轮的「单帧 ÷6」在真机帧抖动下不可持续（相位合并不可逆，见 M1）——不构成回归（最坏退回 R255 旧形态），但本批主打的手感收益会在最需要它的重载场景里随时间衰减，且未在 tracker/注释披露。

## 问题清单

### M1（medium）分片轮相位坍缩——「每帧恰 1 片」只在理想帧距下成立，真机上不可逆退化
- **位置**：`scripts/loop/game_loop.gd:3919-3923`（重排 `_sep_due[i] = _sep_clock + SEPARATION_INTERVAL`）
- **现象**：同帧到期的多片被重排到**完全相同**的新到期时刻，且轮内无任何再错峰机制。一次 ≥33ms 长帧（掉帧/GC，真机重载常态）或任何系统性偏离 60.0Hz 的帧距（如稳 55fps：18.2ms 帧距 vs 16.7ms 片距，周期性同帧双片）即把两片永久锁相同相位；合并单调累积、不可逆，逐步退化为 2 片/帧、3 片/帧……全合并后 = 每 100ms 一帧全量分离，恰是本批要消灭的 R255 旧尖峰形态（enemy 段 10.7-12.3ms「咯噔」）。**衰减最快的地方恰是重载掉帧场景=最需要它的场景。** 30Hz 档（sim30 现默认关）下构造性两片/帧，立即成对合并，实际收益 ÷3 非 ÷6。
- **佐证**：pkg5 B.5b（pkg5_cases.gd:864-868）用固定 0.016s 等步进理想驱动，结构性测不到该形态；:3921 注释只披露「长帧追赶批一次结清不积压」的收益面，未披露相位合并副作用，tracker 同。
- **建议**：重排保留片间相位锚（如按整周期步进 `_sep_due[i] += k×INTERVAL`，仅当落后超一整周期才以 `interval×i/6` 重锚错峰）；B.5b 补一条「模拟一次 200ms 长帧后连续 6 帧仍每帧 ≤2 片」断言。
- **附注（数值推断，非实测）**：本批仅有的三跑 perf_500（14:39-14:44，QA 并行污染）enemy 段均值 5.07/5.66ms 反而高于自述回退对照轮的 4.13ms——单跑噪声下「序 2 有收益」当日没有一次干净测量（14:17 干净窗口 gate1 为序 2 落地前）；「非本批回归」成立（对照轮同 FAIL），「收益兑现」仅由 B.5b 结构断言支撑。

### M2（medium）压力门复活但未堵「负载在场」守卫——16 天敌 0 假 PASS 的故障模式仍可复发
- **位置**：`tests/stress/perf_500p100e_cases.gd` _report 段（仅 P95 :270 与池 :290 两类断言）；soak/orbit_field_bench/deep_wave 同构
- **现象**：敌 0、甚至 state 停 MENU 时空转，P95<8.3ms 依然 PASS、exit=0。本次靠直调复活，但下一次出发链再被任何新模态挂起（R252 同型事故），五套件会再次安静「全绿」——复活治了这一次，没治这一类。storm ①a「≥90% 帧在载」是间接负载守卫，其余五套没有。
- **建议**：每套测量前加硬断言：`state==PLAYING` 且 `spawner.active_count() ≥ 目标×0.8`（弹同理），不满足即 FAIL。几行代码，防复发价值最高。

### M3（medium-low）storm 翻案后缺「派发链活着」下限锚；①b 潜伏 30Hz 假红
- **位置**：`tests/stress/storm_cases.gd:287-298`
- **现象**：①a 计驱动侧 resolve 调用（harness 自检性质，派发链死活不影响），①b 只设上限——派发峰值 0 也 PASS；消费方全断线时断言②比率塌向 1.0 同样 PASS（②只有 ≤2.5 上限无下限）。全死管线仅靠断言④（4 次注入击杀的 DeathPop 复用）间接兜底。稳态实测派发恒钉在帽上（storm_r256b.log「逐检查点帧结算恒 48」），下限锚现成。
- **建议**：①b 补 `peak_resolve ≥ DISPATCH_FRAME_CAP`（300/帧输入+0.5s 顺延窗下稳态必吃满帽）。另：①b 对 60Hz 常量断言，而运行帽走选择器（damage_pipeline.gd:479 `dispatch_cap_now()`，sim30 时 96）——headless 现状 sim30 关无假红，但未来 sim30 生效或测试注入 -3 哨兵时将 49-96 假红，登记为潜伏坑。

### L1（low）tracker「B.5b 六断言」实为 5 条
- **位置**：FEEDBACK_TRACKER.md:1636（列了 5 项）/ pkg5 日志 5 条 `E-10分片` PASS / pkg5_cases.gd `_test_separation_shard_wheel` 5 个 `_check`。计数差 1，文档口径小疵，顺手修。

### L2（low）序 1 战斗泵单帧可超支至 ~7ms（移动端单项原子）
- **位置**：`scripts/cards/card_desc_prewarm.gd:89-99` + game_loop.gd:645
- **现象**：2ms 预算不分割单项，真机单项 3.7-6.7ms（R221 实测注记在案）→ 战斗渲染帧最坏叠加 ~5ms，靠跳 2-3 帧还账。暴露窗=菜单停留短的玩家首局前段（队排空即止）。与根治 45ms card_open 顿挫（gate1 实测峰值 45.40ms）相比净收益明确，注释已如实披露。MENU 态 4+4+4ms 三泵与 PLAYING 2ms 泵互斥不叠加（elif 分支+menu_screen 可见性门，已核），不构成叠加挤占。
- **建议**（不改也能交付）：泵预算按 PerfGovernor 档位门控（tier1 时降 1ms 或停泵），避免与最差档设备叠帧。

### L3（low）deep_wave C3 条件跳过未计入结果口径
- **位置**：`tests/stress/deep_wave_probe_cases.gd:180`
- **现象**：LEVEL_UP 窗未开即打印跳过、不计 fail——本批复跑日志（r256_test_deep_wave_probe.log）显示 C3 实际被跳过（state=2），「六套全绿」中该断言未真正执行。历史遗留非本批引入。建议跳过计 skipped 并入汇总行披露。

### L4（low）A/B 归因不可独立复核（无版本戳）
- perf500_ctl.log 与 r256/r256c 日志格式完全相同、无代码版本标识，且仓库无 git——「ctl=回退轮对照」只能采信开发者自述。建议压力日志头打构建戳（常量 build id 即可），使 A/B 归因可审计。

## 体验断点（玩家视角）

- **序 2 错峰推移**（读码推断，未实机）：每敌服务频率 10Hz、单次 ≤4px、各让一半重叠量的语义逐位不变；同对重叠的两半让步最坏相隔 ~83ms 落地——重叠解析多 1-2 拍（约 100-200ms），对定位为「观感修正非物理约束」的分离系统不可感，簇群去同步呼吸反而更自然。真正的体验风险是 M1：相位合并后手感在「错峰/同帧齐推」间漂移，可能重现旧「咯噔」。真机复验点：满屏敌推挤是否出现周期性密度波动。
- **序 1**：玩家可感知的正向（每局首次升级 45ms 冻结的根治路径）；代价见 L2（头几十秒偶发泵尖峰）。
- **序 0/序 5/洪水裁定**：纯测试设施与日志卫生，零体验面。
- **未体验到**：真机图形界面与手感（约束禁跑 Godot），以上为代码语义+日志证据的推断。
