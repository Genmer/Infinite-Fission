## 一、优先模式说明

设置页新增「优先模式」行（`settings_panel.gd:181`，插在「帧率上限」行之后 y446，十行几何钉死：行距 46、末行钮底 812≤824−6px、卡高 968 不扩——r220_governor ② 实测），两态循环 ✓帧率优先 / ◉特效优先（`settings_panel.gd:502`），写即存（`settings_panel.gd:397-402`）；设置页底部 hint 已补白话：帧率优先=卡时自动压特效/弹幕/跳字密度保帧，特效优先=保持表现（`settings_panel.gd:205`）。

### 1.1 两档语义（PerfGovernor 全局调速器，`autoload/perf_governor.gd`）

| | **帧率优先**（perf_mode=0，默认） | **特效优先**（perf_mode=1） |
|---|---|---|
| 语义 | 掉帧 10% 就采取措施保帧率 | 容忍掉帧 30% 保画面表现 |
| 降档阈值 | EMA < target×**0.90** 持续 **2s** 降一档 | EMA < target×**0.70** 降档 |
| 升档阈值 | EMA > target×**0.95** 持续 **5s** 升一档 | EMA > target×**0.85** 升档 |
| 降档地板 | **tier 1**（`perf_governor.gd:123` `floor_tier := FX_FLOOR_TIER if fx_mode else 1`） | **tier 2**（`FX_FLOOR_TIER=2`，`perf_governor.gd:27`） |
| 模式门控刀 | 刀12/13/14 生效（配额/数值收紧） | 刀12/13/14 全部回到旧值（无配额、原数值） |

- 采样：每 0.5s 采 `Engine.get_frames_per_second()` 入 EMA（α=0.25，首采直赋）；`PROCESS_MODE_ALWAYS`——暂停/选卡期采样不停，但转换计时只在「GameLoop.state==PLAYING ∧ ¬paused」内累计（选卡/暂停挂起：计时冻结不清零、不清 EMA——主控决策#2）。
- **target 帽语义（收口修轮落点，`perf_governor.gd:179-194`）**：target = **min(fps_cap, 120, 屏幕刷新率)**；fps_cap=0（不限）取 120；刷新率不可知（headless/查询失败 → −1）不钳制、保持旧口径。「帧率上限」是**帽不是保底目标**——60Hz 面板 + 上限120 时 target=60，达不到上限不再被当成掉帧（修复原「恒降档钉死 tier1 永不升档」缺陷）。

### 1.2 「帽保持 1」——档位地板与特效质量帽

- 帧率优先降档**地板 tier=1**：调速器最低只降到低档，**档位保持 ≥1**，不存在更低的档（`perf_governor.gd:123`，常量注释同句 `:27`「特效优先降档地板（帧率优先地板 1）」）；升档帽恒 3。
- 特效优先地板 tier=2：mobile 上 fx_quality 帽相应**保持 ≥1**（fx_quality_cap 映射 tier−1，`:61-71`），特效质量最多收到中档、不会收到 0。
- fx_quality_cap() 生效门（顺序冻结，契约 §8#12 承重墙）：① tier_override∈[1,3] 注入直驱 → 按注入值映射；② 否则 mobile → 按 tier 映射（3→2/2→1/1→0）；③ 非 mobile 且无注入 → **恒 2**（桌面/headless 零扰动）。A 包应用面仅 `enemy.gd:319-327`（`_fx_q` 与帽合成取小，默认档 headless 逐位零扰动）。

### 1.3 默认与即时生效

- **默认=帧率优先**：`perf_mode: 0` 入 SETTINGS_DEFAULTS（`meta_manager.gd:246`）+ `_normalized_setting` clampi(0,1) 双注册（`:296`）；旧档缺键回落默认 0（qa_r220_mode 域A 磁盘真档去键实测）——老玩家升级**无感知切换为帧率优先**，可感代价披露见姊妹报告 §1 与本文 §六。
- **即时生效（零推送零滞后）**：`frame_priority()` 每读直查设置（`perf_governor.gd:41-50`），设置行写口后**下一读即翻转**；模式切换由 `_process` 模式观测口轮询单源检测（`:91-100`，覆盖 settings 写口与 mode_override 两通道）→ 双侧转换计时清零重累计、**tier/EMA 保持**（防切换瞬间假触发）；刀12-14 消费点每物理步/每 spawn 直查 `frame_priority()`——切模式下一物理步即生效，无需重启。

### 1.4 工程刀双模生效（模式门总览）

按拆解契约 §2.1 行为7：**刀1-11 为工程刀，两种模式都生效、无模式分支**（含刀6 波首错帧——特效优先下波首全组齐射画面也不复原，见 §六披露）；**仅刀12/13/14 挂帧率优先门**（特效优先=无配额、旧值全保）。调速器升降档（§1.1）也按模式取阈值，特效优先地板更高（2）、降档更迟。

## 五、vc27 真机验证清单（出包归主控；本清单=日志回收后的判读法）

采日志：设置 → 记录日志 开（默认开），打完一局主菜单导出（文件名带 vc27）。1Hz 采样 × 环形 N 行（日志长度档，默认 240）。

**第 0 步·记录测试环境（必记，判据分母全靠它）**：测试机的 **fps_cap 设置值**（30/60/90/120/不限）、屏幕刷新率、优先模式档（帧率/特效）——**target = min(fps_cap, 120, 屏幕刷新率)**，不记 target 读数则 5.1/5.2 无从判。

**主判据（方案书 §2.3，恒适用）**：
1. **player_wp（日志段名「火」）峰值 < 30ms，深段无 >30ms 行**——刀5/6/7 合并验收门（基线 vc26 峰值 102ms 对齐帧）；刀12 配额咬合时 ≤20ms 为子判据（结构性上限推算，仅帧率优先+配额生效时适用）。
2. **弹段 ÷ 结N = 每命中 µs（首测定标）**：弹段ms × 1000 ÷ 结N。**vc27 是该口径的首测**（vc26 日志无 结N 差分与新弹段读数，无法直接对账）——首测值记下即为后轮回归基线；同会话可切「特效优先」打同载荷一局作 A/B 自比（方案书目标：单刀 ≥15%/刀组 ≥40%，待有基线后适用）。结N≈0 而弹段高 = 空转弹（远处敌弹），非命中链成本，勿误读。
3. **卡开子键（开N=card_open）< 30ms，目标 <15ms**；且 **fit_desc_measures 每开窗增量 ≤2**（刀2 验收口，`debug_stats.gd:36`）——普通开窗/双列/Reroll/连升级批均适用（连升批实测 0）。

**波动带读法（用户验收口径 10%/30%，姊妹报告 §2.2 同源）**：
4. **帧率优先**：稳态带允许波动 **±10%**——PLAYING 段 fps 分布 **P5 ≥ 0.90 × target**（深谷不破 −10%）、P50 ≥ 0.95 × target 视为达标。
5. **特效优先**：允许波动 **±30%**——**P5 ≥ 0.70 × target**；调速器可降至 2（地板 2，特效帽最多收到中档）。
6. fps 是 Engine 平滑值，与逐帧清零的段探针**窗口错位**，两者不可直接互除对账（日志头口径声明同句）；模N PLAYING 连续行 ≈ min(fps,60)±2，**跨窗行带 `*` 剔除不读**。

**调速器读数（调N/变N）**：
7. 调N=调速器档 1低/2中/3高；变N=真采样驱动累计档变数（>0 才出现）。帧率优先达标态：调N 稳 3、变N 基本不涨；**若变N 持续走高且调N 钉 1——先核对 target 是否高于设备可达**（fps_cap 设置/刷新率——修轮帽语义后一般不该再发生，再发生即新缺陷）。

**辅助计数口（DebugStats 通用通道，判读）**：
8. **quota 计数应近零**：`quota_dropped` 恒 0（或个位——队列帽 256 溢出才丢，丢弃=守恒破口）；`quota_deferred` 特效优先恒 0、帧率优先重载构筑（万镜/多武器齐射）下允许非零但应远小于生成总量（顺延是设计行为非丢失，守恒断言 r220_firephase ⑥D）；`trait_pool_discarded` 挂卡/质变后首批弹出现属正常、稳态归零；`mirror_budget_skipped` 帧率优先万镜流下可非 0（刀14 咬合证据）。
9. 自N=自导池在场数：**弹N 不含自导**，读总弹幕量用 弹N+自N。
