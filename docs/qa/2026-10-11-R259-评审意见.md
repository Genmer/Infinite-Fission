# R259 三面板行缓存 — 评审意见（2026-10-11）

评审对象：`scripts/meta/meta_manager.gd`（map_records_changed 信号+写点）、`scripts/ui/menu_screen.gd`（成就页缓存/选人全量签名/选关分档缓存/回收白名单）、`tests/qa_r259_panel_cache_cases.gd`。只读评审（未跑 Godot；grep+逐行读码）。

## 总评

刀法方向对路：写点覆盖经全仓 grep 核实**完整**（map_records 全部变更仅 `meta_manager.gd` 两区，均有 emit；选关失效口干净，`_invalidate_map_rows_cache` 连挂树行一并 detach+free）。但三缓存里成就/选人两个在「换血」路径上**漏了 free——覆盖旧缓存条目时旧行已 detach 且失去全部引用=孤儿行泄漏**，与 R254 修轮#2「页毕 ghosts free 防孤儿行」同型教训在新增缓存上复发；且选人 sig 漏了 `_sel_difficulty` 一项，与「行内全部动态输入入 sig」的自我承诺不符。最影响体验的一件事：选人面板每次选角色/买角色/点一次武器循环钮就漏整页约 13 棵行树，长会话菜单交互无上限累积。

## 问题清单

### HIGH-1 缓存覆盖不 free 旧行=孤儿行泄漏（成就+选人两处；选关无此问题）

- **位置**：`menu_screen.gd:1772`（`_ach_page_cache[_ach_page] = {...}` 覆盖）、`menu_screen.gd:1927`（`_char_rows_cache = {...}` 覆盖）。全文件 queue_free 盘点（:213/:529/:1082/:1097/:1109/:1131）无一处指向这两个缓存的被替换行。
- **机理**：sig 未命中→重建前 `_recycle_panel_rows()`(:1086) 已把旧行 detach（白名单名标只 detach 不 free），随后整键覆盖，旧 rows 数组随旧 dict 丢弃——Node 非 RefCounted，孤儿不释放，直到进程退出。项目自身先例佐证：`_invalidate_map_rows_cache` :1076-1083 与 `_invalidate_codex_cache` :1108-1131 都显式 free，唯二新缓存漏掉。
- **触发频率（真实交互）**：选人=每次选用/购买/点一次武器循环钮（:2021/:2026/:2026/:2036 → sig 变 → 整页重建）漏约 13 棵行树（行含按钮/图标/lambda）；武器钮连点是高频点击，20 连点≈260 棵孤儿树。成就=每次类别页签切换（`_on_ach_tab` :1663 恒回 page 0 → 恒覆盖键 0）+ done 位图翻转重建，每次最多漏 24 行。真机反馈本批关注点就是「对象数 925↔1551 跳变」，孤儿行不进场景树躲过诊断口径=静默泄漏。
- **建议**：miss 路径覆盖前对旧条目 rows 逐行 `is_instance_valid` + `queue_free`（旧行已被 recycle detach，直接 free 安全）；或抽一个 `_free_cached_rows(arr)` 供 ach/char 共用，与 map 失效口同款。

### MED-1 选人 sig 八项漏 `_sel_difficulty`——武器循环钮文本陈旧

- **位置**：sig 构造 `menu_screen.gd:1796-1798`（八项=character_id/unlock_bits/buy_bits/crystals/custom_weapon/codex_weapons.size/total_kills/best_endless_depth）；而 `_custom_weapon_label()` :1998-2009 在 :2007 读 `_sel_difficulty`（`MechanicGate.weapon_difficulty_min` 为静态常量表 mechanic_gate.gd:172-174，非 Meta 态）。
- **现象**：改造者·枢行武器钮文本「初始武器：X ▸」（含「（本档未开→手枪）」回落后缀）随所选难度变。复现流：选关面板切难度（`_on_difficulty_pick` :718 只重建选关行）→ 关面板 → 开选人——八项全未变 → 缓存命中直挂 → 钮文本仍是旧难度口径。这正是 R254-D1「漏失效口=显陈旧数据」同型，只是藏在「全量签名」承诺里（:1785 注释自称「行内全部动态输入入 sig」）。
- **建议**：sig 追加第九项 `_sel_difficulty`（一行改动；顺带把注释「八项」改「九项」）。其余七项经逐元素核对**全部覆盖**（✓/锁定 hint 各进度文本含结晶/无尽深度当前值、选用购买钮出现与 disabled、图鉴计数 label、技能图标 modulate、wcycle 文本+tooltip 均在 sig 内）。

### MED-2 成就页缓存键漏 `_ach_tab`——页签切换恒 miss+覆盖（叠加 HIGH-1 即恒泄漏），并存潜在串页

- **位置**：键=`menu_screen.gd:1717` `_ach_page_cache.get(_ach_page)`（仅页码）；sig :1713-1716 = 页码+全表 done 位图，位图遍历 `_ach_filtered()` :1648-1655 依赖 `_ach_tab` 但 tab 本身不入键。
- **现象 A（当下实发）**：四个页签列表长度 98/43/19/160，位图串长必不等 → 切页签必 miss → 整页重建 + 覆盖键 0（每次切=白建 24 行+漏 24 行）。缓存对「页签切换」这一成就面板主要操作完全无效，只剩同页签内翻页/重开受益。
- **现象 B（潜伏）**：若未来两页签列表等长且逐位 done 相同（数据漂移可致），sig 撞车 → 命中他签行=显示错误成就。现网不可达（长度不等），登记为潜伏缺陷。
- **建议**：缓存键改 `"%s|%d" % [_ach_tab, _ach_page]`，一并消 A（切页签变纯挂树）与 B（撞车归零）。HIGH-1 修复后此项泄漏面自动收窄为 done 翻转路径，但仍建议改键拿回切签性能收益。

### LOW-1 测试断言强度：13 项覆盖正面路径，未触本批两个真实风险面

- **位置**：`tests/qa_r259_panel_cache_cases.gd`。已覆盖：三面板复用同实例、desc 轻刷单源、sig 变重建（选中标记移动）、分档独立实例、失效挂树 detach+重开新实例、成就重开中位 <5ms 性能门——正面面扎实。
- **缺口**：①无成就页签切换用例（会暴露 MED-2 恒 miss 与 HIGH-1 覆盖泄漏）；②无武器循环/难度变化后重开选人用例（会暴露 MED-1 陈旧标签）；③无孤儿断言（如覆盖后 `is_instance_valid(old_row)==false`，可机检 HIGH-1）；④性能门只测成就，选人/选关命中路径未设门；⑤用例②换角色分支以 `swapped` 守卫——角色 1 未解锁的档位下退化为「同实例」弱断言（boot 夹具下大概率 swapped=false，实际弱跑）。
- **建议**：补三用例（切签缓存命中、循环钮后旧行 freed、难度变化后选人重建），HIGH/MED 修复时顺带。

### LOW-2 内存面：稳态驻留可接受，上限约 200 行树+图鉴五页先例

- 估算（驻留上限）：成就 ≤7 键（全部 160 条/24=7 页）×24 行≈168 行（每行 Panel+3 Label）；选人 13 行（行较重：图标+按钮+lambda）；选关 3 档×5 行=15 行。合计 ≈200 棵行树/约 700+ 节点常驻，量级与 R254 图鉴五页先例相当，可接受。HIGH-1 修复后无不可控项；若较真可给成就缓存加「切签时 free 他签页」小帽，非必需。

### LOW-3 性能面：命中路径剩余 3.5-4.4ms 构成与下批性价比

- 构成（读码推断，标注推测）：行重挂 `_panel_list.add_child` ×N 触发 VBox 重排（主体）+ 选关面板每次重建 DifficultyRow（约 7 节点，微量）+ `squash_pop` tween 创建（theme.gd:138-150）+ dim/card 显隐。桌面 <5ms 门已达标，真机 ×2-4≈7-17ms 贴近单帧预算但不再爆。
- **建议**：暂缓再压，待 vc66 真机复验收数据；若仍卡，首选「面板级容器交换」（每面板一个整页容器，切面板只挂/摘一个容器节点而非 N 行）与「squash_pop 只做 card 缩放不整卡重排」，属中成本刀。
