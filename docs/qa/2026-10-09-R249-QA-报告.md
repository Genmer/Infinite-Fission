## 4. 缺陷清单

### BUG-1〔medium〕跨局橙盾残留：回菜单再开新局，上局橙盾层原样带入（菜单期时钟冻结）

- 位置：`scripts/entities/player/player.gd` `respawn()`（:2351-2388）未清
  `temp_shield_stacks` / `temp_shield_left`；两字段唯一清零写点为 tick 归零（:593-596）与
  吸收到 0（:765-766）——而 `player.tick` 仅 PLAYING 态被 GameLoop 驱动（game_loop.gd :765
  ②段），MENU/GAME_OVER 期时钟冻结。
- 复现（自动化实跑，`_qa_r249_probe_blind.log` PB1 组）：
  1. `start_run()` 进 PLAYING；`EventBus.emit_mine_dodged` ×5 → `temp_shield_stacks==5`；
  2. `request_pause()`（PLAYING→PAUSED）→ `quit_to_menu()`（PAUSED→MENU，合法链）；
  3. MENU 停留 40 帧 → 层数仍 5、left 9.99 不衰减（冻结实证）；
  4. `start_run()` 开新局 → **`temp_shield_stacks==5`、`left≈9.99`**（PB1e FAIL）；
  5. `_reset_run_state` :3599 调 `hud.refresh_stats()` → **新局开局 HUD 橙条立即可见、读数
     「5·10s」**（PB1f FAIL）。
- 期望：`respawn()` 对比先例——蓝盾层 `shield_layers = 0`（:2370 注释「层数随局归零」）、
  `clear_crystal_shield()`（晶盾纯会话态随局清零）、`clear_revive_protect()` 全部随局收口；
  橙盾同为「纯会话态」（player.gd :822 注释自述）却漏网。同根因路径：GAME_OVER→PLAYING 重开
  （game_loop.gd :1782 `_reset_run_state`）与暂停「继续」（_restore_run_state 不写这两字段）。
- 实际：新局开局白送最多 5 次接触伤免伤 + HUD 陈旧显示；菜单/结算屏停留任意久都不衰减
  （时钟冻结），残留窗口=新局前 10s 全额。
- 影响评估：非崩溃、主流程可走、单机收益型泄漏（玩家占便宜而非吃亏）；但与同函数既有清零
  纪律直接矛盾、且「显示过期时间」读数在新局开局即失真——定 **medium**。
- 修复建议（供开发参考，QA 不动手）：`respawn()` 内补
  `temp_shield_stacks = 0` / `temp_shield_left = 0.0` 两行；注意**不要**走「入 RunSave 快照」
  方向（快照不含瞬态增益是既有口径，与本缺陷正交）。

## 5. 观察项（不计缺陷）

1. **无敌帧内被炸不发 dodge**：`_explode` 的 hit 判定按「玩家在 blast 半径内」而非「实际受伤」
   ——无敌帧/死亡态挡下的爆炸 hit=true 不授盾。代码注释（enemy.gd :3377）已明示
   「躲过=没被炸到这一路」为设计口径，语义自洽，不改不立缺陷。
2. **HUD 填充比例硬编码 10.0**（hud.gd :729 `t_left / 10.0`，注释自称「字面量同源
   Player.TEMP_SHIELD_TIME」）：当前无功能影响；若后续调 TEMP_SHIELD_TIME 需同步两处，
   建议改引常量（low 级维护性，未到缺陷门槛）。
3. **暂停回菜单的「继续」入口丢橙盾**：serialize_run 不含 temp_shield——瞬态增益不入档是
   既有口径（晶盾等同），且当前同会话「继续」因 BUG-1 反而内存残留；修 BUG-1 后两口径
   （重开清零 / 续档无橙盾）将自洽。
4. mine_dodged 走 `_track_dispatch` 风暴哨（阈值 128/帧）：boss 雷场一次至多 8 颗同帧引爆，
   远低于阈值，无风暴风险。
