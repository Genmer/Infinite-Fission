# R231 弹段结构化性能刀单（GDD-lite）

## 概述

本轮把模拟弹段 `grid_projectile` 的深载成本从 16.55ms（p50，PC headless）压到 **<5ms**：刀A 重构 SpaceGrid 读路径（微基准已证天花板 25.4→4.9µs/查询），刀B 把 R220 敌弹快路径先例复刻到玩家弹，刀C 为条件触发的残余瘦身。全部为纯优化刀（设计意图零玩家可感变化），行为等价是第一门禁。

- 双池驱动（`scripts/loop/game_loop.gd:2602`）：`_tick_projectiles` = `_projectile_pool`（直线池）+`_homing_pool`（追踪池）各走 `_tick_one_pool`：每帧分区（team1∧`_fast_path` 走快路径，其余含全部玩家弹走慢路径 `proj.tick` 虚调用）。

## ② 刀单定案

### 刀A 网格读路径结构化（必做，首发）

**一句话**：rebuild 期一次性建位置快照（typed 数组），热路径查询走快照+常量半径，删 `_radii` Dictionary 与逐候选 `_pos_of` 属性读；非 ④ 相位的查询点保持 live 读不动。

**改动点（开发可直接开工粒度）**

1. `space_grid.gd rebuild(p_items)`：一次遍历，先 `_pos_of(item)` 取位（**保留树外节点回退 `position` 的现有语义**）写入自有快照数组 `_snap_items: Array[Node2D]` 与 `_snap_pos: Array[Vector2]`（成员级复用，每帧覆写零分配——R188 红线）。**必须复制进自有数组，不得引用 `p_items` 做索引基**：④ 内击杀会 `active.erase`（O(n) 移位，非 swap-remove），外部数组索引会错位；自有快照数组在 rebuild 期定型、④ 内不重写，天然稳定。
2. 桶改存 **int 索引**（指向 `_snap_items`）：`_buckets: Array[Array]`（内层 Array[int]）。`_cell_index`/`_cells_in_range`/`_occupied` 纪戳机制全部不动。
3. 新增 `query_circle_snap(pos, radius) -> Array[Node2D]`：覆盖格 + 桶内索引直读 `_snap_pos` 做距离平方精判，半径用**只读口 `max_entity_radius()`**（不硬编码 64——Boss/大敌若 configure 传入更大保守半径，粗判超集天然成立），命中项从 `_snap_items[idx]` 解析 append 进复用 `_query_buffer`，返回契约与现网一致（内部缓冲，跨查询持有需复制——`_check_collision` 已有复制）。
4. **删 `_radii` Dictionary 全套**（字段/写入/clear/三查询里的 `.get`）：现网唯一 insert 调用点就是 `rebuild` 自身且恒传 `_max_entity_radius`（微基准 B 臂已证语义等价）；初查全仓无其他 `.insert(` 网格调用者（仅 Array.insert 局部用法），分析阶段复确认后落刀。`insert()`（波内补插口）保留，参数 radius 忽略或删参，同步 append 快照数组。
5. `query_circle`/`query_nearest`/`query_arc` **保留 live 读**（`_pos_of` 不动，半径改常量）：服务 ② 相位查询点（武器索敌 `weapon_base.gd:348`、玩家 `player.gd:1489`、近战 `arc_slash.gd:84/133`、激光 `laser_beam.gd:418/448`、环绕 `orbit_field.gd` 多处、homing 重索敌 `homing_projectile.gd:144`）与 ⑤ 相位点（elemental 连锁 `elemental_system.gd` 多处、敌间分离 `game_loop.gd:3024`）。这些点查询的网格本就是上一帧重建，现网语义=「桶按旧位、距离按 live 新位」；全快照化会引入一帧滞后的命中/索敌差异（近战消弹可能清掉已飞出扇形的弹、索敌瞄旧位），本轮**不动**。
6. `projectile_base._check_collision`（:437）切 `query_circle_snap`；**`_in_reach` 窄相不动（继续 live 读 `target.global_position`+`Enemy.hitbox_r`）**——理由见等价论证。
7. `enemy_bullet_grid` 同实例共享改动：rebuild 统一建快照（多 ~200 件写入，微不足道，避免分叉）；其消费点（`arc_slash` 消弹 `query_arc`）走 live 旧口径，行为不变。

**预期收益**：查询 25.4→~4.9µs（−81%），段 p50 16.55→≈7.9ms；顺带 `query_nearest/query_arc` 免 Dictionary 哈希（②段武器索敌受益，量级小不单列验收）。

**行为等价论证**

- ④ 相位（本刀主战场）：rebuild 与弹 pass 之间敌人不 tick（⑤ 在后），**活敌 live 位 ≡ 快照位**，粗判结果逐位一致。
- 活敌位变仅两源，逐一处置：
  - **死亡-回池**：击杀 → `spawner.on_enemy_killed` → `active.erase` + `pool.release`（`object_pool.gd:79` `bucket_host.unplace` 归位池根，可能改 global_position）。现网行为：该敌桶成员资格按旧位、live 距离按新位 → 后续弹 live 粗判排除。快照行为：粗判可能仍命中（旧位在 reach 内）→ 但 `_in_reach` **live 读**新位 → 排除 → `_submit_hit` 不被调用 → **最终命中结果与现网一致**，仅多一次窄相读。这是把窄相留在 live 的核心收益：候选粗判允许超集，最终裁定口径不变。
  - **击退即时位移（待分析销账 AC 项）**：`projectile_base.gd:692` 在 ④ 内结算时调 `Enemy.knockback(...)`。若 knockback 是速度型（位置在 ⑤ tick 变），论证闭合；若是即时位移型，后续弹的快照粗判与现网 live 粗判可能出现双向差（快照 miss/live hit 的漏击方向）——处置：等价测试加击退场景锁定差异幅度，超过 1px 级再议（兜底方案：粗判 reach 加击退安全余量常量，方向保守只增候选不漏）。
- ②/⑤ 相位查询点：方法与读口径均未改（仅 `_radii`→常量，B 臂已证等价），逐位不变。
- E-03 帧聚合/穿透/回收原因/伤害结算链/词条派发：全在 `_submit_hit` 以后，本刀不触碰。

**风险与回退**：单文件+单调用点切换，回退=恢复 `_radii` 版本（建议刀A 单独一提交，回退粒度独立）。最大风险是快照数组生命周期错位（④ 内 erase 已用自有复制规避）；测试 T5 专项覆盖。

### 刀B 玩家弹快路径（必做，次发，R220 先例复刻到 team0）

**一句话**：无 boomerang/无反弹/无收束/无 ON_TICK 钩/非 LTG/直线池的简单玩家弹走内联快路径（运动+寿命+出界+快照接触预检），**接触时回落慢路径 `_check_collision`**——伤害/词条/穿透链一行不动。

**资格判据（spawn 期缓存 `_pfast` 布尔，逐项 no-op 证据表 + ⚠PR 检查单，方法论沿用 R220）**

```
team == 0
且 属 _projectile_pool（直线池——homing 池排除，_move 被覆写有转向/重索敌）
且 bounces_left == 0（_check_edge_bounce 四边计算后无分支命中）
且 not _boomerang（回旋运动/ICD 扫不可达）
且 _conv_gap == 0.0（_apply_converge_steer 首行守卫直返）
且 element != LTG（电花自旋纯表现）
且 _tick_dispatch_armed == false（R225 armed 快照同口径：栈无 ON_TICK 钩 →
   ON_TICK 闸本就直通且 payload 字典不分配；同时锁定 size_mult/变体生命周期不变——
   半径可快照 _fast_radius）
且 trait_stack is TraitStack 或 _traits_cache 为空（直挂数组通道=测试桩，一律慢路径，
   保 live 注入可见性——R225 qa_r220_simchain ③a 先例）
且 Ballistic 无 accel/range 键（运动退化匀速直线）
```

注意与 R220 敌弹判据的差异：敌弹要求「无词条」，玩家弹**允许带 TraitStack**（深载构筑弹弹 12 词条栈，一刀切无词条会让探针场景零收益），安全性由 `_tick_dispatch_armed==false` 承担——无 ON_TICK 钩即无飞行中改写面（ON_HIT/ON_KILL 都发生在回落段的提交链内）。**前置条件**：分析阶段须复核「size_mult 与 sprite 变体在 spawn 后无非 spawn 期写者」（全仓 grep 写点清零）；复核不过则资格收紧回「无词条」档并重估收益。

**改动点**

1. `projectile_base.gd` spawn 期算 `_pfast`（紧邻现网 `_fast_path` 判据，:245 一带）+ `_fast_radius = effective_radius()` 快照（复用现网 :250）。
2. `game_loop._tick_one_pool` 分区扩为三缓冲：`_proj_slow_buf`（慢路径）/`_proj_efast_buf`（敌弹快路径）/`_proj_pfast_buf`（玩家弹快路径）。驱动序：组内倒序保持，跨组先后无交互论证沿用现网注释并扩写（玩家弹只查敌网格不撞玩家、敌弹不查敌网格）。
3. 新增 `ProjectileBase._tick_fast_player(p_gd)`，分支序保持慢路径原序：
   `if not _live: return` → `hits_this_frame.clear()`（**保留**——玩家弹是 E-03 消费者，与敌弹不同）→ 寿命（EXPIRED 回收）→ 内联直线运动 `global_position += velocity * p_gd`（每步仍驱动，不引入 2δ 隧穿）→ 出界（`_fast_radius + OFFSCREEN_MARGIN`，EXPIRED 口径同 `_check_offscreen`——等价性依赖上面的半径快照前置条件）→ **接触预检**：`query_circle_snap(global_position, _fast_radius)` 非空即回落 `_check_collision()`（完整重查+候选复制+live 窄相+`_submit_hit` 链，本刀零改动）。
4. 预检超集论证：粗判 reach = `_fast_radius + grid.max_entity_radius()` ≥ 真实窄相 reach（保守半径是 hitbox_r 上界）→ **零漏击**；误触发（死亡-回池敌快照位仍在 reach 内）只多付一次回落，回落段 live 窄相正确排除。回收统一 `_recycle`，原因逐位一致（EXPIRED 两处；命中耗尽的 PIERCE_DEPLETED 在回落段内由现网逻辑产生）。

**预期收益**：慢路径逐弹开销（虚调用链+守卫+四边反弹计算+视觉量化+ON_TICK 闸+无接触帧的候选复制）估 −1.5~2.5ms @420 弹（待实测）；接触帧因预检+回落双查略亏，深载命中密度下摊薄。

**风险与回退**：资格判据漏项=行为回归主风险，靠矩阵测试 T8 + ⚠PR 检查单（新玩家弹 spawn 点必须过判据评审——`player.gd:1511` 直发弹、ballistic/homing 武器侧 acquire 全量清单由分析给出）。回退=分区开关常量置 false（沿用 `ENEMY_BULLET_FAST_PATH` 先例加 `PLAYER_BULLET_FAST_PATH`）。

### 刀C 分区循环与慢路径小项瘦身（条件刀，默认不做）

**触发条件（写死，防范围蔓延）**：刀A+刀B 落地并探针复测后，任一情景 grid_projectile p50 仍 ≥5.0ms 才启用；否则本刀不开工。

**候选改动点**（届时按探针残余分布挑 1-2 项，不整包）：
- `_tick_one_pool` 每帧 O(n) 三分区与驱动合并单趟（分类即入队即驱动，减一次缓冲遍历与 `is_instance_valid` 重复判）；
- 慢路径小项：`_check_edge_bounce` 无反弹早退（`bounces_left==0` 直返，省四边 normal 计算——注意弹道覆写内还有双调幂等点，早退须两处同口径）、`_sync_visual` 早退旗标（spawn 期算好「半径/变体生命周期不变」布尔）、`effective_radius()` 在 tick 内多次调用的结果复用。

**等价论证与回退**：全部为「计算后不命中分支」的搬运，no-op 证据表逐条列头注；早退旗标与刀B 资格判据同源同证。回退=逐项独立开关或整刀 revert。

### 刀序与门禁

A → 探针复测 → B → 探针复测 →（条件）C → 探针复测收口。每刀独立提交、独立可回退；A 的收益是 B 预检的地板（B 依赖 `query_circle_snap` 存在），顺序不可倒。
