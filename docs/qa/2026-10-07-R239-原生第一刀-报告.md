## 2. 桥接设计（要点）

**数据面（GDScript → C++ 单向喂入，一次喂入多次查询）：**

1. SpaceGrid 在 `rebuild()/insert()` 期同步维护**原生镜像**两数组（仅 `_native_on` 实例）：
   - `_nat_cells: PackedInt32Array`——插入序 cell 索引（`_cell_index` 现成产物，零重算）；
   - `_nat_pos: PackedVector2Array`——插入序位置（与 `_snap_pos` 逐位同值）。
2. **惰性冲刷**：`_nat_dirty` 置位（rebuild/补插），首次原生查询时一次 `feed_snapshot(_snap_items, _nat_cells, _nat_pos)`——C++ 侧建 CSR（计数→前缀和→按插入序散布），此后多次查询零重建。无 snap 查询的帧零喂入成本。
3. `_snap_items` 以 **引擎 Array COW 共享**传入（非拷贝）：GDScript 侧后续 clear/append 不影响 C++ 持有的旧快照（引擎容器语义），脏标记保证查询前必然重喂——无悬垂面；`④` 相位内击杀链对快照的强引用语义与 R231 刀A 现状一致。

**查询面（C++ 直返，零逐命中 GDScript 解析）：**

4. `query_circle_snap_nodes(pos, radius) -> Array[Node2D]`：C++ 扫描（id 暂存 std::vector，容量复用）→ 结果一次性落**成员类型化缓冲**（`set_typed(OBJECT,"Node2D")`）→ COW 共享直返。GDScript wrapper 一行转返——`SpaceGrid.query_circle_snap` 返回值契约不变（内部复用缓冲，跨查询持有须复制；`_query_buffer` 在原生路径不参与）。
5. `query_circle_snap_ids` 诊断口保留（同源同序，返回快照索引）。
6. **逐位等价口径**（等价性测试实证）：
   - `reach = maxf(radius,0)+max_entity_radius` 全 double 域——实测锚：GDScript `maxf` 为 double 原生无 float32 往返；radius 参数绑定为 double（Variant FLOAT 原样透传）；
   - 覆盖格与 `_cells_in_range` 同式同序：`((pos.x ± reach) − origin.x)/128.0` double 域 → 向零截断（GDScript `int()` 语义）→ clampi（min>max 时 max 胜出）→ 行主序；
   - 距离精判 = `Vector2.distance_squared_to` 同式 `(sx−px)²+(sy−py)²` **float32** 域（SConstruct `-ffp-contract=off` 禁 FMA 收缩），升 double 与 reach_sq 比较；
   - 候选序 = 格行主序 × 桶内插入序（CSR 散布序天然=插入序）= GDScript 双循环序——返回序逐位一致。

**成本披露**（JSON bridge 段）：镜像随建 ≈ +42µs/rebuild（120 实体，rebuild off=449µs vs on=491µs，含冷启动噪声）；feed CSR 建桥 ≈ 67µs（每 rebuild 一次，首查时）；查询稳态零分配（结果缓冲容量复用）。

## 3. 开关门实现

```gdscript
static var NATIVE_QUERIES: bool = false          # 默认关=零扰动
static func native_available() -> bool           # ClassDB.class_exists + can_instantiate（判定缓存）
```
- 判定在 `configure()` **实例定型**（实例生存期内不翻转——镜像与桶序一致性依赖 rebuild/insert 期同步构建）；扩展缺失/加载失败 → `_native_obj` 恒 null、`_native_on` 恒 false，全路径自动回落 GDScript（T1.5 白盒注入 `_native_state=0` 实证回退分支）。
- 加载机制按工具链文档 §5：`.gdextension`（`repo/native/fission_space_grid.gdextension`，entry `fission_space_grid_library_init`，compat 4.3）→ 编辑器扫描 → `.godot/extension_list.cfg`（已实证生成）。**新环境/CI 首跑前必须过一次编辑器扫描**，否则静默不加载（门开也自动回落，不崩）。
- .gdextension 注册了 windows debug/template_debug/release/template_release + android template_debug 五键；android.release 键未注册（本轮只编译验证 .so，真机出包轮随 gradle 链补）——缺失键的安全面=导出后 native_available()=false 自动回落。

## 4. A/B 基准（数字全录 JSON）

夹具：生产 configure（720×1280+192 margin→9×13 格，max_entity_radius=64）、敌 120 深载驻场（vc42 口径，5 簇确定性聚簇）、4000 查询/轮×5 轮取中位、半径四档轮转 6→22.5px（60Hz 点判定→30Hz swept 带）、轮内臂序交替抵消漂移。

|---|---|---|---|

## 6. 过程坑（后来者直接抄）

1. **C++ 空结果也必须返回类型化缓冲**：返回裸 `Array()` 会让 `SpaceGrid.query_circle_snap` 的 typed return 对**每次空查询**抛 SCRIPT ERROR（I/O 计入耗时 → on 臂读数恶化三个数量级）——空路径 `resize(0)+return 成员缓冲` 修复。锚：`probe_r239_native.json` 前次读数与本次对比。
2. **set_typed 后 resize 保型、operator= 会清型**：类型化成员缓冲只在 configure（空+未共享）设型一次，后续仅 resize/写值。
3. **本轮引入并已修复的自伤**：一次编辑误删非空路径 `resize(m)` 导致 OOB 写 segfault（`_crash_diag.log` 已删）；最小复现探针定位后修复——教训：**直返缓冲的 fill 前必须 resize 到精确尺寸**（等价性套件 T1.7/T2.4 已把"空/非空返回类型化"纳入回归面防复发）。

## 7. 风险与下一步

- **风险①（架构）**：原生路径下 `_query_buffer` 不参与——返回的是 C++ 成员缓冲（契约同构：内部缓冲+调用方复制），调用方 `_check_collision` 现有 `append_array` 复制语义天然兼容；嵌套查询 hazard 与现口径一致（首个消费者即复制）。
- **风险②（真机）**：桌面 3.75× 为 MinGW x86_64 读数；ARM 侧 `-ffp-contract=off` 已钉收缩口径，但引擎 GDScript 侧 arm64 的 float32 收缩行为未对拍——**等价性真机对拍（固定种子 A/B 逐位）随下轮出包执行**，不等即按 R238 Plan B 双轨回退（门关）。
- **风险③（电池）**：`test_r239_native.gd` 已入电池 glob（test_ 前缀）——它要求 dll 在位+编辑器扫描过；缺载时套件 FAIL（报红不跳过，属预期门禁）。默认关态下其余 120 套件行为零扰动（本日 R231/r233 双套件实证）。
- **下一步（不在本刀范围）**：①真机 A/B+电池全量（主控出包轮）；②查询结果 id 化喂给 R240 词条命中链（本刀的 CSR/id 面已预留）；③rebuild 镜像随建成本若真机超预期，改惰性重算或 C++ 侧直接吃 `_cell_index` 产物。
