# R234 探索：overkill 封顶（需求侧砍半刀）定量分析与方案设计

日期：2026-10-06｜探针：`tests/probe_r234_overkill.gd` + `tests/probe_r234_overkill_cases.gd`｜留档：`docs/qa/probe_r234_overkill_baseline.json`（S0/S0hp015/S1_ref 全参数入 meta；S2_ref 见 run2 log——run3 命令超时截断于 S2 驱动中，S2 读数以 run2 完整跑为准，两跑 S0 口径一致性见 §1.4）

## 0. 摘要（一句话）

**任务前提被实证否定、但更好的替代路径被实测证实**：「一发够杀、后续 N 发白算」的同帧白打在当前架构下已经是 **0.0%**（E-06 死亡短路当帧同步传播，早已在提交前拦截）——可砍的不是白打，而是**同帧同目标的重复磨血发**：39% 的命中落在多发组（组均 2.46 发），**提交前同帧同目标聚合（A 案）实测可砍需求 −59%**，且与 R223 顺延合并机制完全同构（DPS 期望守恒可证），深载真机需求 4500-5500/s → ~1840-2480/s，**低于 60Hz tier2 帽 2880/s → 弃N 归零、顺N 归零，R223 的「诚实丢弃」形态直接闭合**。

## 2. 任务前提的实证判决（如实）

任务书假设：「深载命中需求 4500-5500/s，其中大量命中打在将死敌人身上（一发够杀，后续 N 发白算）」。**两项实证均否定**：

1. **一发够杀占比仅 3.2-6.3%**（①a）：深载是「~30 发磨死一个」的形态（发/击杀 29.4），不是秒杀形态。
2. **同帧白打 = 0.0%**（③）：第一发致死的瞬间 `apply_damage → _on_died` **同步置 `dead=true`**（enemy.gd:798-806），同帧后续命中在**提交之前**就被死亡短路拦下（弹侧 `projectile_base.gd:703-705`、AoE 侧 `weapon_base.gd:312`）——不占结算预算、不占幂等缓存。**架构早已把「白打」消灭在需求形成之前**。账本自洽（dead_groups==lethal_a 逐位相等）排除观测口径漏洞。

**替代发现**（②）：39.1% 的命中落在同帧同目标多发组（组均 2.46 发、max 51——死亡新星 AoE 帧内突发是 5+ 组主源，与 R223 注释「settle_aoe 级联帧内突发 200-400 结算」互证）。这些命中**不是白打**（每发都在真实磨血），但**N 发可以合并为 1 次结算**——这就是需求侧的实测降幅空间：**1 − 组数/命中数 = 1 − 19.3/47.5 = −59.4%**（S0）／−55.1%（S0hp015）。

## 3. 方案空间（全部在 R223 DPS 守恒语义内设计）

### A 案：提交前同帧同目标聚合（推荐）

**机制**：帧内同一 `target_uid` 的第 2..N 发提交，`base_atk`/`flat_bonus` 累加进首发的聚合项，帧末（或首发即时段）一次真结算。

- **实现变体 A2（推荐）**：不写新聚合表——**把帧内同对第二发直接并入现成的 R223 顺延合并路径**（`_defer_settle` 的同对累积分支，damage_pipeline.gd:441-472：base/flat 累加、袋池、FIFO、冲刷、硬帽、过期强冲全套复用），并在 `end_frame` 帧末维护处把「本帧内聚合项」强制冲刷（新增一个帧内聚合标志位，区别于超帽顺延——或者更简单：聚合项入队即记 `frame=当前帧`，帧末维护的过期强冲天然覆盖）。伤害落地时序后移 ≤1 帧（16.7ms@60Hz，R223 过期窗 12 帧先例内）。
- **实现变体 A1**（独立帧聚合表，不推荐）：`_frame_agg: Dictionary` 每帧聚合、dispatch 前统一结算——新代码路径无先例，袋池/冲刷/去重三套语义要重写，改动面大 2-3 倍。

**需求降幅（实测推）**：−59%（S0）/−55%（S0hp015）。真机深载 4500-5500/s → **~1840-2480/s**；S2 饱和态 6122/s → ~2500/s（且正反馈切断后弹带回落，实际更低）。

**伤害语义变化**：
- **DPS 守恒**：`E[(Σd)×C] = Σd × E[C]`——与 R223 顺延合并的期望论证**同一条**（一次掷骰 E[Σ]=Σ×E[单发]，damage_pipeline.gd:337-339 原注释）。合并组同源同武器，乘区/词条参数同参（`_defer_settle` 注释 :443-444 已论证「同对同源，逐命中本就同参」）。
- **暴击**：N 发 N 次独立 roll → 1 次 roll 作用于总和。期望不变；**方差增大**（全有/全无）。实测暴击率 4.4%，深载组均 2.46——跳字视觉上「大暴击」频率略变。**处理**：如实披露为期望守恒内的方差重排；若要逐发暴击保真可在合并时按概率加权（`crit_mult` 期望折算进 base），但会失去暴击跳字二元性——不推荐，A2 原样一次 roll 即可。
- **序数条件词条**（HIT_AFTER_PIERCE 等）：合并取首发的 `pierce_index`/`bounce_count` 判定一次，后发弹的序数差异并入 base 和——**R223 顺延合并已是同一处理**（顺延不保留逐发 ctx 差异），先例成立。深构筑五词条无此类条件，风险敞口=通用性披露。
- **元素附着**：附着以结算为载体，合并后附着频次 −59% → 元素反应覆盖率下降（深构筑感0 无元素；构筑带元素时附着冷却机制本身限频，实际影响小于线性——需 A 案落地时用 r22x 元素套件回归）。
- **跳字/派发**：条目 N→1——popup 轴与派发轴（DISPATCH 帽 48、派deferred）负载同降 59%，**附带收益**（vc38 派deferred 峰 50028/s、dispatch stale_drop 5391/30s 均随之消失）。
- **与 E-03 帧聚合（现有去重）的关系（任务书点名写清）**：E-03（`projectile_base.gd:685-687` `hits_this_frame`）是**单弹级**帧去重——同一发弹一帧只打同一目标一次；管线幂等键 `(source_uid=弹uid, target_uid, frame)`（damage_pipeline.gd:914-919）是**同弹同帧**去重。**两者都不跨弹**——不同弹同帧打同一目标仍是 N 条独立提交，这正是 39% 多发组的来源。A 案补的正是这一层：**跨弹、同帧、同目标**的合并。三层关系：E-03（弹内）→ 幂等（弹×帧）→ A 聚合（目标×帧）——A 落在管线 resolve 入口（幂等检查之后、预算闸之前或直接走顺延分支），与 E-03/幂等零冲突（聚合项本身也是「去重后的独立提交」口径）。

**等价性风险**：低-中。期望守恒可证 + R223 同构先例 + 回滚开关（聚合分支关闭=现状一键回退）。两处披露（序数条件词条按首发、元素附着频次）。

**改动面**：damage_pipeline.gd（resolve 入口聚合判定 + 帧末冲刷挂钩）~60-120 行；r223 系测试套扩展（聚合语义 + 守恒断言 + 同参性）~4-6 用例；探针/基线口径更新。**不碰** enemy/weapon/projectile 产品路径（纯管线内刀）。

### B 案：hp 钳制预筛（提交前拦截将死目标的「第二发起」）——**否决**

- **实证否定**：可拦截对象不存在——③ 白打 0.0%（同帧首杀后多发本就被死亡短路拦截在提交前）。B 案的「目标剩余 hp 不足以吃下第二发时提前拦截」针对的正是这批命中。
- **仅存形态破红线**：若把口径改成「预期判死」（首发未结算时按预期伤害预判死亡、拦截后发），则首发被预算丢弃/掷骰未暴时后发已拦——**主动丢弃可能有效的伤害 = R223 DPS 守恒红线被破**（弃N 是「诚实卸载」，预判拦截是「语义违规」）。
- 结论：**B 案无实证支撑 + 守恒风险，弃**。

### C 案：结算预算单位重定义（帽从「每命中」改为「每目标每帧」）——**并入 A 的验收口径，不单独立案**

A 的预算侧对偶：聚合落地后结N 天然=组数，帽 48/96 语义自动变为「每帧目标数」上限——等效扩容 2.46× 而无需改任何帽常量。单独做 C（不聚合、只改帽口径）等于把超帽命中按目标折叠顺延——本质还是聚合，但丢失 R223 合并路径的成套机制，无增量价值。**作为 A 的验收读数口径**（结N/组N 对账）写入测试套即可。

## 4. 推荐案与落点预估

**推荐 A2**（借 R223 顺延合并路径实现帧内同目标聚合）：改动面最小、机制同构先例、回滚开关天然、DPS 守恒论证复用。

### 深载每步落点（真机 vc37/vc38 口径，纸面推算——标注：以下全部为「实测降幅 × 已留档单结成本」的推算，非直测）

| 轴 | 现状（深载） | A2 后 | 依据 |
|---|---|---|---|
| 结算轴（resolve+冲刷） | 8-10ms | **~3.3-4.1ms** | 条数 −59%（结N 47.5-102/步 → 19-42/步）× 单结 44.65µs（R232 已到底）；单结成本微升（合并 base 大、九步不变）取保守 |
| 顺延队列维护（帧末维护/袋池/过期扫描） | 含在长尾 ~17-19ms 内（S2 顺 47.4/步） | **~0**（顺N 归零——需求 2500/s < 帽 2880/s） | S2 参照轴推 |
| 派发/跳字轴（DISPATCH 帽顺延+stale drop+popup） | 他段含尖峰（vc38 派deferred 峰 50028/s） | 条目 −59% → 派deferred/stale_drop 归零，估 **−1-2ms** | 条目数等比 |
| 弹段（tick/碰撞） | 25-35ms | **基本不动**（敌死时点帧内不变、弹带正反馈切断后小幅回落，估 −0-3ms——不强主张） | 无直测依据，如实 |
| **每步合计** | 41-71ms | **~32-62ms（−9±3ms）** | 上四行加总 |

**诚实结论：单刀不达 16.6ms 预算**——overkill 封顶是需求侧第一刀（砍 −59% 提交 + 闭合弃N 守恒链），弹段 25-35ms 的结构性大头仍需 R235/R236（池化/原生路线）跟进。本刀的核心价值排序：①**弃N 400-1550/s 归零**（真伤害卸载形态消失——R223 红线从「设计内卸载」升格为「真守恒」）；②结算轴 −5-6ms；③派发/跳字轴减压为后续刀腾余量。

## 6. 风险清单

1. **等价性**：暴击方差重排（期望不变）、序数条件词条按首发判定（R223 先例）、元素附着频次 −59%（深构筑零暴露，通用构筑需 r22x 套件回归）。
2. **工具链**：A2 借 `_defer_settle` 路径需区分「超帽顺延」（下帧冲刷）与「帧内聚合」（帧末冲刷）两个冲刷时点——冲刷点错置会把聚合伤害推迟一帧落地（体感 16.7ms，R223 12 帧窗内可容但应精确到当帧）。
3. **回退**：聚合分支静态开关（REUSE_MODIFIER_STACK 先例），关闭=现状逐位回归（r223/r232 全套电池作证）。
4. **观测**：结µs/结N 判读口径不变（聚合后结N=组数）——vc39 真机对账时注意「结贴帽」判据的语义自动切换为「目标数贴帽」。
