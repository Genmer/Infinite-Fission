### 契约迁移忠实性复核（P2c2 / P4b）

- **P2c2**：驱动序列与上轮缺陷形态逐位一致（帽1 真结 ea → eb 顺延 → end_frame → release → 池 LIFO 同节点取回 → spawn 新身份 → 次帧头冲刷）。判别器由「幻影伤害实锤（Δhp=−10 · settle_flush+1）」翻转为「Δhp=0 + settle_flush_reuse+1 + 8401 零幻影事件派发」。**未弱化**：三条断言在修前代码下全部必 FAIL（Δhp、复用计数、派发面三向钉死），且新增事件消费面断言（上轮缺陷实际结果中「死锚派发」波及面的直接回归）——覆盖面加强。
- **P4b**：驱动序列未动（ctxX 真结算 → ry 顺延 → 同键 ry2 → 门关冲刷）。判别器由「base 翻倍（冲刷 −30）」翻转为「ry2==ry 同一占位实例 + FIFO 仍 1 + 冲刷单次落账 −20」。修前代码下 ry2 必为新占位实例且 Δhp=−30，三断言全 FAIL——忠实反转。开发套件③同步验证跨帧同对（幂等缓存逐帧清空后）仍走累积合并，QA-2 修复未伤设计合并语义。

无新缺陷。探针首跑（qa_r223_retest_edge_run1.log）出现 2 处 FAIL，经查均为**探针自身表述错误**而非被测代码缺陷，已修正探针后复跑全绿：① E2c 误将「复用重生节点满血」与「旧体归还将前血量」相比（重生后血量重置本就满血，帽内真结算落账改以归还前快照断言）；② E4 误以两次拉取值相减为期望（diag 值本身即自上次拉取的差分——boot 期调试行可能已立基线，改为直接断言 pull1/pull2 值；修正后 pull0 原始值与全程账目交叉核对逐位吻合，反而成为差分正确性的独立证据）。

### 观察项（不计缺陷）

1. `_flush_entry` 以 `var t: Enemy = ctx.target` 强类型收窄（damage_pipeline.gd:415）：若测试桩以非 Enemy 目标走顺延冲刷将运行时报错。生产四路调用方（settle_aoe/projectile/laser/orbit）目标恒为 Enemy，全部在库套件亦然（电池 96 套件绿）——仅测试桩形态的理论收窄，与既有 `_target_alive`/`_apply_to_target` 的鸭子类型兜底路径并存。如后续引入非 Enemy 目标桩需注意。
2. 战斗门控下泄漏 resolve 的语义依门态分流：cap>0（真机 tier1/2）→ 顺延挂起到恢复战斗（E3 实证）；cap=0（headless/桌面门关）→ 泄漏命中即时真结算（无预算闸可走）。game_loop 固定帧序中全部结算调用方均在 PLAYING 分支内（代码核读），生产不可达；该刀目标形态即真机 cap>0，语义正确。
