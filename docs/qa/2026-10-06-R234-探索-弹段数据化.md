## 一、结论（RouteProbe 摘要）

**条件可行——系数实证成立，但外推证伪。**

1. **系数实证（本日实测）**：属性轴 A/B=**12.1×**；快路径弹运动核「现状方法调用形态 → typed 数组批处理」E/F=**4.3×**（落在任务假设 2-4× 带内偏上）。假设的系数是真的。
2. **外推证伪（分解实测）**：运动学核只占每弹成本的极小份额——PC 口径快路径运动核 0.943µs/弹（E 臂）vs 深载每弹纯 tick 实测 64-73µs（R225 T0 TICK 臂，docs/qa/2026-10-05-R231-T0分离测量.log），**占比 ~1.4%**。弹段大头=慢路径词条弹的命中链（E-03/穿透表/ctx 构建/词条预聚合）+查询链+GDScript 分支机器——这些不随「位置/速度/寿命/穿透计数搬数组」消失。**「弹段整体 2-4×」不成立（桌面口径）。**
3. **真机不确定带（诚实披露）**：R210 前科=Variant/属性跨界在 ARM 代价放大 3-10×。若真机属性轴份额上移至 25-50%，路线收益随之放大——**PC 分解不能外判定案，需真机校准（Phase 0 门）**。
4. **达标判定（纸面推算，标注于 §六）**：全路线（数据化+查询链 typed 化+插值层遍历 typed 化+MultiMesh）合计砍深载每步约 **3-8ms（推算带）**：41-71ms → **34-63ms** → fps 16-30（预算 11-16.6ms 口径）。**单独实施不达标**；达标还须另砍长尾 17-19ms（物理服务器/敌 tick/spawner——本路线不覆盖）。
5. 建议：**R235 作为组合刀组件立项**（前置 Phase 0 真机校准门）；不建议按「弹段 2-4×」的原始假设单独立项。

## 三、弹段成本分解：可压缩面到底有多大（判路线的承重分析）

### 3.1 已有实测锚（全部本 repo 留档，本日复读核对）

| 真机弹段（vc37） | **25-35ms**；整步 41-71ms（模N 14-24） | 任务书给定 |

### 3.2 分解（PC 口径，实测+算术，无引用外部系数）

- 快路径运动核（E 形态工作）：0.943µs/弹 × ~400 弹 ≈ **0.38ms** —— 占弹段 14.4ms 的 **~2.6%**；占每弹成本 64-73µs 的 **~1.4%**。
- 查询链：~4.3µs/弹 × 400 ≈ **1.7ms**（~12%）。
- **其余 ~75-85% = 慢路径词条弹机器**：深载构筑（弹幕肉鸽定义上的词条构筑）大量弹带 BOUNCE/FRACTAL/NOVA 词条 → **不满足 pfast 判据（projectile_base.gd:324-329）走慢路径**；每命中付出 E-03/生命周期去重字典、ctx 22 字段构建、12 词条 collect_mult_pools+ON_HIT 派发、遗物注入、穿透簿记——这是 R225 TICK 臂 16.5ms 的主体，也是「弹段真正大头=查询链+结算链」结论（R231 报告 §三.3）的量化再现。
- 结算轴 8-10ms（真机）：R232 已到底，**本路线不触碰**（resolve 调用序/条数不变）。

### 3.3 推论（路线判定）

数据化「位置/速度/寿命/穿透计数」压缩的是 §3.2 第一项（PC ~0.38ms，真机按属性放大带 ×2-4 推 0.8-1.5ms）；捆绑查询链 typed 化（SpaceGrid `_snap_pos: Array[Vector2]`→PackedFloat32Array、桶迭代/距离判定数组化，PC ~1.7→~0.7ms 推算、真机 2-4ms）与插值层三遍历 typed 化（restore/snapshot/render_write 各 ~400 属性写/步+120 帧/s 渲染写，真机 1-2ms）后，**全路线合计 3-8ms（真机推算带）**。这是「条件可行」的量化内容：条件=捆绑三件+真机校准，单独=1-3ms 不达标。

## 五、等价性风险（逐位保持方案 vs 必变项）

### 5.1 可逐位保持（方案在位）

1. **命中序**：现序=慢组倒序→敌弹快组倒序→玩家快组倒序（game_loop.gd:2964-2991，跨组序慢/pfast 已披露偏移一次=R231 定案）。批循环按 slot 注册序（=acquire 序）**倒序遍历** = 现快组倒序驱动序逐位；跨组两次循环结构保持。R223 FIFO 按 (source,target) 对累积期望守恒（预算关 S0 全即时逐位；饱和帧位次同现网披露口径 ±10% 观察项）。
2. **回收原因**：五路径（EXPIRED/PIERCE_DEPLETED/BOUNCE_DEPLETED/NULLIFIED/FORCED）在批循环内按现判定序（寿命→range→出界→接触）同位触发；DebugStats 原因键查表（projectile_base.gd:160-163）保留。
3. **RNG 消费序**：弹 tick 无 RNG；命中链 RNG 全在 pipeline resolve（rng_stream_id per ctx）——resolve 调用序/条数不变 ⇒ 消费序逐位。
4. **E-03 帧聚合**：快路径弹 hits_this_frame 恒空（无命中回落时）；回落命中时由数组步内位图（PackedInt32Array per-slot bitset over enemy slots）代查——一帧一目标一条语义同。
5. **浮点截断点**：现网 `global_position += velocity * p_gd` = float32 存储→64 位乘加→写回截断 float32；数组版 `px[i] = px[i] + vx[i]*gd` 同截断点位（PackedFloat32Array 写回即截断）⇒ **逐位等价**。设计红线：批循环内禁止 64 位中间量跨步链式累积不落数组（traveled 每步写回=现网口径）。
6. **swept（_swept_prev）**：数据化下=步前数组值（免存语义，projectile_base.gd:129-135 注释口径「恒=上步末位」天然成立）；spawn 置位=出生位写数组。
7. **插值包络**：prev/curr 数组双缓冲；spawn prev=curr=出生位；slot 复用时 spawn 重置（release 不清——数组版同豁免语义，game_loop.gd:141-143 设计 3.4）。

### 5.2 必变项（影响面披露）

1. **对象 identity**：`ctx.kill_backlink = weakref(self)`（projectile_base.gd:833）依赖对象引用——快路径弹命中回落时仍经对象壳构建 ctx（壳保留，仅数据外移）⇒ 可保持；若后续彻底去壳须改 slot-id 回链（本路线不做）。
2. **词条弹不迁移**：TraitStack/派发链对象态保留（慢路径双轨并存）——架构复杂度上升，测试面 ×2（R231 双轨先例）。
3. **视觉同步粒度**：MultiMesh 帧末批量上传 vs 现逐 Sprite 变体解析——`_vis_invariant` 量化缩放/朝向跟踪（曳光/导弹）须在 MultiMesh transform/自定义数据通道重实现；回旋刃 `_draw` 拖尾（:1151-1163）留 Node2D 叠层（boomerang 弹不进 MultiMesh——量少披露）。
4. **池静载阀门**（R229 trim_free_to）：对象壳池保留裁闲语义；slot 数组容量固定 2000 不裁（静载 8×2000×4B≈64KB，可忽略）。
