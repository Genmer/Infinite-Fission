# R233 模拟 30Hz 解耦 + 渲染插值层 — 可行性分析

> 分析依据：设计稿 `docs/qa/2026-10-05-R233-模拟30Hz解耦-设计.md`（下称「设计」），
> 对照代码库逐处实读（本报告全部行号以实读为准）。Godot 4.3-stable / Android 120Hz / gl_compatibility。
> 主控裁剪遵循：必做保 AC-1（fps 稳定性）/AC-2（弃N 兑现）两硬验收；打磨类列可选；
> 渲染轴独立上限 = vc38 真机观察项不阻塞；性能结论只认留档 JSON、当日同进程复测、
> 证伪实验专用隔离配对探针。

## 结论 — **修改后放行**

方案A（Engine.physics_ticks_per_second=30）的影响面闭合判断**成立**：全仓唯一
`_physics_process` 消费者确在 game_loop.gd:419，零物理帧 Timer/await/Tween 依赖属实，
headless 电池零扰动路径属实（meta_manager.gd:513 mobile 门早退）。但分析发现**4 处
设计未覆盖的必改点**（第四处半频相位、DISPATCH_FRAME_CAP 派发瓶颈、swept prev 源
规格错误、插值 false 分支写策略）和 **1 个门禁级预算算术风险**（cap192 下结算轴+
弹段已吃掉 18-29ms，长尾容忍余量 4-15ms，而「Area2D 半频省一半」的参照系是 60Hz
理想态——现状深载物理服务器实际已跑 14-25Hz 有效率，对折参照不存在）。预算风险有
廉价的先测手段（结µs 修复 + 步长 A/B 配对探针），不构成打回理由，但**探针结果必须
先于帽值定稿**。放行条件 = 本报告「给策划的修改意见」5 条全部落实。

账目确认（一句）：R232 报告 §五预留的 R233=ctx typed 已按主控裁定改道 R234+ 与
overkill 封顶合并排期，本刀不背该账，其动机（FULL 盲区 35%/袋重建 4.1µs）未被消解。

### Q2 30Hz 长尾等比性 — A/B 配对探针方案 + 一个设计未言明的预算硬约束

**先给算术（比设计更紧）**：设计 33ms 管线拆分 = 结算轴 8-10 + 弹段 7-10 + 长尾
17-19，是在**帽96、结算 ~96/步**的现状下测的。30Hz+cap192 且典型需求 4500-5500/s
（=150-183 结/步）时，仅结算轴就变为 **150-183 × 58-99µs ≈ 8.7-18.1ms**；弹段/
敌段是每步成本不随 dt 缩（同活口数同调用数）。于是：

```
步预算 33.3ms ≥ 结算轴(8.7-18.1) + 弹段(7-10) + 敌/网/其他(~6-9) + 引擎侧
→ 长尾+引擎侧容忍上限 ≈ 0-12ms（最坏组合下为负）
```

而设计「物理服务器同步降 30Hz：Area2D 成本减半」的参照系是 60Hz 理想态——**现状
深载在帽1 下物理服务器实际已随 fps 跑 14-25Hz**，30Hz 固定后引擎侧物理成本相对
现状深谷**不降反微升**（30 > 25）。即：对折收益的账对象不存在，预算等式最坏不成立。

**A/B 探针定案**（专用隔离配对，R232 纪律：只对同轮同进程）：
- 文件：`tests/probe_r233_stepsize.gd` + `probe_r233_stepsize_cases.gd`（probe_r224_deepload
  同构 harness：boot→start_run→W2 L5 五词条→敌120 驻场→风筝；无 test_ 前缀不入电池）。
- 臂设计：同进程同种子（20261003）双臂——A 臂 `DT60 ×（300 预热+1800 测量）`；
  B 臂 `DT30 ×（150+900）`（同 30s 模拟时长，同构成）。读数：整帧墙钟 p50/p95/步 +
  十六段均值/P95（**「他」段=回调内长尾，可直接对账**）+ 饱和三轴/步。
- 引擎物理侧补充臂：`Engine.physics_ticks_per_second=60 vs 30` 两轮，驱动循环含
  `await process_frame` 的墙钟差分（含引擎物理步进/Area2D monitoring 成本；headless
  可测方向性，桌面≠真机系数照 R224 声明）。
- 判据（门禁而非观察）：B 臂步耗 p95（按结µs 修复后口径折算 cap192 档）≤ 34ms 才
  允许 tier2=192 定稿；若 >34ms，帽值降档（192→144 起步，供给 4320/s 仍 > 典型需求
  下沿）或接受本刀只保 fps 轴不保模N=30（须用户裁定）。
- 边界：渲染轴（dc/o 面真机能力）headless 不可测 → vc38 真机观察项（主控已裁定）。
- 产出：`docs/qa/probe_r233_stepsize_baseline.json`，全参数入档（种子/臂序/构筑/帽值）。

**时序要求**：本探针必须在 T0（结µs 修复）之后、T3（帽值定稿）之前跑——它给的是
步耗实测而非假设，这正是设计开放问题 4 要的答案，且结论直接决定 AC-1 能否达成。

逐武器×词条实读（弹速通道 = `proj_speed × (1+Σadd_spd)`，ballistic_weapon.gd:295-300

| W6/W7 主弹（homing speed_max） | 720（tres:74） | **979.2**（homing_weapon.gd:89 吃 spd_mult） | **32.6px** |

  仍满足（富余从设计口径的 2 倍缩到 1.1 倍）。
- 敌方速度实读：`spd_base` 38-190（enrage ×1.2-1.25 → ≤238）；E18 冲锋 spd=560

### Q4 帽 240 备选 — 99µs 口径下单帽破预算；120/240 双档否决

以结µs 真值区间（vc37 反推 58-99µs；r232 MICRO 档案参照 ~50µs 跨日披露）对账：

| 档 | 供给/s | 典型需求 4500-5500 | 峰值 8460（vc37 0:31） | 结算轴/步（58µs / 99µs） | 判定 |
|---|---|---|---|---|---|
| tier1 96 / tier2 192（设计案） | 2880 / 5760 | tier2 覆盖（裕 5-28%） | 118%→FIFO 顺延 ~2700/s 峰值排队不丢语义 | 192 帽满打 **11.1 / 19.0ms**（典型 150-183 结=8.7-18.1ms） | 可行但贴边，须 T8 探针门禁 |
| 备选 120 / 240 | 3600 / 7200 | tier2 覆盖；**tier1 反超典型需求下沿，深谷限量语义被稀释** | 118% | 240 帽满打 **13.9 / 23.8ms** | **否决**：99µs 档 240×99=23.8ms 单轴即破 33.3ms 预算（+弹段 7-10 必破） |
| 单档 240（vc38 条件触发） | 7200 | 覆盖 | 99%≈峰值 | 同上 13.9/23.8ms | 仅当**结µs 修复后 ≤60µs 且步耗 p95≤32ms 且弃N p50>50/s** 三条同时成立才可上调（240×60=14.4ms+弹 7-10+敌/网 6-9=27.4-33.4ms 恰好贴线） |

弃N 兑现账（R223 FIFO 守恒语义下）：弃N 三源=亡目标（settle_flush_dead）+uid 复用
（settle_flush_reuse）+超载修剪（settle_overload_drop，硬帽 256）。峰值 8460/s 时每步
净顺延 =(8460-5760)/30=90 项 < 每步冲刷 192 → 积压≈0 → 亡目标丢弃窗口（积压/帽）
从现状深谷的百 ms 级缩到 ~0.5s 内偶发——**弃N p50<50/s 可达，AC-2 口径成立**；
顺N 高位是守恒形态（设计已声明允许）。
**vc38 真机标定触发条件（定案）**：结µs 新口径读数 × 192 > 13ms，或步耗 p95 > 34ms，
或弃N p50 > 50/s —— 任一成立即启动帽值复议（144/192/240 三档按上表算术重选）。
