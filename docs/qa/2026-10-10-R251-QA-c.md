## 2. 盲区探查结论（5 项）

### 2.1 首遇卡片 × 红卡确认门 / 升级选卡窗 / 暂停菜单 同帧叠加

**方法**：临时探针 boot `scenes/main.tscn` 真实 GameLoop（MENU 态），取 `_gl.first_encounter_card_ui` 真件，发卡后置 `tree.paused = true`，逐帧观测 `is_open()/pending_count()`，并以 `root.push_input(左键)` 走完整 GUI→_unhandled_input 链测点击吞噬。

**实测（探针①，日志 `probe_r251_qac_stack.log`）**：

| 观测 | 结果 |
|---|---|
| P1-2 父链 process_mode | GameLoop = **ALWAYS(3)**（`game_loop.gd:214`，帧序契约既有） |
| P1-3 卡 UI 声明 process_mode | INHERIT(0)，与源码一致（`first_encounter_card_ui.gd` 未显式设） |
| P2-1 **暂停期卡片倒计时** | `tree.paused=true` 下卡片照常消散（advanced_frame=469）→ **`_process` 暂停期照跑** |
| P3-1 **暂停期点击** | 卡可见时点空白处：open true→false → **点击被卡 `_unhandled_input` 吞掉（`set_input_as_handled`）** |
| P4-1 **暂停期队列** | 340 帧 pending 3→2、下一张照常出场 → **队列暂停期照放行** |

**结论**：设计 §3.3 与代码注释（`first_encounter_card_ui.gd:58`「INHERIT：LEVEL_UP 暂停期本函数不跑——队列冻结不丢」）的**前提失效**——INHERIT 挂在 ALWAYS 父下解析为 ALWAYS，实测暂停期三路行为（倒计时/队列/输入）全部照常。`change_state` 对 PAUSED 与 **LEVEL_UP** 均置 `get_tree().paused = true`（`game_loop.gd:1038-1039`），故选卡窗、R245 红卡确认门（SublimeConfirmUI，`PROCESS_MODE_ALWAYS` + `tree.paused` 持续）与暂停菜单三种弹窗态全部落在此语义内。

**功能性冲突排查（无新增硬伤）**：红卡门键盘确认走 `ui_accept/ui_select`（`sublime_confirm_ui.gd:96-103`），与卡的鼠标吞噬互不相干；选卡窗/暂停/红卡的按钮均为 GUI 事件（先于 unhandled 消费），点击不被卡截胡；卡全链 `MOUSE_FILTER_IGNORE`（`first_encounter_card_ui.gd:225/239/250/269/277`）不挡下层按钮命中。剩余影响为：①卡片在弹窗 dim 之上继续按 4.5s 节奏轮播（layer 50 > 上述全部弹窗的默认 layer 1，白卡横条浮于压暗层上方）；②暂停/选卡期间点击空白处会被吞（现无弹窗依赖空白点击，暂无功能 casualties）；③玩家恢复战斗后本应看到的后queued 卡在暂停期被烧掉。→ **QA丙-2（中）**，见 §3。

### 2.2 橙盾扩展：boss 战「雷海+自爆海」叠加滚雪球

**方法**：探针②（日志 `probe_r251_qac_snowball.log`）boot 真实 GameLoop + registry/EnemyPool 真件，串行引爆 **6 颗 BossMine**（r249 同款：威胁圈 141px 内武装、爆时未伤人）+ **6 只 E4_volatile**（贴身 1 帧 arm → 拉远 600px 引爆；6 只 = `E6_boss3.tres:21` 二阶段召唤批次口径 `interval_s=8.0, count=6`），逐发记录事件数/层数/剩余时长，末尾做满层吸收。

**实测**：12 源全躲 → **dodge_events=12**；层数 1→2→3→4→5 后**恒帽 5**，且每发后 `left=10.00`（整体刷新，`player.gd:829-830`）；满层时 `take_contact_damage(30)` 两连击 hp 恒 60、层数 5→4→3（**每层恰吞一击**，两击间清无敌帧隔离变量）。

**结论**：机制面零缺陷——帽 5 / 刷新 10s / 每层一击与 r249 H3/H4 锁完全一致，本批只加了发射点未动数值。**量化基线**：雷海 boss（E17 6 雷 / E19 6→8 雷 / E20 p1 布雷）与自爆海 boss（E6_boss3 每 8s 6 只）同屏窗口内，全躲玩家可**常态保持 5 层橙盾 = 约 8 秒 5 次免伤**，且每发刷新使层数在连续躲避下不衰减。这是设计 §3.4 明文收益闭环（「躲开即有橙盾」）的定量结果而非回归——登记 **QA丙-3（低，设计知悉项）**供平衡侧评估 E6_boss3 场景的免伤供给速率。

### 2.3 「blink 降频」后波表节奏（低波真空？）——先正 premise

**premise 修正**：ask 中「blink 降频」与设计不符——设计 D3 明确 **blink 三族（E24/E25/E30）本批零触碰**，②降频对象 = E28_hexcaster（fire_cd 3.2→4.8 + 织入权重 2/其余 3）。探针③逐波统计同时覆盖了 premise 验证：困难 w1~w9 E25 期望 0.52~0.78、E26 0.55~0.79（权重 3 未动），E24 走魔域波表非织入池（M11，blink 套件复跑绿佐证）。

**方法**：探针③（日志 `probe_r251_qac_rhythm.log`）经 `wave_director._roll_composition(wave)` 真缝（verify:3604 / B3 同款），每波 n=1000 固定 seed。

**实测（主表 world_grass）**：

| 档位 | 织入总量均值 | E28 期望/波 | P(波内零咒术师) | 对照降频前 |
|---|---|---|---|---|
| 普通 w3/5/7/9 | **0.00**（R72 普通零改动 ✓） | 0 | — | 0 |
| 困难 w1~w5 | **2.00**（≥2 ✓） | 0.46~0.50 | **55.6%~59.4%** | 均匀 0.67、P(0)=44% |
| 困难 w6~w9 | **2.00** | 0.36~0.39 | **64.8%~67.0%** | 均匀 0.50、P(0)=50% |
| 地狱 w6~w12 | **4.00**（≥4 ✓） | 0.43~0.52 | 57.4%~63.2% | 均匀 0.67、P(0)=48% |

**结论**：**无结构性真空**——织入总量逐波恒 2/4、E25/E26（及地狱 E27/E29/E30）期望不变，新形态总压力不掉；R72 三条方向锁全保持。但「低波真空」的体感有数据支撑：困难低波（w1~w5）**约 56~59% 的波次一只咒术师都没有**（降频前 44%），叠加单只施圈间隔 3.2→4.8s，困难前期的「法师压迫感」降幅比设计 §2.2 表的份额数字（−25%）在体感上更陡。属预期内的调频结果，登记 **QA丙-4（低，平衡知悉项）**；若后续用户反馈「咒术师见不到了」，优先回看此表。

### 2.4 HUD 新增元素布局碰撞（r198_hud_layout 绿但真机竖屏？）

**方法**：探针④（日志 `probe_r251_qac_layout.log`）boot 真实 GameLoop（HUD/BossBar 在 `_build_ui` 即建，`game_loop.gd:2635/:2715`），发真卡后遍历 HUD/BossBar 全部 Control 子树做矩形交，并 `root.size=(720,1280)` 切真机竖屏画布复测（project.godot：720×1280 设计分辨率 + stretch viewport/expand）。

**实测（竖屏，卡矩形 (95.6,11.2)~(624.4,104.8)）——被压元素清单**：

| HUD 元素 | 位置/尺寸 | 交叠 |
|---|---|---|
| **PauseButton + PauseIcon** | (514,20) 72×72 | **全遮（交叠=5184=满积）** |
| **R187Readout**（武器形态读数） | (368,30) 224×25 | **全遮（5600）** |
| **ReviveBadge**（✚×N） | (300,16) 64×23 | **全遮（1472）** |
| **LevelText**（Lv 标签） | (356,60) 36×25 | **全遮（900）** |
| HP 胶囊 + HpText（血量数字） | (24,24) 340×30 | **遮 268/340px（79%）——数字文本整体落入卡区** |

**结论**：设计 §3.3 声明的两个避让对象均成立——hud toast（y392）不相交 ✓、BossBar（y154）不相交 ✓；但**顶带读数组（y16~128）整段未避让**：真机竖屏下每张卡 4.5s 内暂停按钮不可见、血量/经验/等级/复活徽标/武器形态读数被压。另发现设计声明的「橙条 (306,132)」坐标不准：橙盾条实为 **ShieldBar (306,92) 148×36**（hud.gd 源码 + 实测一致），故卡底部对橙盾条顶部有 12.8px 实削。新档首局开场（首发武器卡 + 首波 2~3 种敌卡连播 ≈20s）与 Boss 首遇卡（Boss 战开场）是受扰最重的两个时刻。方形开发窗（1280×1280 画布）下碰撞收窄为右缘细条（R187Readout/LevelText 仍全遮），**真机竖屏才是最坏形态**。→ **QA丙-1（中）**，见 §3。
