# R254「真机反馈批」独立评审意见（game-reviewer 子代理 · 2026-10-10）

评审基准注记：本批无独立设计稿，验收锚 = R252 设计（docs/design/2026-10-10-R252-design.md §2 祝福 / §4.5 菜单性能 M0-M7 / §4.4-8 页签重建语义）+ FEEDBACK_TRACKER R254 两条登记，其余按通用品质标准。评审方式 = headless 实跑（探针/套件/自建沙箱计时）+ 静态审读（main.tscn 图形界面无法 headless 试玩，体验语义以代码路径+实测数据判读，真机数字为 2-4× 外推、已标注）。

## 总评
两条主诉的「病根」都真实修掉了：出发死路有自愈闭环（四象限探针 + B16 实证），图鉴切页降到挂树级 1.5-6.9ms（桌面实测，与披露 −76%~−82% 相符）。但评审发现 **1 个确定性红套件**（rxn_codex 44 断言 43/1——R252 设计明文保护的「同页重切必刷新」语义被页缓存打破，承载断言漏迁移）和 **冷启动菜单单帧 311ms（桌面实测）** 两个必须处理的 medium。0 high。红套件两行迁移必修后方可放行；泵帧形态建议同批收口。

## 体验断点（medium 4 项）
1. **[medium·门禁红·必修] rxn_codex 留红：同页重切刷新语义被页缓存打破**
   - 现象：`test_rxn_codex.gd` 两轮复跑均 43/44，红项 = tests/runner/rxn_codex_cases.gd:400「还原 coef=2.0 后倍率复原」实测 txt=`结算倍率 ×3.5`——改表还原后同页重切（:395 `_on_codex_tab("反应")`）命缓存行，显示过期倍率。
   - 归因：R254 页缓存把「同页签重复点击仍全量重建」改为「命中即挂树」。实现侧只迁移了 r252_menu_perf 的 M6 副本（r252_menu_perf_cases.gd:355/:366 补 `_invalidate_codex_cache()`），rxn_codex 原版（R252 设计 §4.4-8 点名的语义承载面）漏迁。
   - 影响面：**产品无过期数据**——reaction_table 运行期静态、生产零改表路径（唯一改表方是本测试）；纯回归语义/门禁问题。但按本项目「全绿为批次门禁」纪律，此红不清不可放行。
   - 修法：同款两行迁移——:384 改表后、:394 还原后各补一次 `menu._invalidate_codex_cache()`（照 r252_menu_perf M6 先例）；产品代码零改动。
2. **[medium] 冷启动主菜单冻结帧：泵原子单位=整页，武器页冷贴图 311ms 桌面实测**
   - 实测（沙箱探针，boot 语境、贴图预热 op:7 未达）：五泵帧分别 ≈ 10.1 / **310.9** / 54.3 / 23.9 / 84.4 ms，合计 483.6ms——「boot 后约半秒备齐」桌面属实，但分布是 1 个 311ms 胖帧而非 4ms×N。
   - 根因链：武器图标预热项（op:7）排在 boss 段后（game_loop.gd:2663-2669），boss 3s 挂机门内不可达（:2701-2704）；而图鉴泵在菜单可见后 ~2 帧内就构建武器页 → `TextureFactory.weapon_icon` 近战委托臂冷生成（R252 侦察单枚 ~31ms）。**每次进程冷启动必发**（贴图静态缓存进程级常驻，仅首次冷；后续回菜单武器页重建仅 5.3ms 暖）。真机 2-4× 外推 = 启动菜单即 0.6-1.2s 单帧冻结——恰是「游戏外卡」感知域，等于把 R252 修的「首次点武器页卡」提前到人人必经的启动路径。
   - 修法（选一，改动都小）：图鉴泵门控——`_tex_prewarm_queue` 消化过 boss 段（或 op:7 域清空）前不开工/武器页延后；或泵改行粒度预算 + 超支占空还账（card_desc_prewarm R221 / tex R222 同款 `skip_frames` 先例，本泵完全没有还账机制）。
3. **[medium] 回菜单五连小卡 + 「4ms/帧」名不符实**
   - 实测（暖重建，即每次回菜单的失效重排成本）：9.4 / 5.3 / 21.0 / 13.0 / 23.8ms 共 72.5ms 摊在进菜单后首 5 帧；真机外推 ~150-290ms。反应页内容静态（表+首见标记，后者另有 codex_changed）也被无差别重建，约占三成。
   - 预算账本过期：MENU 态现在三泵并存——tex 4ms（game_loop.gd:634）+ carddesc 4ms（BUDGET_US，R252D P5 已从 12ms 降到位）+ 图鉴泵名目 4ms = **名目 12ms/帧**（60Hz 占 72%），叠加期最坏帧还要吃断点 2 的原子超支；card_desc_prewarm.gd:29-34「合计 8ms < 16.6ms 还余量」的算术注释未随第三泵更新，M4c 断言（两泵 ≤8000µs）也未扩到三泵。任务摘要里「CardDescPrewarm 12ms」口径本身也过期了（现为 4ms）。
   - 修法：反应页免入进菜单失效口（省 ~1/3）；泵行粒度化后本条与断点 2 一并消解；M4 补第三泵断言 + 注释算术更新。
4. **[medium·R252 遗留、本批主题未收口] 祝福模态零输入阻挡 + 每日入口无 pending 闸 → 双 start_run 链**
   - 证据：blessing_pick_ui.gd 全链 `mouse_filter = IGNORE`（:212 root / :221 dim / :236 card）——模态只是视觉压暗，点击穿罩直达下层菜单；`_on_menu_start_daily`（game_loop.gd:1724-1730）只查 `state != MENU`，而模态期 state 恰是 MENU。
   - 静态推演链（未实机复现）：模态期罩下点「返回大厅」→ 开每日面板 →「开始每日挑战」→ start_run(每日种子) → state→PLAYING → 面板防御收口 `_on_state_changed`（blessing_pick_ui.gd:149-154）dismissed → `_finish_menu_start(_blessing_pick_map)` **第二次 start_run()（无种子）**——每日局被常规局覆盖、每日种子被洗成 -1。玩家点了每日、进了普通图。
   - 修法：`_root`/dim 改 `MOUSE_FILTER_STOP`（一行级，真模态，同时消「罩后点击无响应」的隐性困惑）；`_on_menu_start_daily` 头部补 pending 自愈（同 `_on_menu_start` 口径）或拒绝。
5. **[low] pending 期二次出发忽略新点选上下文**：重开分支（game_loop.gd:1808-1811）早 return 在 `current_map_id/_difficulty` 赋值前——面板丢失窗口改选难度/地图后再点出发，confirm 启动的是首开缓存的旧地图旧档（subtitle 档位名可察）。建议重开分支先按本次入参更新缓存上下文（含解锁校验）再 open。
