## 缺陷清单

### QA-1【medium·产品·UI】祝福面板行描述标签宽度失控：32/62 行 desc 横穿价签文字区并溢出卡宽——设计「desc 让位价签」运行时失效

- **严重级别**：medium（核心新 UI 视觉缺陷，功能可用、不崩溃、价签仍绘制在上层可读）
- **期望**（设计稿 §2.6 / 验收 S9）：「desc_label 宽 480→420 让位（x68 起，与价签无缝隙不重叠）」——描述文字在 [68, 488] 内绘制，超出部分按 OVERRUN_TRIM_ELLIPSIS 截断加省略号；不与价签 (488,22) 文字区重叠、不出卡宽 572。
- **实际**（探针实测，确定性复现）：
  - desc 标签 rect 在行构建时即自增：设计设宽 420，实测 62 行中 **32 行** rect 宽度 447~1665px（`ELE_ANEMO` desc size=(1490,23)、`MEC_FRACTAL` (1665,23)、`ELE_SHOCK`/`ELE_IGNITE` 等 ELE 族全中、`MEC_BEAM_COFOCUS` 649 等）；desc 框右缘最坏 1733px，横穿价签文字区（价签「-N」右对齐实测左缘≈537）并远超卡宽 572；全 UI 无 clip_contents/ScrollContainer（R261 已拆滚动壳），溢出文本无裁剪直接绘制。
  - 名字行与价签本体几何正确（名字实测最大宽 98px ≤488；价签 62/62 行全在 x=488 宽 80、右缘 568≤572、rarity 色、右对齐）——问题孤立于 desc 标签。
- **复现步骤**：
  1. `tools/Godot_v4.3-stable_win64_console.exe --headless --path repo -s tests/qa_r263_gap_probe.gd` → D1 项 FAIL，detail 列出 32 个受影响行 id 与实测右缘。
  2. 最小复现（已定位触发因子）：`Label` 为 `Button` 子节点 + 文本自然宽超设宽 + `text_overrun_behavior=OVERRUN_TRIM_ELLIPSIS` → 设宽 420 的标签 size 同步变为 (1490,23)（ELE_ANEMO 首行 115 字）；同款 Label 直挂 VBox 则不增（(572,18)）；与 overrun 赋值先后顺序无关。
- **归因线索（供开发，非最终结论）**：Godot 4.3 Label 在 Button 内、超宽文本 + overrun 截断的组合下同步自增 rect（触发行构建当帧、与 squash_pop 动画无关——open 同步时点已增）。R263 前 desc 设宽 480 同构存在，溢出方向是卡缘外（不显眼）；R263 价签落位 [488,568] 后，溢出路径正穿价签文字区，把存量引擎交互缺陷变成面板内文字对撞。修复方向建议：desc_label 加 `clip_text = true` 或改 autowrap 固定宽（只报告，不代改）。
- **影响面**：祝福面板「全部」签及紫/金签长描述行（ELE 族 7 行 + MEC/AFF 长描述行等 32 行）；价签行信息仍可读（上层绘制+白描边），desc 末段被价签压住、出卡文本溅到面板右侧背景。
