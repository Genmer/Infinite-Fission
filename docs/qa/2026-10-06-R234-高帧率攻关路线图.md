## 1. 用户摘要（白话：这条路怎么走到 90-120）

现在的游戏在深载下每一步模拟要花 **41-71 毫秒**，而 90-120 帧只允许每步 **11-16.6 毫秒**——差 3-6 倍。四路探察已经把钱花在哪算清楚了：**子弹段 25-35ms + 伤害结算 8-10ms + 杂项长尾 17-19ms**；也把老路判死了：GDScript 里能抠的都抠完了，30Hz 降频被真机证伪。**唯一被实测证明走得通的结构性新路**：把最贵的代码搬进 C++ 原生模块——探索员在本机把工具链全打通了，真引擎实测**同一段子弹计算快 14-17 倍**。

路分两大段、共 9 轮出包（vc39-vc47），总工期约 **33-42 人日（单人 7-9 周，双人并行约 5-6 周）**：

1. **第一段"先摘低处的果"（2 轮，约 1.5 周）**：R235 三把快刀 + R236 伤害聚合。不换架构，先砍 10-20ms，帧率 14-24 → 约 20-45；R236 还顺手把"伤害被预算系统诚实丢弃"的口子彻底堵死（弃N 归零，玩家打的每一分伤害都真实落地）——这是公平性收益，与帧率无关也值得做。
2. **第二段"搬进原生代码"（7 轮，约 5-7 周）**：R237 先在真机上打通 C++ 模块链路并实测真机加速比（这是全路线的生死门，第 1 轮就验）；然后按"哪块贵先搬哪块"：R238 空间查询 → R239/R240 子弹段全量（最大头）→ R241 伤害结算 → R242 杂项长尾 → R243 终点对账。每一轮都有真机验收数字，搬错可逐轮回退（不注册 .gdextension 文件即回到纯 GDScript，游戏照跑）。
3. **终点预计**：深载每步约 **8-15ms**（全推算链）→ 120fps（16.6ms 线）大概率稳、90fps（11ms 线）中带走标、最坏差 0-4ms。差的那一点有明码标价的补缺清单（§5）；补完仍差，就如实报告缺口和下一期工程量，不糊弄数字。

一句话：**前两轮便宜且稳赚，后七轮贵但每轮有实测门禁；90-120 不是拍脑袋，是"14-17 倍实测加速 × 逐块搬运 × 逐轮验收"堆出来的，堆到最后几毫米的缺口，本文档明写。**

### 5.2 对 90-120 硬指标的判定（如实）

- **120fps（每步 ≤16.6ms）：大概率达标**——终点带上界 15ms < 16.6ms。前提：R240 词条链加速比不落宽带下界之下、R242 长尾刀兑现 ≥6ms。
- **90fps（每步 ≤11ms）：中带走标、尾部有缺口 0-4ms**——中位 ~10-11ms 贴线；若真机落带上段（14-15ms），90 不稳。
- **渲染轴提醒**：每步 ≤16.6ms 后 fps 上限转由渲染帧支配（vc37/38 深载 dc 700-1000，快项 §1 证据指向真机余桶大头在渲染侧）——模拟达标≠fps 自动达标，渲染轴补缺是 90-120 的另一半。

### 5.3 缺口补缺清单（按 ROI 排序，R243 对账不过时启用）

1. **MultiMesh 弹渲染实例化**（弹段数据化 §六 Phase 3 资产：九变体 MultiMesh+帧末批量上传+弹桶退役；1-2 人日+回退口）——dc 收益≈0 披露（桶已合批，弹桶=2），收益在对象数/变换传导/插值写与渲染帧预算；
2. **UI/跳字链三刀**（快项 §4e 全量+选卡窗专项；0.5-1.5 人日，真机估 1-3ms）；
3. **摊销压缩**：批调用合并/事件回流减频（依 `摊销` 键实测，0.5-1 人日）；
4. **原生二期（完整形态）**：弹对象壳全灭、C++ 直驱 RenderingServer（原生报告 §6 架构走向终态；另立立项，量级 15-20 人日，本路线图不承诺）。

**若补缺后仍不达 90：如实报告卡点**（当前引擎形态 gl_compatibility+GDScript 壳+已下沉面的实证尽头在哪、缺口几毫秒、二期工期多少），由用户定夺——不降级目标数字、不虚报达标。

## 6. 规划师裁定（与探索结论的分歧与矛盾处置）

1. **桌面弹段口径差（14.4 vs 30.09ms）不是矛盾，是夹具口径差**：probe_r231_final S0（三刀后终态、PC 全模拟）vs 快项同步臂 D（r224 夹具 60Hz 档）【两报告各自留档】。裁定：**规划一律以任务书真机 vc37 口径（弹段 25-35/每步 41-71ms）为锚**，桌面读数只取差值（Δ）作收益依据，绝对值不外推（两报告自身同此纪律）。
2. **弹段数据化 Phase 1-3 不上主路线，Phase 0 与布局蓝本保留**。理由：其单独终点 34-63ms 不达 11ms 预算（其报告 §六自认"单独实施不达标"）；与原生路线攻击同一目标（弹段），双轨叠加=43+ 人日且测试面 ×2（其 §5.2 自认）。保留资产：Phase 0 真机校准（1 人日，搭 vc39）产出的 ARM 属性放大系数**同样支配原生路线的真机收益预期**；§四 typed/SOA 布局与 R188 零分配方案直接作 R239 的 C++ 数据布局蓝本。**备胎触发条件**：R237 真机加速比 <8x 或 APK 链路死锁→弹段数据化+MultiMesh 升主路线（届时终点退至 ~20-30ms → 33-50fps，90-120 无实证路径，如实上报）。
3. **不同意原生报告"弹段 ÷15"的整体折算方式**（其 perfProjection 将弹段 25-35 一体 ÷15）：17x 实证仅覆盖运动核形态（bullet_tick_xy/batch_mul_add），而弹段数据化分解【实证】证明运动核仅占每弹成本 ~1.4%、大头（75-85%）在词条命中链——**词条链的 C++ 加速比从未被实测**。裁定：总量结论（弹段→2-5ms）保留，但 R240 收益标宽带 ÷5-15，等价性成本（R220/R225/R187/R15 对拍）也集中压在该阶段——它是全路线最大单刀，也是最大不确定点。
4. **overkill（GDScript 聚合）与原生结算下沉的顺序**：先 R236 后 R241。代价=R241 收益从原生报告原估的 −7-9ms 缩水至 −2.5-3ms。顺序仍然正确：弃N 语义闭合早 4 轮兑现（与帧率无关的公平性收益）、管线缩短让 R241 等价性面更小、且 R236 是纯 GDScript 无工具链依赖。
5. **出包编号裁定**：快项与 overkill 两报告都自称"vc39 取证"——裁定 R235=vc39、R236=vc40 串行出包（一包一刀归因隔离；工作可并行）。Phase0 校准件、长尾分键、mask A/B 全部搭 vc39 一次携带。
6. **Area2D 完整迁移与弹群批筛维持证伪否决**（快项 §1/§2 桌面实证），敌 mask 2 行刀搭 vc39 真机终审——与探索员结论一致，无分歧。同类纪律适用于 R242：**分键实测证伪的子项即弃，不做无实证支撑的搬运**。
7. **R242 长尾刀是本路线图相对四路探索的唯一"无 precedent"新增**：四路均未实测长尾下沉收益（原生报告明说"未实测其下沉收益"、弹段数据化明说"归属未归因不预估"）。本路线图给它的 5-7 人日与 6-14ms【纸面】是全文档依据最弱的数字，故把分键诊断前置到 vc39、把 D1 重锚设为它的立项门——**如果 vc39 分键显示长尾真机构成与桌面严重背离，本阶段预算与子项随 D1 重写**。
