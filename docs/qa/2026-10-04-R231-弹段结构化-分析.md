# R231 弹段结构化性能刀单 — 可行性分析（开放问题销账）

分析对象：docs/qa/2026-10-04-R231-弹段结构化-设计.md（刀A=SpaceGrid 读路径快照化、刀B=玩家弹快路径、刀C=条件瘦身）。
方法：全部结论对照代码库逐行核实（file:line 均为本次实读），只读不改；微基准数字（25.4→9.1→4.9µs）按任务指示采信。

## 结论

**修改后放行。** 刀A 的行为等价论证全面闭合（且比设计稿假设更强——敌回池后位置不变），可直接开工。刀B 有三处判据级缺陷必须先改：①资格判定必须移到 ON_SPAWN 派发之后计算（MEC_BOUNCE 会在派发期给弹加跳弹预算、EF_SIZE 会改半径，照设计稿 :245 预计算会误标快路径=可感行为回归）；②资格须排除 EF_SIZE 词条（否则跳过首帧视觉重同步，贴图缩放陈旧）；③「无 range 键」判据不可照搬——玩家直线弹恒带 range>0，快路径必须内联超射程回收。另有一个收益侧重大风险：探针指纹构筑带 MEC_BOUNCE×3，全部主弹带 +6 跳弹预算走慢路径，刀B 实际主要覆盖 MEC_FRACTAL 分裂子代，−1.5~2.5ms 估算偏高，A+B+C 后 AC-P1（<5ms）达标概率中偏低——须先跑前置测量（T0）再定收口口径，不静默放水。

## 可玩性评估

纯优化刀（设计意图零玩家可感变化），无上手门槛/反馈密度/挑战节奏维度变化。唯一可感风险点是刀B 视觉 no-op 破缺（EF_SIZE 弹半径在 ON_SPAWN 变化、慢路径首帧 _sync_visual 会补同步，快路径跳过则贴图缩放永久陈旧）——已通过资格排除消解，纳入 T12 测试锁定。

## 技术可行性 — 8+2 项销账表

### AC-1 Enemy.knockback 语义

**结论：速度型（冲量衰减位移），④ 相位内不改 global_position——「快照粗判超集」论证闭合，无需击退安全余量。**

证据：
- enemy.gd:809-824 knockback(p_force)：Boss 免疫；knock_vel += scaled * 9.0（:818）只写速度字段。头注明言 R7 重构已把「即时 += 位移」改为冲量衰减（原一步跳半屏=「闪退」观感根因）。
- knock_vel 唯一消费点在敌 tick：enemy.gd:700-702（global_position += knock_vel * dt + lerp 衰减）——敌 tick 在帧序 ⑤（game_loop.gd:468-474），晚于 ④ 弹 pass。
- knockback 其余副作用：_cancel_fuse/_cancel_blink（状态取消，不写位置）、EventBus.emit_knockback_hit（纯表现广播）。

对刀单影响：设计稿「即时位移→披露+击退场景测试+粗判余量」处置路径全部不需要；等价测试无需击退专项用例。

### AC-2 敌死亡回池

**结论：敌是池化实体；active.erase 为 Array.erase O(n) 移位；回池不改 global_position（比设计稿假设更强——快照粗判与 live 粗判在 ④ 内完全一致）。**

证据：
- enemy_spawner.gd:183-189 on_enemy_killed：active.erase(p_enemy)（GDScript Array.erase=线性扫描+移位，非 swap-remove）→ pool.release(p_enemy)。
- object_pool.gd:70-86 release：bucket_host.unplace（:79-80）→ _before_repool（调 _reset_state）→ _prepare_for_pool（visible=false/停处理，不写位置）。
- tex_bucket_host.gd:46-51 unplace：reparent(_home)——Godot 4 reparent 默认 keep_global_transform=true，且桶节点与池根均为原点无变换（头注「原点无变换——local position 语义恒等」），双重保证 global_position 不变。
- enemy.gd:1890-1922 Enemy._reset_state：不写位置；置 dead=true（:1919 注释「池内=不存在（死亡态短路）：同帧网格快照仍含已归还节点，二次命中经 dead 短路」——现网已内建该语义）。
- 死亡链同步性：enemy.gd:1006-1020 _on_died → emit_enemy_killed → spawner 处理全在 ④ 结算内同步完成；下次 rebuild（下帧 ④ 头）才移出网格。

对刀单影响：设计稿「快照粗判可能仍命中→_in_reach live 读新位→排除」的论证前提（回池会移位）实际不成立——回池敌位置=死亡位，快照粗判、live 粗判、live 窄相三者结果逐位一致，随后 _submit_hit 内 dead 短路（projectile_base.gd:513-516）。T5 用例按「位置不变+dead 短路」构造。刀A 自有快照数组必要性论证成立（erase O(n) 移位使外部数组索引错位）。

### AC-3 _sync_visual 量化比较对象

**结论：比较 (a) _vis_variant < 0（变体未初始化）与 (b) scale_q = floorf(effective_radius()/(TEX_SIZE*0.5) * 32)（1/32 级量化半径）；不比较位置。资格弹（半径 spawn 后不变）量化比较恒不触发重设——no-op 证据闭合，但有一个设计稿未提的细节：tracked 变体的 rotation 每帧无条件刷新。**

证据：
- projectile_base.gd:1030-1048：scale_f=effective_radius()/32、scale_q=floorf(scale_f*32)；仅当 _vis_variant<0 or scale_q!=_vis_scale_q 才重设贴图/缩放/落桶；elif _vis_rot_tracked: _apply_visual_rotation()（:1047-1048）——曳光（W2_gatling=探针武器！）/导弹变体每 tick 刷 rotation。
- 资格弹速度方向恒定（无 accel/无反弹/无收束/无转向）→ rotation 自 spawn 期 _sync_visual（:215，velocity 已就位）后不变 → 快路径跳过整段 _sync_visual 逐位 no-op。

对刀单影响：刀B 跳过 _sync_visual 成立，但 T12 须加「曳光弹（_VIS_TRACER）rotation 恒定」断言；_place_in_bucket 只在重设分支内调用（:1147），跳过不影响桶归属。

### AC-4 size_mult/弹半径/视觉变体的非 spawn 期写者

**结论：写者存在，但全部位于 ON_SPAWN 事件（spawn 期尾部、projectile_base.gd:258 派发点），不存在 spawn 后写者——设计前置条件字面成立，但派发点在 :245-250 快照点之后，产生两个必改项。**

证据：
- trait_effect_size.gd:12-28：EF_SIZE 家族（AFF_AREA/MEC_SIZE_STACK）ON_SPAWN 写 p_ctx.projectile.size_mult *= ...；ON_HIT 分支 _maybe_nova 只读不写（:31-51）。
- trait_effect_bounce.gd:14-27：MEC_BOUNCE ON_SPAWN 写 bounces_left += value×layers（:20）并抬 lifetime_left（:27）；ON_BOUNCE 期 _maybe_eternal（:44-46）写 lifetime/range_left——仅反弹弹可达（判据已排除）。
- 全部 66 个 .tres 无一含 ON_TICK 挂钩（枚举 game_const.gd:14：ON_SPAWN=0,ON_TICK=1,...；grep event_hooks 无含 1 者）——R225 论断复核成立，_tick_dispatch_armed==false 判据安全。
- hitbox_radius 无词条写者（全仓 grep）；TH_BANK_SHOT 金染只在 _apply_bounce 失效重判（projectile_base.gd:873），反弹弹被判据排除；weapon_ref 中途失效导致的变体陈旧是现网既有行为（重设只由 scale_q 变化触发 :1041），非刀B 引入。

对刀单影响（两项必改）：

2. **资格判据追加 not _stack_has_effect(&"EF_SIZE")**（或 spawn 期 size-armed 旗标，同 _crit_shard_armed 先例 projectile_base.gd:226）：慢路径首帧 _sync_visual 会按 ON_SPAWN 后的新半径重设贴图（spawn 期 :215 的 _sync_visual 在派发前、拍不到），快路径跳过则贴图缩放永久陈旧=玩家可感。探针构筑无 size 词条，覆盖率不受此条影响。
